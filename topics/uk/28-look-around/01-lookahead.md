# Перегляд уперед

**Перегляд уперед** (lookahead) перевіряє, що стоїть *після* поточної позиції, не включаючи цей текст у збіг. З його допомогою можна сказати: «знайди `X`, але лише якщо за ним іде `Y`» (або «лише якщо за ним **не** йде `Y`»). На перегляді вперед побудовано перевірку паролів, пошук «числа з одиницею виміру», перекривні збіги та чимало хитрих замін.

## Що ви дізнаєтесь

- Що таке твердження нульової ширини і чим перегляд уперед відрізняється від звичайного збігу
- Позитивний перегляд уперед `X(?=Y)` і негативний `X(?!Y)`
- Як кілька переглядів уперед перевіряються на **одній і тій самій** позиції і як це використати для правил пароля
- Як повернення назад (backtracking) може обійти негативний перегляд уперед і як цьому запобігти
- Як знаходити перекривні збіги, захоплюючи текст усередині перегляду вперед
- Як вставляти текст у певну позицію, наприклад роздільники тисяч

## Твердження нульової ширини

Більшість частин шаблону **поглинає** символи: `\d` збігається з цифрою і пересуває рушій за неї. Деякі ж частини лише **стверджують** щось про поточну позицію й нічого не поглинають. Кілька таких ви вже знаєте: `^`, `$` і `\b`. Їх називають **твердженнями нульової ширини** (zero-width assertions).

Перегляд уперед — це твердження нульової ширини, яке ви пишете самі. На поточній позиції рушій пробує зіставити підшаблон усередині перегляду. Якщо це вдається (або не вдається — для негативного перегляду), рушій повертається на позицію, з якої почав, і продовжує з рештою шаблону. Переглянутий текст до збігу не потрапляє.

Порівняйте звичайний шаблон і шаблон із переглядом уперед:

```python
import re

s = "1 Python is about 4 feet long"

print(re.findall(r"\d+\s*feet", s))
print(re.findall(r"\d+(?=\s*feet)", s))
```

Результат:

```text
['4 feet']
['4']
```

Обидва шаблони вимагають `feet` після числа, але лише перший включає це слово у збіг.

## Позитивний перегляд уперед: `X(?=Y)`

Синтаксис такий:

```text
X(?=Y)
```

Він означає: знайди `X`, але лише якщо одразу за ним іде `Y`. Щоб знайти кількість футів у тексті вище:

```text
\d+(?=\s*feet)
```

- `\d+` збігається з однією або кількома цифрами.
- `(?=...)` — це перегляд уперед.
- `\s*` усередині нього допускає нуль або більше пробільних символів.
- `feet` — буквальний текст, який має йти далі.

```python
import re

s = "1 Python is about 4 feet long"
pattern = r"\d+(?=\s*feet)"

for match in re.finditer(pattern, s):
    print(match.group())
```

Результат:

```text
4
```

Після числа `1` немає `feet`, тому воно пропускається.

Ще один щоденний приклад — ім'я користувача в адресі електронної пошти: символи слова, за якими йде `@`.

```python
import re

text = "Write to olena@example.com or max@test.org"
print(re.findall(r"\w+(?=@)", text))
```

Результат:

```text
['olena', 'max']
```

На відміну від перегляду назад (наступна тема), перегляд уперед може містити шаблон **будь-якої довжини**: `\s*`, `.*` та інші квантифікатори змінної ширини всередині `(?=...)` цілком допустимі.

## Негативний перегляд уперед: `X(?!Y)`

```text
X(?!Y)
```

Такий шаблон збігається з `X`, лише якщо за ним **не** йде `Y`. Щоб знайти в тому самому реченні `1`, але не `4`:

```python
import re

s = "1 Python is about 4 feet long"
pattern = r"\d+(?!\s*feet)"

for match in re.finditer(pattern, s):
    print(match.group())
```

Результат:

```text
1
```

Негативний перегляд уперед на *початку* лексеми працює як фільтр за тим, із чого вона починається. Цей шаблон знаходить слова, що не починаються з `un`:

```python
import re

print(re.findall(r"\b(?!un)\w+\b", "undo redo unify apply"))
```

Результат:

```text
['redo', 'apply']
```

### Пастка повернення назад

Негативний перегляд `\d+(?!\s*feet)` виглядає правильним, але має тонку ваду, яка проявляється на числах із двох і більше цифр:

```python
import re

text = "The pole is 14 feet long, the rope 3 metres"
print(re.findall(r"\d+(?!\s*feet)", text))
```

Результат:

```text
['1', '3']
```

Звідки взялося `1`? На `14` рушій спершу зіставляє `\d+` з `14`. Далі йде ` feet`, тож негативний перегляд не спрацьовує. Але рушій не здається: він **повертається назад** (backtracking) і дозволяє `\d+` захопити лише `1`. Тепер далі йде `4 feet`, що не відповідає `\s*feet`, перегляд успішний, і в результат потрапляє `1`.

Виправлення — заборонити зупинку посеред числа. Додайте другий перегляд `(?!\d)` або внесіть цифру до забороненого тексту:

```python
import re

text = "The pole is 14 feet long, the rope 3 metres"

print(re.findall(r"\d+(?!\d)(?!\s*feet)", text))
print(re.findall(r"\d+(?![\d\s]*feet)", text))
```

Результат:

```text
['3']
['3']
```

> **Порада:** щоразу, коли негативний перегляд уперед стоїть після квантифікатора (`\d+`, `\w+`, `.*`), запитайте себе, що станеться, якщо квантифікатор віддасть частину символів. Зазвичай прогалину закриває `\b` або додатковий `(?!\d)` / `(?!\w)`.

## Кілька переглядів уперед на одній позиції

Перегляди вперед можна ставити поспіль:

```text
X(?=Y)(?=Z)
```

Рушій знаходить `X`, потім перевіряє `Y` **на позиції одразу після `X`**, повертається і перевіряє `Z` **на тій самій позиції**. Перегляди нічого не поглинають, тому `Z` перевіряється *не* після `Y`. Обидві умови мають виконуватися одночасно, як логічне І.

Це видно на крихітному прикладі. Якби `Z` перевірявся після `Y`, другий пошук був би успішним, адже після `abc` іде `d`:

```python
import re

print(re.search(r"x(?=abc)(?=a)", "xabcd"))
print(re.search(r"x(?=abc)(?=d)", "xabcd"))
```

Результат:

```text
<re.Match object; span=(0, 1), match='x'>
None
```

### Правила для пароля

Кілька переглядів уперед на початку шаблону — класичний спосіб перевірити кілька незалежних правил. Кожен перегляд починається з позиції 0 і проглядає текст далі за допомогою `.*`:

```python
import re

PASSWORD = re.compile(r"(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}")

for pw in ["secret", "secret123", "Secret123", "SECRET123", "Sec123"]:
    print(f"{pw!r:12} {bool(PASSWORD.fullmatch(pw))}")
```

Результат:

```text
'secret'     False
'secret123'  False
'Secret123'  True
'SECRET123'  False
'Sec123'     False
```

- `(?=.*[a-z])` означає «десь далі є мала літера».
- `(?=.*[A-Z])` означає «десь далі є велика літера».
- `(?=.*\d)` означає «десь далі є цифра».
- `.{8,}` — єдина частина, що поглинає текст: щонайменше 8 символів.
- `fullmatch()` змушує весь рядок пройти всі перевірки.

`.*` тут обов'язкове. Без нього `(?=\d)` вимагав би, щоб цифрою був **перший** символ.

## Перегляд уперед до лексеми чи після неї

Місце перегляду змінює його зміст:

- `X(?=Y)`: після `X` перевіряємо, що **йде за ним**.
- `(?=Y)X`: перед `X` перевіряємо, з чого `X` **починається** або що містить.

Наприклад, `\b(?=\w*\d)\w+\b` знаходить слова, що містять хоча б одну цифру. Перегляд зазирає в слово ще до того, як `\w+` його поглине:

```python
import re

print(re.findall(r"\b(?=\w*\d)\w+\b", "room 101, floor B2, exit"))
```

Результат:

```text
['101', 'B2']
```

## Перекривні збіги

`findall()` і `finditer()` ніколи не повертають збігів, що перекриваються: після збігу пошук продовжується з місця, де збіг закінчився. Перегляд уперед нічого не поглинає, тож збіг, що складається лише з перегляду, порожній, і рушій просувається на один символ за раз. Поставте всередину перегляду групу захоплення — і отримаєте кожне перекривне входження:

```python
import re

print(re.findall(r"\d\d", "12345"))
print(re.findall(r"(?=(\d\d))", "12345"))
```

Результат:

```text
['12', '34']
['12', '23', '34', '45']
```

Групи всередині перегляду вперед захоплюються як звичайно, хоча сам перегляд ні з чим не збігається.

## Вставлення в позицію: роздільники тисяч

Оскільки перегляд уперед (як і `\B`) збігається з *позицією*, `re.sub()` може вставити текст, нічого не замінюючи:

```python
import re

print(re.sub(r"\B(?=(?:\d{3})+(?!\d))", ",", "Total: 1234567 and 999"))
```

Результат:

```text
Total: 1,234,567 and 999
```

Читайте шаблон так: «позиція всередині слова (`\B`), за якою йде одна або кілька груп по три цифри (`(?:\d{3})+`), а далі цифр немає (`(?!\d)`)». Саме в таких місцях і має стояти кома. Це гарна демонстрація, але вона ламає десяткові дроби (`1234.5678` перетворюється на `1,234.5,678`). Для справжніх чисел використовуйте форматування рядків: `f"{1234567:,}"` дає `'1,234,567'`.

## Типові помилки

- **Очікувати текст перегляду в результаті.** `\d+(?=\s*feet)` повертає `4`, а не `4 feet`. Якщо потрібні обидві частини, скористайтеся звичайним шаблоном із групами.
- **Потрапити в пастку повернення назад.** `\d+(?!%)` на `15%` повертає `1`. Додайте `(?!\d)` або використайте `[\d%]` усередині перегляду.
- **Вважати, що перегляди поспіль перевіряються послідовно.** У `X(?=Y)(?=Z)` і `Y`, і `Z` перевіряються на одній позиції.
- **Забувати `.*` у перевірках «містить».** `(?=\d)` перевіряє лише наступний символ. Щоб перевірити «десь далі», пишіть `(?=.*\d)`.
- **Перевіряти через `^...$` і `re.match()`.** `$` збігається ще й перед кінцевим символом нового рядка, тому `re.match(r"^(?=.*\d).{8,}$", "abcdefg1\n")` знаходить збіг. `re.fullmatch()` (або `\Z`) зайвого `"\n"` не пропускає.

## Підсумок

- Перегляд уперед — це твердження нульової ширини: він перевіряє текст попереду й нічого не поглинає.
- `X(?=Y)` збігається з `X`, лише якщо далі йде `Y`. `X(?!Y)` — лише якщо далі не йде `Y`.
- Текст усередині перегляду не входить у збіг, але групи всередині нього захоплюються.
- Перегляд уперед може містити шаблони змінної довжини, як-от `.*` і `\s*`.
- Кілька переглядів поспіль перевіряються на одній позиції, як логічне І. На цьому ґрунтується перевірка паролів.
- Квантифікатор перед негативним переглядом може повернутися до коротшого збігу. Захищайтеся від цього за допомогою `(?!\d)`, `\b` або ширшого класу символів.
- Захоплення всередині перегляду дає перекривні збіги, а «чистий» перегляд у `re.sub()` вставляє текст у позицію.

## Практика

### Вправа 1: Суми в доларах

З рядка `"Paid 120 USD, 75 EUR and 30USD"` витягніть суми, за якими йде `USD` (із пробілом або без). Очікуваний результат — `['120', '30']`.

### Вправа 2: Числа, що не є відсотками

З рядка `"Growth 15% on 200 units, 7% tax"` витягніть числа, за якими **не** йде `%`. Очікуваний результат — `['200']`. Спершу спробуйте наївний шаблон `\d+(?!%)` і поясніть, що з ним не так.

### Вправа 3: Надійний пароль

Напишіть функцію `is_strong(password)`, яка повертає `True`, лише якщо пароль має щонайменше 8 символів, хоча б одну велику літеру, хоча б одну цифру, хоча б один із символів `!@#$%` і не містить пробільних символів. Перевірте її на `"Passw0rd!"`, `"passw0rd!"`, `"Password!"`, `"Passw0rd"`, `"Pass w0rd!"` і `"P0!a"`.

### Вправа 4: Перекривні входження

`"banana".count("ana")` повертає `1`, бо `str.count()` не враховує входжень, що перекриваються. За допомогою перегляду вперед порахуйте всі входження `ana` у `"banana"`, зокрема перекривні, і виведіть позиції, з яких вони починаються.

## Розв'язки

### Вправа 1

```python
import re

text = "Paid 120 USD, 75 EUR and 30USD"
print(re.findall(r"\d+(?=\s*USD)", text))
```

Результат:

```text
['120', '30']
```

### Вправа 2

```python
import re

text = "Growth 15% on 200 units, 7% tax"

print(re.findall(r"\d+(?!%)", text))
print(re.findall(r"\d+(?![\d%])", text))
```

Результат:

```text
['1', '200']
['200']
```

Наївний шаблон повертається назад усередині `15%`: після `15` іде `%`, тож рушій пробує `1`, після якого йде `5`, а не `%`, і збіг вдається. Якщо заборонити в перегляді ще й цифру (`[\d%]`), число може закінчитися лише там, де закінчуються цифри.

### Вправа 3

```python
import re

STRONG = re.compile(r"(?=.*[A-Z])(?=.*\d)(?=.*[!@#$%])(?!.*\s).{8,}")


def is_strong(password):
    return STRONG.fullmatch(password) is not None


for pw in ["Passw0rd!", "passw0rd!", "Password!", "Passw0rd", "Pass w0rd!", "P0!a"]:
    print(f"{pw!r:13} {is_strong(pw)}")
```

Результат:

```text
'Passw0rd!'   True
'passw0rd!'   False
'Password!'   False
'Passw0rd'    False
'Pass w0rd!'  False
'P0!a'        False
```

Три позитивні перегляди вимагають потрібних видів символів, а негативний перегляд `(?!.*\s)` відкидає будь-які пробільні символи. Усі чотири перевіряються на позиції 0. Текст поглинає лише `.{8,}`, а `fullmatch()` змушує його охопити весь пароль.

### Вправа 4

```python
import re

text = "banana"
matches = list(re.finditer(r"(?=ana)", text))

print(text.count("ana"))
print(len(matches))
print([m.start() for m in matches])
```

Результат:

```text
1
2
[1, 3]
```

Кожен збіг — це порожній рядок на позиції, з якої починається `ana`. Оскільки нічого не поглинається, пошук знаходить і друге `ana`, перша літера `a` якого збігається з останньою літерою першого.
