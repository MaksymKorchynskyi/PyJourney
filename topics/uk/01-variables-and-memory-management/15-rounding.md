# Округлення

Округлення замінює число простішим, але близьким до нього: `89`, округлене до десятків, дорівнює `90`, а `3.14159`, округлене до двох знаків після коми, — `3.14`. У Python для цього є вбудована функція `round()`, проте вона дотримується двох правил, які дивують багатьох: «половинки» округлюються до **парного** сусіда (`round(2.5)` дорівнює `2`), а float округлюється за його **точним двійковим значенням** (`round(2.675, 2)` дорівнює `2.67`). Розуміючи причини, ви зможете вибрати правильний інструмент для кожного завдання.

## Що ви дізнаєтесь

- Як працює `round(number, ndigits)` і який тип вона повертає
- Що означають додатні, нульове та від'ємні значення `ndigits`
- Чому «половинки» округлюються до парного сусіда і чому це зменшує зміщення
- Чому деякі float нібито округлюються «неправильно» і як побачити, що насправді зберігається
- Як правильно округлювати «половинки» від нуля і чому `int(x + 0.5)` ненадійний
- Коли округлювати і чим округлення для виведення відрізняється від округлення в обчисленнях

## Функція round()

```text
round(number, ndigits=None)
```

`round()` повертає `number`, округлене до **найближчого кратного `10 ** -ndigits`**. Для `ndigits=2` це найближче кратне `0.01`, для `ndigits=0` — найближче кратне `1`, а для `ndigits=-1` — найближче кратне `10`. Якщо `ndigits` не вказано або воно дорівнює `None`, результатом буде найближче ціле число:

```python
print(round(1.25))
print(round(1.25, None))
print(round(1.25, 0))
print(round(3.14159, 2))
print(round(-2.7))
```

Результат:

```text
1
1
1.0
3.14
-3
```

Порівняйте перший і третій рядки. В обох випадках результат — ціле значення, але тип різний.

### Тип результату

- Без `ndigits` (або з `None`) `round()` повертає `int`.
- З `ndigits`, навіть із `0`, функція повертає **той самий тип**, що й `number`: `float` для float, `int` для int, `Decimal` для `Decimal`, `Fraction` для `Fraction`.

```python
from decimal import Decimal
from fractions import Fraction

print(type(round(2.7)), type(round(2.7, 0)), type(round(2.7, 1)))
print(round(1234, 2), type(round(1234, 2)))
print(round(Decimal("2.675"), 2))
print(round(Fraction(7, 3), 2))
print(round(Fraction(7, 3)))
```

Результат:

```text
<class 'int'> <class 'float'> <class 'float'>
1234 <class 'int'>
2.68
233/100
2
```

За лаштунками `round(x, n)` викликає `type(x).__round__(x, n)`. Саме так `Decimal` і `Fraction` округлюються точно у власному представленні, і так само ваші класи можуть підтримати `round()`. Тип без методу `__round__()` функція відхиляє:

```python
print(round("2.5"))
```

Результат (останній рядок трасування):

```text
TypeError: type str doesn't define __round__ method
```

### Від'ємне ndigits

Від'ємне `ndigits` округлює до десятків, сотень, тисяч і так далі:

```python
print(round(15.5, -1))
print(round(1234, -2))
print(round(1_234_567, -3))
print(round(1250, -2))
print(round(1350, -2))
```

Результат:

```text
20.0
1200
1235000
1200
1400
```

Для `ndigits=-1` число `15.5` лежить між кратними десяти `10` і `20` і ближче до `20`. Результат — `20.0`, тобто float, бо на вході був float. Останні два рядки — це «половинки», рівно посередині між двома сотнями, і тут вступає в дію наступне правило.

## «Половинки»: округлення до парного

Коли число лежить рівно посередині між двома кандидатами, «найближчого» немає. Тоді Python вибирає кандидата, остання цифра якого **парна**. Це називається **округленням половини до парного** (round half to even), або **банківським округленням** (banker's rounding):

```python
for x in [0.5, 1.5, 2.5, 3.5, 4.5, -0.5, -1.5, -2.5]:
    print(f"round({x}) = {round(x)}")
```

Результат:

```text
round(0.5) = 0
round(1.5) = 2
round(2.5) = 2
round(3.5) = 4
round(4.5) = 4
round(-0.5) = 0
round(-1.5) = -2
round(-2.5) = -2
```

Правило стосується лише точних «половинок». `2.51` так само округлюється до `3`, а `2.49` — до `2`. Те саме правило діє в будь-якому розряді: `round(1250, -2)` дорівнює `1200`, бо цифра сотень `2` парна, а `round(1350, -2)` дорівнює `1400`, бо парна цифра `4`.

### Чому до парного

Шкільне правило «половина завжди округлюється вгору» має приховане **зміщення** (bias): кожна «половинка» збільшує значення, тож коли округлюють багато чисел, сума поступово «повзе» вгору. Округлення до парного відправляє половину «половинок» угору, а половину вниз, тож у середньому похибки взаємно компенсуються. Тому це стандартний режим округлення в стандарті рухомої коми IEEE 754 і в модулі `decimal`, і тому його використовують у статистиці та бухгалтерії.

```python
import math


def half_up(x):        # «половинки» завжди вгору; підходить для додатних чисел
    return math.floor(x + 0.5)


values = [1.5, 2.5, 3.5]
print(sum(values) / len(values))
print(sum(round(v) for v in values) / len(values))
print(sum(half_up(v) for v in values) / len(values))

values = [i + 0.5 for i in range(10)]    # 0.5, 1.5, ..., 9.5
print(sum(values))
print(sum(round(v) for v in values))
print(sum(half_up(v) for v in values))
```

Результат:

```text
2.5
2.6666666666666665
3.0
50.0
50
55
```

| Число | До парного | Половина вгору |
|---|---|---|
| 1.5 | 2 | 2 |
| 2.5 | 2 | 3 |
| 3.5 | 4 | 4 |
| **Середнє** (точне: 2.5) | 2.666... | 3.0 |

Справжнє середнє чисел `1.5`, `2.5` і `3.5` дорівнює `2.5`. Округлення «половина вгору» дає `3.0`, тобто помиляється на `0.5`. Округлення до парного дає `2.67`, значно ближче. На десяти значеннях `0.5 ... 9.5` округлення до парного зберігає точну суму `50`, а «половина вгору» перевищує її на `5`.

## Float, які нібито округлюються неправильно

Подивіться на такі результати:

```python
print(round(1.25, 1))
print(round(1.35, 1))
print(round(1.15, 1))
print(round(2.675, 2))
```

Результат:

```text
1.2
1.4
1.1
2.67
```

`1.25 -> 1.2` — це правило округлення до парного. Але `1.35 -> 1.4` — **не** «половинка», округлена до парного, а `1.15 -> 1.1` і `2.675 -> 2.67` взагалі схожі на помилки. Пояснення в тому, що більшість десяткових дробів не можна точно зберегти як двійковий float (див. тему «Дробові числа (float)»). `round()` працює зі значенням, яке **справді зберігається**, і `Decimal(x)` його показує:

```python
from decimal import Decimal

for x in [1.25, 1.35, 1.15, 2.675]:
    print(f"{x:<6} is stored as {Decimal(x)}")
```

Результат:

```text
1.25   is stored as 1.25
1.35   is stored as 1.350000000000000088817841970012523233890533447265625
1.15   is stored as 1.149999999999999911182158029987476766109466552734375
2.675  is stored as 2.67499999999999982236431605997495353221893310546875
```

- `1.25` — сума степенів двійки, тому зберігається точно. Це справжня «половинка», і округлення до парного дає `1.2`.
- `1.35` зберігається трохи **вище** за середину, тому округлюється вгору. «Половинки» тут немає.
- `1.15` і `2.675` зберігаються трохи **нижче** за середину, тому округлюються вниз.

`round()` тут не помиляється. Функція дає правильно округлений результат для того числа, яке насправді є в комп'ютері. Коли потрібне десяткове округлення, як на папері, працюйте зі значеннями `Decimal`, створеними з рядків (див. тему «Десяткові числа (Decimal)»).

## Округлення для виведення

Часто число округлюють лише для того, щоб його *показати*. Специфікації формату, як-от `:.2f`, округлюють так само, як `round()` (до парного, за збереженим значенням), але повертають рядок із фіксованою кількістю знаків після коми:

```python
price = 2.675
print(round(price, 2))
print(f"{price:.2f}")
print(f"{2.5:.0f} {3.5:.0f}")

total = 3.0
print(round(total, 2))
print(f"{total:.2f}")
print(f"{1234567.891:,.2f}")
```

Результат:

```text
2.67
2.67
2 4
3.0
3.00
1,234,567.89
```

`round(3.0, 2)` повертає float `3.0`, а float не пам'ятає, скільки знаків після коми вам потрібно. Для виведення використовуйте форматування: воно зберігає кінцеві нулі й уміє додавати роздільники тисяч.

### Округлюйте в кінці, а не посередині

Кожне округлення відкидає частину інформації. Якщо округлювати проміжні результати, похибки накопичуються:

```python
price = 1 / 3
print(round(price, 2) * 3)      # спершу округлити, потім обчислити
print(round(price * 3, 2))      # спершу обчислити, потім округлити один раз
```

Результат:

```text
0.99
1.0
```

Під час обчислень зберігайте повну точність і округлюйте один раз — коли зберігаєте чи показуєте остаточний результат.

## Спеціальні значення

З `ndigits` нескінченності й NaN повертаються без змін. Без `ndigits` функція `round()` має повернути `int`, а це неможливо:

```python
print(round(float("inf"), 2), round(float("nan"), 2))
print(round(float("inf")))
```

Результат (останній виклик завершується помилкою, показано останній рядок трасування):

```text
inf nan
OverflowError: cannot convert float infinity to integer
```

`round(float("nan"))` так само генерує `ValueError: cannot convert float NaN to integer`.

## Округлення половини від нуля

Іноді специфікація, податкове правило чи користувач очікують шкільного округлення: «половинки» зсуваються **від нуля** (`2.5 -> 3`, `-2.5 -> -3`). Вбудованої функції для цього в Python немає. Поширений прийом — додати `0.5` і відкинути дробову частину через `int()`:

```python
print(int(1.2 + 0.5))
print(int(1.5 + 0.5))
print(int(-1.2 + 0.5))
print(int(-1.5 + 0.5))
```

Результат:

```text
1
2
0
-1
```

Для додатних чисел це працює, а для від'ємних — ні: `-1.2` має дати `-1`, а `-1.5` — `-2`. Оскільки `int()` відкидає дробову частину в бік нуля, для від'ємних чисел `0.5` треба **віднімати**:

```python
print(int(-1.2 - 0.5))
print(int(-1.5 - 0.5))
```

Результат:

```text
-1
-2
```

`math.copysign(x, y)` повертає модуль `x` зі знаком `y`, тож `copysign(0.5, x)` дорівнює `0.5` для додатного `x` і `-0.5` для від'ємного. Так виходить версія без `if`:

```python
from math import copysign


def round_half_away(x):
    return int(x + copysign(0.5, x))


for x in [1.2, 1.5, 2.5, -1.2, -1.5, -2.5]:
    print(x, round_half_away(x), round(x))
```

Результат:

```text
1.2 1 1
1.5 2 2
2.5 3 2
-1.2 -1 -1
-1.5 -2 -2
-2.5 -3 -2
```

Третій стовпець для порівняння показує вбудовану `round()`: результати відрізняються лише на «половинках» `2.5` і `-2.5`.

### Чому додавати 0.5 ненадійно

`x + 0.5` — це теж операція з рухомою комою, і її результат округлюється. Для деяких вхідних даних це приховане округлення змінює відповідь:

```python
from math import copysign


def round_half_away(x):
    return int(x + copysign(0.5, x))


x = 0.49999999999999994      # найбільший float, менший за 0.5
print(x + 0.5)
print(round_half_away(x))
print(round(x))

y = 4503599627370497.0       # 2**52 + 1, уже ціле число
print(round_half_away(y))
print(round(y))
```

Результат:

```text
1.0
1
0
4503599627370498
4503599627370497
```

Число `0.49999999999999994 + 0.5` не можна точно подати як float, і воно округлюється до `1.0`, тож значення, менше за половину, перетворюється на `1`. Після `2**52` сусідні float відстоять один від одного на одиницю, тому додавання `0.5` створює «половинку», яка округлюється до парного сусіда, і ціле число змінюється. Вбудована `round()` правильно обробляє обидва випадки.

### Надійна версія з decimal

Модуль `decimal` реалізує режими округлення точно. Його режим `ROUND_HALF_UP` означає «до найближчого, половинки **від нуля**» (попри назву, `-2.5` стає `-3`). `Decimal.quantize()` округлює до експоненти свого аргументу, тож `Decimal("0.01")` означає «два знаки після коми»:

```python
from decimal import Decimal, ROUND_HALF_UP


def round_half_away(x, ndigits=0):
    quantum = Decimal(10) ** -ndigits          # 1, 0.1, 0.01, ...
    rounded = Decimal(repr(x)).quantize(quantum, rounding=ROUND_HALF_UP)
    return int(rounded) if ndigits == 0 else float(rounded)


for x in [2.5, -2.5, 0.5, 0.49999999999999994, 4503599627370497.0]:
    print(x, "->", round_half_away(x))

print(round_half_away(2.675, 2), round(2.675, 2))
print(round_half_away(1.25, 1), round(1.25, 1))
```

Результат:

```text
2.5 -> 3
-2.5 -> -3
0.5 -> 1
0.49999999999999994 -> 0
4503599627370497.0 -> 4503599627370497
2.68 2.67
1.3 1.2
```

`Decimal(repr(x))` будує десяткове число з найкоротшого рядкового запису float, `"2.675"`, а не з його точного двійкового значення `2.67499999...`. Тож ця функція округлює число *так, як воно записане*, і саме цього зазвичай очікує людина. Якщо потрібно округлювати точне збережене значення, використовуйте `Decimal(x)`. Для грошей найкращий варіант — узагалі уникати float і від самого початку зберігати суми як `Decimal`.

## Як вибрати інструмент округлення

| Інструмент | Правило | Повертає |
|---|---|---|
| `round(x)` | до найближчого, половинки до парного | `int` |
| `round(x, n)` | до найближчого кратного `10 ** -n`, половинки до парного | той самий тип, що й `x` |
| `math.floor(x)` | униз, у бік мінус нескінченності | `int` |
| `math.ceil(x)` | угору, у бік плюс нескінченності | `int` |
| `math.trunc(x)`, `int(x)` | у бік нуля | `int` |
| `f"{x:.2f}"` | до найближчого, половинки до парного | `str` |
| `Decimal.quantize(q, rounding=...)` | будь-який режим округлення `decimal` | `Decimal` |

`floor`, `ceil` і `trunc` розглянуто в темі «Перетворення float на int», а режими округлення `decimal` — у темі «Десяткові числа (Decimal)».

## Типові помилки

- **Очікувати, що `round(2.5)` дорівнює `3`.** Python округлює «половинки» до парного, тож результат — `2`. Якщо потрібне шкільне округлення, використовуйте `Decimal` з `ROUND_HALF_UP`.
- **Очікувати, що `round(2.675, 2)` дорівнює `2.68`.** Float зберігається як `2.67499999...`. Для точних десяткових значень використовуйте `Decimal("2.675")`.
- **Плутати `round(x)` і `round(x, 0)`.** Перший виклик повертає `int`, другий — `float` (для float на вході).
- **Використовувати `round()` для форматування виведення.** `round(3.0, 2)` дорівнює `3.0`, а не `3.00`. Пишіть `f"{x:.2f}"`.
- **Округлювати проміжні результати.** Округлення на кожному кроці накопичує похибку. Округлюйте один раз, у кінці.
- **Використовувати `int(x + 0.5)`.** Цей прийом неправильний для від'ємних чисел і ламається на граничних випадках навіть для додатних.
- **Порівнювати округлені float на рівність.** Два значення, що відрізняються на дрібницю, можуть округлитися по-різному. Порівнюйте float через `math.isclose()` (див. тему «Дробові числа (float)»).

## Підсумок

- `round(x)` повертає найближчий `int`. `round(x, n)` повертає найближче кратне `10 ** -n` того самого типу, що й `x`.
- `n` може бути від'ємним: `round(1234, -2)` дорівнює `1200`.
- Точні «половинки» округлюються до парного сусіда (банківське округлення), завдяки чому суми й середні не зміщуються.
- Float округлюється за точним двійковим значенням, тому `round(2.675, 2)` дорівнює `2.67`. Збережене значення можна побачити через `Decimal(x)`.
- Специфікації формату, як-от `:.2f`, округлюють так само й підходять саме для виведення.
- Округлюйте один раз, наприкінці обчислень.
- Для округлення «половинок» від нуля використовуйте `Decimal.quantize()` з `ROUND_HALF_UP`. Уникайте `int(x + 0.5)`.

### Вправа 1: Передбачте результат

Напишіть `round_half_away(x)`, яка округлює float до найближчого цілого, зсуваючи «половинки» від нуля, і використовує лише `math.floor()` та арифметику float, причому працює правильно й для `0.49999999999999994`, `-0.49999999999999994` та `4503599627370497.0`. ## Розв'язки

### Вправа 1


- `0.5`, `1.5` і `-2.5` — точні «половинки», тож вони йдуть до парного сусіда: `0`, `2`, `-2`.
- `round(7.0)` повертає `int`, а `round(7.0, 0)` — `float`.
- `2.675` зберігається трохи нижче за середину, тому округлюється вниз.
- `0.125` точно подається у двійковому вигляді (одна восьма), тож це справжня «половинка», і парний сусід — `0.12`.
- `1250` — «половинка» між `1200` і `1300`, а `2` — парна цифра. `1251` уже за серединою, тому округлюється вгору.

### Вправа 2

```python
def round_percentages(counts):
    total = sum(counts)
    result = []
    leftovers = []
    for i, count in enumerate(counts):
        whole, rest = divmod(count * 100, total)
        result.append(whole)
        leftovers.append((-rest, i))    # спершу найбільша остача, потім за позицією
    missing = 100 - sum(result)
    for _, i in sorted(leftovers)[:missing]:
        result[i] += 1
    return result


for counts in [[1, 1, 1], [1, 2, 2, 2], [2, 3, 5]]:
    naive = [round(c * 100 / sum(counts)) for c in counts]
    fixed = round_percentages(counts)
    print(counts, naive, sum(naive), fixed, sum(fixed))
```

Результат:

```text
[1, 1, 1] [33, 33, 33] 99 [34, 33, 33] 100
[1, 2, 2, 2] [14, 29, 29, 29] 101 [14, 29, 29, 28] 100
[2, 3, 5] [20, 30, 50] 100 [20, 30, 50] 100
```

`divmod(count * 100, total)` дає округлений униз відсоток і остачу в точних цілих числах, без жодного float. Округлення вниз втрачає менше одного відсотка на кожен елемент, тож бракує щонайбільше `len(counts) - 1` відсотків, і вони дістаються елементам, які були найближчі до наступного цілого відсотка. Завдяки `-rest` сортування за зростанням ставить найбільші остачі першими, а однакові впорядковує за позицією.

### Вправа 3

```python
def cash_round_naive(amount):
    return round(amount / 0.05) * 0.05


def cash_round(amount):
    return round(amount * 20) / 20


for amount in [0.16, 0.33, 1.38, 2.12, 9.99]:
    print(amount, cash_round_naive(amount), cash_round(amount))
```

Результат:

```text
0.16 0.15000000000000002 0.15
0.33 0.35000000000000003 0.35
1.38 1.4000000000000001 1.4
2.12 2.1 2.1
9.99 10.0 10.0
```

Проста версія правильно рахує кількість п'ятицентових кроків (`round(0.16 / 0.05)` дорівнює `3`), але потім множить на `0.05`, яке у двійковому вигляді неточне, тому `3 * 0.05` потрапляє поруч із `0.15`, а не точно в нього. Ділення цілого числа кроків на `20` — одна правильно округлена операція, тож результат є найближчим float до точного кратного й виводиться «чисто». Для справжніх грошей зберігайте суми в цілих центах (копійках) або в `Decimal`.

### Вправа 4

```python
import math
import random
from decimal import Decimal, ROUND_HALF_UP


def round_half_away(x):
    m = abs(x)
    n = math.floor(m)
    if m - n >= 0.5:      # для невід'ємного float m різниця m - n точна
        n += 1
    return n if x >= 0 else -n


def reference(x):
    return int(Decimal(x).quantize(Decimal(1), rounding=ROUND_HALF_UP))


tricky = [2.5, -2.5, 0.5, -0.5, 1.2, -1.7,
          0.49999999999999994, -0.49999999999999994, 4503599627370497.0]
for x in tricky:
    print(x, round_half_away(x), reference(x))

random.seed(1)
samples = [random.uniform(-1000, 1000) for _ in range(100_000)]
samples += [k / 2 for k in range(-200, 201)]    # багато точних «половинок»
print(all(round_half_away(x) == reference(x) for x in samples))
```

Результат:

```text
2.5 3 3
-2.5 -3 -3
0.5 1 1
-0.5 -1 -1
1.2 1 1
-1.7 -2 -2
0.49999999999999994 0 0
-0.49999999999999994 0 0
4503599627370497.0 4503599627370497 4503599627370497
True
```

До `x` нічого не додається, тож жодне приховане округлення не може перенести значення через середину. Дробова частина `m - n` невід'ємного float обчислюється точно, і порівняння з `0.5` визначає результат. Робота з `abs(x)` важлива: для `x = -0.49999999999999994` `math.floor(x)` дорівнює `-1`, а різниця `x - (-1)` неточна. Вона округлюється до `0.5`, і функція повернула б `-1` замість `0`.
