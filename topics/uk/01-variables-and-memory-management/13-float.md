# Дробові числа (float)

Для дійсних чисел на кшталт `3.14` чи `1.5e-5` Python використовує тип `float`. Такі числа швидкі й охоплюють величезний діапазон, але зберігаються у **двійковому** вигляді з фіксованою кількістю бітів. Більшість десяткових дробів, навіть найпростіших, як-от `0.1`, неможливо зберегти точно. Розуміння причин пояснює результати на кшталт `0.1 + 0.1 + 0.1 != 0.3` і показує, як правильно порівнювати такі числа.

## Що ви дізнаєтесь

- Як зберігається float: знак, порядок і мантиса в 64 бітах
- Які обмеження точності й діапазону має float і як їх переглянути
- Чому `0.1` зберігається лише наближено і як побачити значення, яке справді записано в пам'яті
- Як `float()` створює числа з чисел, рядків і власних об'єктів
- Що таке спеціальні значення `inf`, `nan` і `-0.0`
- Як порівнювати float за допомогою `math.isclose()` і зменшувати похибки округлення

## Тип float

Літерал float містить десяткову крапку або експоненту. Ділення через `/` завжди дає float:

```python
print(type(3.14))
print(1.5e-5)      # експоненційний запис: 1.5 x 10**-5
print(2e3)
print(1_000.5)     # підкреслення для читабельності
print(.5, 5.)      # цифри перед чи після крапки можна пропускати
print(7 / 2)       # звичайне ділення завжди повертає float
print(4 / 2)
```

Результат:

```text
<class 'float'>
1.5e-05
2000.0
1000.5
0.5 5.0
3.5
2.0
```

CPython реалізує `float` через тип `double` мови C, який майже на всіх платформах відповідає формату **подвійної точності IEEE 754**, або *binary64*. На відміну від `int`, що може зростати, доки вистачає пам'яті, значення float завжди займає рівно **64 біти (8 байтів)**.

## Як зберігається float

64 біти поділено на три поля:

```text
  1 біт       11 бітів            52 біти
+------+--------------+-----------------------------+
| знак |   порядок    |          мантиса            |
+------+--------------+-----------------------------+

значення = (-1)**знак  *  1.мантиса (у двійковому вигляді)  *  2**(порядок - 1023)
```

- **Знак** (1 біт): `0` для додатних чисел, `1` для від'ємних.
- **Порядок** (exponent, 11 бітів): степінь **двійки**, а не десятки. Для звичайних («нормалізованих») чисел він лежить у діапазоні від `-1022` до `1023`. Запис `1.5e-5` у коді — лише десяткова нотація; Python перетворює її на найближче двійкове значення вигляду `m * 2**e`.
- **Мантиса** (fraction, 52 біти): двійкові цифри після коми. Початкова `1.` мається на увазі й не зберігається, тож float фактично має **53 значущі біти**, що відповідає приблизно **15–17 значущим десятковим цифрам**.

*Значущі цифри* — це цифри числа без нулів на початку й у кінці: `0.25` має дві, `0.125` — три, `12.25` — чотири. Float уміщує приблизно 15–17 таких цифр; усе, що далі, округлюється.

Обмеження можна переглянути в `sys.float_info`:

```python
import sys

info = sys.float_info
print(info.max)
print(info.min)
print(info.epsilon)
print(info.mant_dig)
print(info.dig)
```

Результат:

```text
1.7976931348623157e+308
2.2250738585072014e-308
2.220446049250313e-16
53
15
```

`max` — найбільше скінченне число float, а `min` — найменше додатне *нормалізоване* число (існують і менші, «субнормальні» значення, але з нижчою точністю). `epsilon` — відстань між `1.0` і наступним числом float. `mant_dig` — ті самі 53 біти точності, а `dig` — кількість десяткових цифр, що гарантовано зберігаються після перетворення туди й назад (15).

### Які числа точні у двійковій системі?

Двійковий дріб — це сума степенів двійки. Деякі десяткові числа можна так записати кількома бітами:

```text
(1.25)10 = 1*2**0 + 0*2**-1 + 1*2**-2 = (1.01)2
```

Інші — ні. `0.1` у двійковій системі — періодичний дріб, так само як `1/3 = 0.333...` у десятковій:

```text
(0.1)10 = (0.0001100110011001100110011...)2     "0011" повторюється безкінечно
```

Float мусить обрізати цей нескінченний візерунок на 53 значущих бітах і округлити його, тож зберігається значення, дуже близьке до `0.1`, але не рівне йому. Загалом дріб точно представляється у двійковій системі лише тоді, коли його знаменник (після скорочення) — степінь двійки: `0.5`, `0.25`, `0.375` точні, а `0.1`, `0.2`, `0.3` — ні.

`float.hex()` і `float.as_integer_ratio()` показують збережені біти:

```python
print((1.25).hex())
print((0.1).hex())
print((0.1).as_integer_ratio())
print(2**55)
```

Результат:

```text
0x1.4000000000000p+0
0x1.999999999999ap-4
(3602879701896397, 36028797018963968)
36028797018963968
```

`1.25` — короткий «чистий» шістнадцятковий дріб. Для `0.1` видно повторюваний візерунок `999...`, округлений угору до `a` в кінці, а насправді зберігається дріб `3602879701896397 / 2**55`.

## Яке значення зберігається насправді

Коли ви виводите float, Python показує **найкоротший** десятковий рядок, який перетворюється назад рівно в те саме число (Python 3.1+). Тому `0.1` виводиться як `0.1`, хоча збережене значення трохи інше. Щоб побачити більше цифр, відформатуйте число з фіксованою точністю. Щоб побачити збережене значення **точно**, перетворіть його на `Decimal`:

```python
from decimal import Decimal

x = 0.1
print(x)
print(repr(x))
print(format(x, ".20f"))
print(Decimal(x))
```

Результат:

```text
0.1
0.1
0.10000000000000000555
0.1000000000000000055511151231257827021181583404541015625
```

Зверніть увагу: збережене значення має **скінченну** кількість десяткових цифр. Будь-який двійковий дріб можна точно записати в десятковому вигляді (бо 10 ділиться на 2); не працює лише зворотний напрямок. Похибка виникає через округлення `0.1` до найближчого двійкового дробу, а не через нескінченний запис збереженого значення.

## Створення чисел за допомогою float()

Конструктор `float()` перетворює числа й рядки на float:

```python
print(float(0.1))
print(float("1.25"))
print(float("  -1e3 \n"))
print(float("1_000.5"))
print(float(7))
print(float())
print(float("inf"), float("-Infinity"), float("nan"))
```

Результат:

```text
0.1
1.25
-1000.0
1000.5
7.0
0.0
inf -inf nan
```

Рядок може містити пробіли на краях, експоненту, підкреслення між цифрами, а також спеціальні назви `inf`, `infinity` і `nan` у будь-якому регістрі. Без аргументу `float()` повертає `0.0`. Рядок, який не є числом, призводить до `ValueError`:

```python
print(float("abc"))
```

Результат (останній рядок traceback):

```text
ValueError: could not convert string to float: 'abc'
```

Для інших об'єктів `float(obj)` викликає `obj.__float__()`. Якщо в класі немає `__float__()`, Python звертається до `__index__()` (Python 3.8+) — методу, який реалізують цілочисельні об'єкти:

```python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    def __float__(self):
        return float(self.celsius)


class Port:
    def __init__(self, number):
        self.number = number

    def __index__(self):
        return self.number


print(float(Temperature(21.5)))
print(float(Port(8080)))
```

Результат:

```text
21.5
8080.0
```

У Python 3.14 з'явився метод класу `float.from_number()`. Він працює як `float()`, але приймає лише числа й ніколи не приймає рядки. Це корисно, коли рядок на вході свідчить про помилку в програмі:

```python
print(float.from_number(3))
print(float.from_number(2.5))

try:
    float.from_number("1.5")
except TypeError as error:
    print("TypeError:", error)
```

Результат:

```text
3.0
2.5
TypeError: must be real number, not str
```

## Спеціальні значення: inf, nan і -0.0

Стандарт IEEE 754 визначає кілька спеціальних значень, і Python підтримує їх усі:

```python
import math

inf = float("inf")
nan = float("nan")

print(inf + 1, -inf * 2, inf - inf)
print(1e308 * 10)
print(nan == nan, nan != nan)
print(math.isnan(nan), math.isinf(inf), math.isfinite(1.5))
print(-0.0 == 0.0, math.copysign(1, -0.0))
```

Результат:

```text
inf -inf nan
inf
False True
True True True
True -1.0
```

- `inf` (нескінченність) більша за будь-яке скінченне число. Множення з переповненням дає `inf` (`1e308 * 10`).
- `nan` («не число», not a number) — результат невизначених операцій на кшталт `inf - inf`. Воно **не дорівнює нічому, навіть самому собі**, тож перевіряйте його через `math.isnan()`, а не через `==`.
- `-0.0` існує й дорівнює `0.0`, але зберігає знак (його видно через `math.copysign()`).

Деякі операції замість `inf` генерують `OverflowError`. Піднесення до степеня — одна з них:

```python
print(10.0 ** 400)
```

Результат (останній рядок traceback):

```text
OverflowError: (34, 'Result too large')
```

Перетворення завеликого для float цілого числа (`float(2**1024)`) теж генерує `OverflowError`. А цілі числа, більші за `2**53`, під час перетворення втрачають точність, бо 53 бітів не вистачає:

```python
big = 2**53 + 1
print(big)
print(float(big))
print(float(big) == 2**53)
```

Результат:

```text
9007199254740993
9007199254740992.0
True
```

## Перевірка на рівність

Оскільки багато значень наближені, арифметика може давати результати, що відрізняються від «очевидної» відповіді в останніх бітах:

```python
x = 0.1 + 0.1 + 0.1
y = 0.3

print(x == y)
print(x, y)
print(format(x, ".20f"))
print(format(y, ".20f"))
```

Результат:

```text
False
0.30000000000000004 0.3
0.30000000000000004441
0.29999999999999998890
```

Кожне `0.1` трохи більше за одну десяту, а додавання ще раз округлює результат. У підсумку отримуємо інше число float, ніж найближче до `0.3`.

### Округлення перед порівнянням (ненадійно)

Один зі способів обійти проблему — округлити обидві частини до певної кількості знаків після коми:

```python
x = 0.1 + 0.1 + 0.1
y = 0.3
print(round(x, 3) == round(y, 3))

a = 1.0049999999
b = 1.0050000001
print(round(a, 2), round(b, 2), round(a, 2) == round(b, 2))
```

Результат:

```text
True
1.0 1.01 False
```

Другий випадок показує, чому це ненадійно: два числа, що відрізняються лише на `0.0000000002`, потрапляють по різні боки від межі округлення й вважаються нерівними.

### math.isclose(): надійний спосіб

[PEP 485](https://peps.python.org/pep-0485/) (Python 3.5) додав функцію `math.isclose()`, яка перевіряє, чи близькі два числа **відносно свого розміру**:

```text
math.isclose(a, b, *, rel_tol=1e-09, abs_tol=0.0)

True, якщо  abs(a - b) <= max(rel_tol * max(abs(a), abs(b)), abs_tol)
```

`rel_tol` — допустима відносна різниця (за замовчуванням `1e-09`, тобто приблизно дев'ять однакових значущих цифр), а `abs_tol` — мінімальний абсолютний допуск. Обидва аргументи можна передавати лише за іменем.

```python
from math import isclose

x = 0.1 + 0.1 + 0.1
y = 0.3

print(isclose(x, y))
print(isclose(1.0049999999, 1.0050000001))
print(isclose(1000.0, 1000.1))
print(isclose(1000.0, 1000.1, rel_tol=1e-3))
```

Результат:

```text
True
True
False
True
```

Тут є важлива пастка. **Відносний** допуск марний, коли одна зі сторін дорівнює нулю, адже «дев'ять цифр від нуля» — це все одно нуль. Порівнюючи з `0.0`, передавайте `abs_tol`:

```python
from math import isclose

tiny = 0.1 + 0.2 - 0.3
print(tiny)
print(isclose(tiny, 0.0))
print(isclose(tiny, 0.0, abs_tol=1e-9))
```

Результат:

```text
5.551115123125783e-17
False
True
```

## Як зменшити накопичення похибок

Коли ви поєднуєте багато чисел float, похибки округлення накопичуються. Python пропонує кілька інструментів:

```python
import math
from fractions import Fraction

total = 0.0
for _ in range(10):
    total += 0.1
print(total)

print(sum([0.1] * 10))          # компенсоване підсумовування з Python 3.12
print(math.fsum([0.1] * 10))    # коректно округлена сума

print(Fraction(1, 10) * 3 == Fraction(3, 10))
print(Fraction("0.1") + Fraction("0.2"))
```

Результат:

```text
0.9999999999999999
1.0
1.0
True
3/10
```

- Звичайний цикл із `+=` накопичує похибку на кожному кроці.
- Починаючи з **Python 3.12**, вбудована `sum()` для float використовує компенсоване підсумовування (алгоритм Ноймаєра), яке зберігає більшу частину втраченої точності. У старіших версіях `sum([0.1] * 10)` теж дає `0.9999999999999999`.
- `math.fsum()` повертає коректно округлену суму в будь-якій версії.
- `fractions.Fraction` зберігає точні раціональні числа. Створюйте його з рядка або двох цілих чисел, а не з float.
- Для грошей та інших десяткових величин використовуйте цілі числа (копійки) або `decimal.Decimal` (див. тему про Decimal).

## Типові помилки

- **Порівнювати обчислені float через `==`.** Використовуйте `math.isclose()`, а коли одна зі сторін може бути нулем, додавайте `abs_tol`.
- **Використовувати float для грошей.** `0.1 + 0.2` дорівнює `0.30000000000000004`. Зберігайте суми в копійках (`int`) або використовуйте `Decimal`.
- **Перевіряти `nan` через `==`.** `x == float("nan")` завжди дорівнює `False`. Пишіть `math.isnan(x)`.
- **Вважати, що `print()` показує точне значення.** Він показує найкоротший рядок, що перетворюється назад у те саме число. Щоб роздивитися ближче, використовуйте `Decimal(x)` або `format(x, ".20f")`.
- **Перетворювати великі цілі числа на float.** Після `2**53` не кожне ціле число має представлення у float, тож `float(2**53 + 1)` непомітно стає `2**53`. Зберігайте великі цілі як `int`.
- **Вважати порядок десятковим.** `1.5e-5` — лише спосіб *записати* число; всередині воно зберігається як двійковий дріб, помножений на степінь двійки.

## Підсумок

- `float` — 64-бітне двійкове число з рухомою комою за стандартом IEEE 754: 1 біт знака, 11 бітів порядку (степінь двійки) і 52 біти мантиси плюс неявна початкова одиниця.
- Це дає 53 значущі біти, приблизно 15–17 значущих десяткових цифр і діапазон приблизно до `1.8e308` (`sys.float_info`).
- Точно зберігаються лише дроби, знаменник яких — степінь двійки. `0.1`, `0.2` і `0.3` зберігаються наближено.
- `print()` показує найкоротший рядок, що перетворюється назад у те саме число. `Decimal(x)` показує точне збережене значення.
- `float()` приймає числа, числові рядки, `"inf"`/`"nan"` та об'єкти з `__float__()` або `__index__()`. `float.from_number()` (3.14+) приймає лише числа.
- `nan` не дорівнює самому собі. Використовуйте `math.isnan()`, `math.isinf()` і `math.isfinite()`.
- Порівнюйте float через `math.isclose()`. Коли важлива точність, використовуйте `math.fsum()`, `Fraction`, `Decimal` або цілі числа.

## Практика

### Вправа 1: Точно чи ні?

Передбачте, що виведе кожен рядок, `True` чи `False`, а потім запустіть код. Для кожного результату поясніть, які числа точні у двійковій системі.

```python
print(0.1 + 0.2 == 0.3)
print(0.5 + 0.25 == 0.75)
print(1e16 + 1 == 1e16)
print(float("nan") == float("nan"))
print(0.1 * 3 == 0.3 * 1)
print(2.0 ** 0.5 * 2.0 ** 0.5 == 2.0)
```

### Вправа 2: Де цілі числа перестають бути точними

Напишіть цикл, який знаходить найменше `k`, для якого `float(2**k) + 1 == float(2**k)`, тобто момент, коли додавання одиниці вже не змінює число float. Виведіть `k` і `2**k`. Пов'яжіть відповідь із `sys.float_info.mant_dig`.

### Вправа 3: Сума цін

Десять товарів коштують по `0.10`. Обчисліть загальну суму трьома способами: циклом `for` з `+=`, за допомогою `math.fsum()` і в цілих центах. Виведіть кожен результат і те, чи дорівнює він одному долару.

### Вправа 4: Власна isclose()

Реалізуйте функцію `is_close(a, b, rel_tol=1e-9, abs_tol=0.0)` за формулою з PEP 485, не імпортуючи `math` усередині неї. Потім перевірте, що вона збігається з `math.isclose()` для таких пар: `(0.1 + 0.2, 0.3)`, `(1000.0, 1000.1)`, `(1000.0, 1000.1)` з `rel_tol=1e-3`, `(1e-12, 0.0)` і `(1e-12, 0.0)` з `abs_tol=1e-9`.

## Розв'язки

### Вправа 1

Результат:

```text
False
True
True
False
False
False
```

- `0.1`, `0.2` і `0.3` — наближення, і похибки округлення не компенсують одна одну.
- `0.5`, `0.25` і `0.75` — суми степенів двійки, тож вони точні, і сума теж точна.
- Біля `1e16` відстань між сусідніми числами float дорівнює `2.0`, тому додана `1` округлюється назад до `1e16`.
- `nan` ніколи нічому не дорівнює.
- `0.1 * 3` дорівнює `0.30000000000000004`, а `0.3 * 1` — найближчому до `0.3` числу float.
- `2.0 ** 0.5` — округлене значення квадратного кореня, і його квадрат дорівнює `2.0000000000000004`.

### Вправа 2

```python
k = 0
while float(2**k) + 1 != float(2**k):
    k += 1

print(k)
print(2**k)
print(float(2**k) + 1)
```

Результат:

```text
53
9007199254740992
9007199254740992.0
```

Float має 53 значущі біти (`sys.float_info.mant_dig`). Після `2**53` відстань між сусідніми числами float дорівнює `2`, тож `+ 1` потрапляє рівно посередині й округлюється назад (у разі рівновіддаленості вибирається парний сусід).

### Вправа 3

```python
import math

prices = [0.10] * 10

total = 0.0
for price in prices:
    total += price
print(total, total == 1.0)

print(math.fsum(prices), math.fsum(prices) == 1.0)

cents = [10] * 10
total_cents = sum(cents)
print(total_cents, f"{total_cents // 100}.{total_cents % 100:02}")
```

Результат:

```text
0.9999999999999999 False
1.0 True
100 1.00
```

Цикл накопичує похибку. `math.fsum()` округлює лише один раз, наприкінці. Цілі центи взагалі усувають похибку рухомої коми; у долари їх перетворюють лише для відображення.

### Вправа 4

```python
import math


def is_close(a, b, rel_tol=1e-9, abs_tol=0.0):
    return abs(a - b) <= max(rel_tol * max(abs(a), abs(b)), abs_tol)


pairs = [
    (0.1 + 0.2, 0.3, {}),
    (1000.0, 1000.1, {}),
    (1000.0, 1000.1, {"rel_tol": 1e-3}),
    (1e-12, 0.0, {}),
    (1e-12, 0.0, {"abs_tol": 1e-9}),
]
for a, b, options in pairs:
    mine = is_close(a, b, **options)
    print(mine, mine == math.isclose(a, b, **options))
```

Результат:

```text
True True
False True
True True
False True
True True
```

Перший стовпчик — результат `is_close()`, другий підтверджує, що він збігається з `math.isclose()`. Справжня `math.isclose()` додатково перевіряє, що допуски невід'ємні, і особливим чином обробляє `inf` та `nan`.
