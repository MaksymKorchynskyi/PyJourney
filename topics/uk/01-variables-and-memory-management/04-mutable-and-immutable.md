# Змінювані та незмінювані об'єкти

Кожен об'єкт у Python має ідентичність, тип і значення. У деяких об'єктів значення може змінюватися після створення: вони **змінювані** (mutable). В інших воно не змінюється ніколи: вони **незмінювані** (immutable), і кожна «зміна» насправді створює новий об'єкт. Розуміння цієї різниці пояснює помилки через спільні посилання, те, чому список не може бути ключем словника, і чому `+=` іноді змінює «іншу» змінну.

## Що ви дізнаєтесь

- Що означає «змінюваний» і «незмінюваний» та які вбудовані типи належать до кожної групи
- Як побачити різницю за допомогою `id()` та `is`
- Чому спільні посилання безпечні для незмінюваних об'єктів і небезпечні для змінюваних
- Чому `+=` поводиться по-різному для списків і кортежів
- Чому незмінюваний кортеж усе ж може містити дані, що змінюються
- Чому ключами словника й елементами множини можуть бути лише хешовані (зазвичай незмінювані) об'єкти і як створити власний незмінюваний клас

## Змінювані й незмінювані об'єкти

**Внутрішній стан** об'єкта — це дані, які він зберігає: цифри числа, символи рядка, елементи списку.

- Об'єкт **незмінюваний**, якщо його стан не може змінитися після створення.
- Об'єкт **змінюваний**, якщо він має способи змінити свій стан на місці.

| Незмінювані | Змінювані |
|---|---|
| `int`, `float`, `complex`, `bool` | `list` |
| `str`, `bytes` | `dict` |
| `tuple`, `frozenset` | `set` |
| `range`, `None` | `bytearray` |

Екземпляри ваших власних класів за замовчуванням змінювані (їхнім атрибутам можна присвоювати нові значення), але їх можна спроєктувати незмінюваними, як показано наприкінці цієї теми.

## Приклад незмінюваності: числа й рядки

Коли ви присвоюєте число, Python створює (або використовує наявний) об'єкт `int` і прив'язує до нього ім'я. `id()` показує ідентичність об'єкта, а `hex()` — те саме число в шістнадцятковому вигляді:

```python
counter = 100
print(id(counter))
print(hex(id(counter)))
```

Результат (змінюється від запуску до запуску й між комп'ютерами):

```text
4359224352
0x103d47c20
```

Тепер «змінимо» лічильник. Збережемо друге посилання на початковий об'єкт, щоб було з чим порівняти:

```python
counter = 100
before = counter      # друге посилання на початковий об'єкт

counter = 200
print(counter)
print(before)
print(counter is before)
```

Результат:

```text
200
100
False
```

Здається, ніби значення `counter` змінилося, але цілочисловий об'єкт `100` ніхто не змінював. Python створив (у цьому випадку — взяв готовий) об'єкт `200` і **перев'язав** на нього ім'я `counter`. Об'єкт `100` лишився недоторканим, що й доводить `before`.

```text
до присвоєння:                  після counter = 200:

counter --+                     counter ---> int 200
          +--> int 100
before ---+                     before  ---> int 100
```

Рядки поводяться так само. Кожен метод рядка повертає **новий** рядок, а присвоєння елементу заборонене:

```python
name = "python"
upper_name = name.upper()

print(name)
print(upper_name)

name[0] = "P"
```

Результат:

```text
python
PYTHON
Traceback (most recent call last):
  ...
TypeError: 'str' object does not support item assignment
```

## Приклад змінюваності: списки, словники й множини

Список можна змінювати на місці. Об'єкт лишається тим самим, змінюється лише його вміст:

```python
ratings = [1, 2, 3]
before = ratings      # друге посилання на той самий список

ratings.append(4)
ratings[0] = 10
del ratings[1]

print(ratings)
print(before)
print(ratings is before)
```

Результат:

```text
[10, 3, 4]
[10, 3, 4]
True
```

`append()`, присвоєння елементу та `del` змінюють наявний список, тож ім'я не потрібно перев'язувати, а `before` бачить усі зміни. Словники й множини працюють так само:

```python
settings = {"theme": "dark"}
settings["font"] = "mono"
settings.pop("theme")
print(settings)

tags = {"python"}
tags.add("memory")
print(sorted(tags))
```

Результат:

```text
{'font': 'mono'}
['memory', 'python']
```

> **Зверніть увагу:** корисне практичне правило: методи, що змінюють об'єкт на місці, зазвичай повертають `None` (`list.append()`, `list.sort()`, `dict.update()`), а операції над незмінюваними об'єктами повертають новий об'єкт (`str.upper()`, `tuple + tuple`).

## Чому це важливо: спільні посилання

Коли два імені посилаються на той самий об'єкт, вони є **псевдонімами** (aliases). Для незмінюваних об'єктів це безпечно: спільний об'єкт ніхто не може змінити, тож «зміна» одного імені лише перев'язує його. Для змінюваних об'єктів кожна зміна на місці видна через усі псевдоніми. Саме це сталося з `before` у прикладі зі списком вище.

Тому незмінювані об'єкти можна без копіювання передавати між функціями, потоками й структурами даних, а змінювані доводиться копіювати (`list.copy()`, `dict.copy()`, `copy.deepcopy()`), коли потрібні незалежні дані.

## `+=`: зміна на місці чи новий об'єкт?

Складене присвоєння (augmented assignment) виглядає однаково для всіх типів, але робить різні речі:

- для **змінюваних** типів, що його підтримують (`list`, `set`, `dict` з `|=`), `x += y` змінює об'єкт на місці;
- для **незмінюваних** типів (`int`, `str`, `tuple`) воно створює новий об'єкт і перев'язує ім'я.

```python
nums = [1, 2]
alias = nums
nums += [3]          # список: змінюється той самий об'єкт
print(alias)
print(nums is alias)

nums = nums + [4]    # створюється новий список, nums перев'язується
print(alias)
print(nums is alias)

point = (1, 2)
alias_point = point
point += (3,)        # кортеж: завжди створюється новий об'єкт
print(alias_point)
print(point)
print(point is alias_point)
```

Результат:

```text
[1, 2, 3]
True
[1, 2, 3]
False
(1, 2)
(1, 2, 3)
False
```

Зверніть увагу: для списків `nums += [3]` і `nums = nums + [3]` **не** рівнозначні. Перший вираз змінює спільний список, другий будує новий.

## Незмінюваний — не означає «заморожений до самого дна»

Кортеж незмінюваний: у ньому не можна додати, видалити чи замінити елемент. Але кортеж зберігає **посилання**, а об'єкти, на які вони вказують, самі можуть бути змінюваними:

```python
low = [1, 2, 3]
high = [4, 5]

rankings = (low, high)

high.append(6)
print(rankings)

rankings[1].append(7)
print(rankings)
print(high)
```

Результат:

```text
([1, 2, 3], [4, 5, 6])
([1, 2, 3], [4, 5, 6, 7])
[4, 5, 6, 7]
```

Кортеж і далі містить ті самі два списки, тож із його погляду нічого не змінилося. Змінилися списки всередині. А от замінити елемент не можна:

```python
low = [1, 2, 3]
high = [4, 5]
rankings = (low, high)

rankings[1] = [9, 9]
```

Результат:

```text
Traceback (most recent call last):
  ...
TypeError: 'tuple' object does not support item assignment
```

```text
rankings (кортеж, фіксований) --> комірка 0 ---> list [1, 2, 3]      <- список може змінюватися
                                  комірка 1 ---> list [4, 5, 6, 7]   <- список може змінюватися
              самі комірки ніколи не можуть вказати на інший об'єкт
```

### Пастка `+=` із кортежем списків

Поєднайте дві попередні ідеї, і отримаєте одну з найвідоміших головоломок Python:

```python
pair = ([1, 2], [3])

try:
    pair[0] += [99]
except TypeError as error:
    print("TypeError:", error)

print(pair)
```

Результат:

```text
TypeError: 'tuple' object does not support item assignment
([1, 2, 99], [3])
```

Операція **водночас і невдала, і успішна**. `pair[0] += [99]` виконується у два кроки: спершу `list.__iadd__` розширює список на місці (це працює), а потім Python намагається записати результат назад через `pair[0] = ...` (це не вдається, бо кортежі не підтримують присвоєння елементам). Замість цього пишіть `pair[0].append(99)` або `pair[0].extend([99])`.

## Хешованість: чому список не може бути ключем словника

Словники й множини шукають елементи за їхнім **хешем** — числом, обчисленим зі значення. Якби значення ключа могло змінитися після того, як його збережено, змінився б і хеш, і словник більше не зміг би знайти цей ключ. Тому ключі словника й елементи множини мають бути **хешованими** (hashable), а вбудовані змінювані типи такими не є:

```python
locations = {(50.45, 30.52): "Kyiv", (49.84, 24.03): "Lviv"}
print(locations[(49.84, 24.03)])

visited = {[50.45, 30.52]: "Kyiv"}
```

Результат (Python 3.14):

```text
Lviv
Traceback (most recent call last):
  ...
TypeError: cannot use 'list' as a dict key (unhashable type: 'list')
```

Старіші версії виводять просто `TypeError: unhashable type: 'list'`. Кортеж хешований лише тоді, коли хешоване все, що в ньому міститься, тож кортеж списків `rankings` з прикладу вище теж не може бути ключем:

```python
low = [1, 2, 3]
high = [4, 5]
rankings = (low, high)
print(hash(rankings))
```

Результат:

```text
Traceback (most recent call last):
  ...
TypeError: unhashable type: 'list'
```

Якщо потрібна множина множин, використовуйте `frozenset` — незмінювану версію `set`:

```python
groups = {frozenset({"ann", "bob"}), frozenset({"bob", "ann"}), frozenset({"eve"})}
print(len(groups))
print(frozenset({"ann", "bob"}) in groups)
```

Результат:

```text
2
True
```

## Як створити власні незмінювані об'єкти

Найпростіший спосіб створити незмінюваний клас — заморожений датаклас (frozen dataclass). Замість того щоб змінювати об'єкт, ви створюєте новий:

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Point:
    x: int
    y: int


p = Point(1, 2)
moved = Point(p.x + 10, p.y)
print(p, moved)
print({p, Point(1, 2)})

p.x = 5
```

Результат:

```text
Point(x=1, y=2) Point(x=11, y=2)
{Point(x=1, y=2)}
Traceback (most recent call last):
  ...
dataclasses.FrozenInstanceError: cannot assign to field 'x'
```

Заморожений датаклас ще й хешований, тож однакові точки зливаються в один елемент множини. `collections.namedtuple` і `typing.NamedTuple` — інші способи створити невеликі незмінювані записи.

## Типові помилки

- **Викликати метод рядка й ігнорувати результат.** Сам по собі `name.upper()` нічого корисного не робить. Пишіть `name = name.upper()`.
- **Присвоювати результат методу, що змінює об'єкт на місці.** `items = items.sort()` записує в `items` значення `None`. Пишіть `items.sort()` або `items = sorted(items)`.
- **Вважати, що вміст кортежу ніколи не змінюється.** Кортеж списків може змінитися через ці списки. Справді сталим є лише кортеж незмінюваних об'єктів.
- **Вважати `a += b` і `a = a + b` однаковими для списків.** Перше змінює спільний список, друге створює новий.
- **Використовувати список як ключ словника чи елемент множини.** Перетворіть його на кортеж (`tuple(coords)`), а множину — на `frozenset`.
- **Порівнювати збережений `id()` із пізнішим, коли початкового об'єкта вже немає.** Ідентифікатор знищеного об'єкта може дістатися новому. Зберігайте посилання (як `before` вище) і використовуйте `is`.

## Підсумок

- Незмінювані об'єкти (`int`, `float`, `bool`, `str`, `bytes`, `tuple`, `frozenset`, `None`) ніколи не змінюються після створення. Кожна «зміна» створює новий об'єкт.
- Змінювані об'єкти (`list`, `dict`, `set`, `bytearray`, більшість екземплярів класів) можна змінювати на місці, і кожен псевдонім бачить ці зміни.
- Перев'язування імені — не те саме, що зміна об'єкта. Щоб зрозуміти, що саме сталося, використовуйте `is` (або `id()`).
- `+=` змінює списки на місці, але для незмінюваних типів створює нові об'єкти.
- Незмінюваність поверхнева: комірки кортежу фіксовані, але об'єкти в них можуть бути змінюваними.
- Ключі словника й елементи множини мають бути хешованими. Вбудовані незмінювані типи хешовані, якщо хешований їхній вміст.
- Заморожені датакласи й іменовані кортежі дають змогу створювати власні незмінювані типи.

## Практика

### Вправа 1: Той самий об'єкт чи новий?

Для кожного блоку передбачте, чи виведе остання перевірка `is` значення `True` (об'єкт змінено на місці) чи `False` (ім'я перев'язано на новий об'єкт).

```python
a = "hello"
original_a = a
a += " world"
print(a is original_a)

b = [1, 2]
original_b = b
b += [3]
print(b is original_b)

c = {"x": 1}
original_c = c
c["y"] = 2
print(c is original_c)

d = (1, 2)
original_d = d
d = d + (3,)
print(d is original_d)

e = {1, 2}
original_e = e
e |= {3}
print(e is original_e)
```

### Вправа 2: Поясніть головоломку

Не запускаючи код нижче, передбачте результат. Потім запустіть його й покроково поясніть, чому виняток генерується, *а* список усе одно змінюється.

```python
pair = ([1, 2], [3])

try:
    pair[0] += [99]
except TypeError as error:
    print("TypeError:", error)

print(pair)
```

### Вправа 3: Унікальні точки

Ви отримуєте точки у вигляді списків: `[[1, 2], [3, 4], [1, 2], [0, 0], [3, 4]]`. Напишіть `unique_points(points)`, яка повертає **множину** унікальних точок. Виведіть їх кількість і відсортований результат. Чому множина не може містити самі списки?

### Вправа 4: Незмінювані гроші

Створіть заморожений датаклас `Money` з полями `amount: int` і `currency: str` та методом `add(other)`, що повертає **новий** об'єкт `Money` (якщо валюти різні, згенеруйте `ValueError`). Покажіть, що:

- `add()` не змінює початковий об'єкт;
- присвоєння `price.amount = 0` генерує `FrozenInstanceError`;
- два однакові об'єкти `Money` у множині вважаються одним елементом.

## Розв'язки

### Вправа 1

Результат:

```text
False
True
True
False
True
```

- `str` незмінюваний: `+=` створив новий рядок.
- `+=` для списку розширює той самий список на місці.
- Присвоєння ключа змінює словник.
- `d + (3,)` завжди створює новий кортеж.
- `|=` для множини оновлює ту саму множину на місці.

### Вправа 2

Результат:

```text
TypeError: 'tuple' object does not support item assignment
([1, 2, 99], [3])
```

`pair[0] += [99]` приблизно означає `pair[0] = pair[0].__iadd__([99])`:

1. `pair[0]` повертає перший список.
2. `list.__iadd__([99])` розширює цей список **на місці**, і він стає `[1, 2, 99]`.
3. Далі Python намагається виконати `pair[0] = <той самий список>`. Кортежі не підтримують присвоєння елементам, тому генерується `TypeError`, але крок 2 уже відбувся.

### Вправа 3

```python
def unique_points(points):
    return {tuple(point) for point in points}


raw = [[1, 2], [3, 4], [1, 2], [0, 0], [3, 4]]
unique = unique_points(raw)
print(len(unique))
print(sorted(unique))
```

Результат:

```text
3
[(0, 0), (1, 2), (3, 4)]
```

Списки змінювані, а отже, не хешовані, тому `{[1, 2]}` генерує `TypeError`. Кортежі чисел хешовані, і однакові кортежі зливаються в один елемент.

### Вправа 4

```python
from dataclasses import FrozenInstanceError, dataclass


@dataclass(frozen=True)
class Money:
    amount: int
    currency: str

    def add(self, other):
        if other.currency != self.currency:
            raise ValueError("currencies differ")
        return Money(self.amount + other.amount, self.currency)


price = Money(100, "UAH")
total = price.add(Money(50, "UAH"))
print(price)
print(total)

try:
    price.amount = 0
except FrozenInstanceError as error:
    print("FrozenInstanceError:", error)

wallet = {price, Money(100, "UAH"), total}
print(len(wallet))
```

Результат:

```text
Money(amount=100, currency='UAH')
Money(amount=150, currency='UAH')
FrozenInstanceError: cannot assign to field 'amount'
2
```

`price` і `Money(100, "UAH")` рівні й мають однаковий хеш, тож множина зберігає лише один із них, а також `total`.
