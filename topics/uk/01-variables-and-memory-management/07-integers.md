# Цілі числа

Цілі числа — це числа без дробової частини: від'ємні, нуль і додатні, як-от `-3`, `0` і `42`. У Python кожне ціле число — об'єкт класу `int`, і, на відміну від більшості мов, `int` не має фіксованого розміру: він може зростати, доки вистачає пам'яті. У цій темі пояснено, як комп'ютери зберігають цілі числа у двійковому вигляді, чим цілі числа довільної точності в Python відрізняються від чисел фіксованої ширини і чого це коштує з погляду пам'яті та швидкодії.

## Що ви дізнаєтесь

- Як цілі числа записуються у двійковій системі і скільки значень уміщують `n` бітів
- Як працюють знакові цілі числа (доповняльний код) і звідки беруться діапазони на кшталт `-128..127`
- Як Python зберігає цілі числа зі змінною кількістю бітів і які обмеження все ж лишаються
- Як виміряти розмір цілого числа в пам'яті за допомогою `sys.getsizeof()`
- Літерали цілих чисел (`0b`, `0o`, `0x`, `1_000_000`) і перетворення через `int()`
- Які операції повертають `int`, а які — `float`

## Клас `int`

Усі цілі числа в Python — екземпляри `int`:

```python
counter = 10
print(type(counter))
print(isinstance(-3, int), isinstance(True, int))
```

Результат:

```text
<class 'int'>
True True
```

`bool` — підклас `int`: в арифметиці `True` поводиться як `1`, а `False` — як `0`.

## Як комп'ютери зберігають цілі числа

Пам'ять зберігає лише біти — нулі й одиниці. Щоб зберегти ціле число, комп'ютер записує його у **двійковій системі** (за основою 2). Наприклад, 5 — це:

```text
5 = 1 x 2**2 + 0 x 2**1 + 1 x 2**0
  = 1 x 4    + 0 x 2    + 1 x 1
  = 0b101                         (3 біти)
```

Python уміє показувати й розбирати двійковий запис:

```python
print(bin(5))
print(int("101", 2))
print((5).bit_length())
print(bin(255), (255).bit_length())
```

Результат:

```text
0b101
5
3
0b11111111 8
```

`bit_length()` повертає, скільки бітів потрібно, щоб записати число (без урахування знака).

### Беззнакові цілі числа

За допомогою `n` бітів можна записати `2**n` різних комбінацій. Якщо всі вони відведені під невід'ємні числа, `n` бітів уміщують діапазон `0 .. 2**n - 1`. Для 8 бітів це `0 .. 255`: **256** різних значень, від `0b00000000` до `0b11111111`.

### Знакові цілі числа: доповняльний код

Щоб зберігати від'ємні числа, один біт відводять під знак. Наївна схема (біт знака + модуль) марнувала б одну комбінацію на «від'ємний нуль» і давала б діапазон `-127 .. 127`. Справжнє обладнання використовує **доповняльний код** (two's complement), у якому старший біт має *від'ємну* вагу. Для 8 бітів ваги такі: `-128, 64, 32, 16, 8, 4, 2, 1`:

```text
0b01111111 =  64+32+16+8+4+2+1        =  127   (найбільше)
0b00000000 =                              0    (нуль лише один)
0b11111111 = -128+64+32+16+8+4+2+1     =  -1
0b10000000 = -128                      = -128  (найменше)
```

Оскільки нуль лише один, зайва комбінація дістається від'ємній частині, і `n` бітів уміщують `-2**(n-1) .. 2**(n-1) - 1`:

```python
for bits in (8, 16, 32, 64):
    low = -(2 ** (bits - 1))
    high = 2 ** (bits - 1) - 1
    print(f"{bits:>2} bits: {low:,} .. {high:,}")
```

Результат:

```text
 8 bits: -128 .. 127
16 bits: -32,768 .. 32,767
32 bits: -2,147,483,648 .. 2,147,483,647
64 bits: -9,223,372,036,854,775,808 .. 9,223,372,036,854,775,807
```

Доповняльний код можна побачити напряму, якщо перетворити `int` на фіксовану кількість байтів. Значення поза діапазоном не вміщується:

```python
print((127).to_bytes(1, "big", signed=True))
print((-1).to_bytes(1, "big", signed=True))
print((-128).to_bytes(1, "big", signed=True))
print(int.from_bytes(b"\xff", "big", signed=True))
print(int.from_bytes(b"\xff", "big", signed=False))
print((128).to_bytes(1, "big", signed=True))
```

Результат:

```text
b'\x7f'
b'\xff'
b'\x80'
-1
255
Traceback (most recent call last):
  ...
OverflowError: int too big to convert
```

Той самий байт `0xff` означає `-1` як знакове значення і `255` як беззнакове.

## Як Python представляє цілі числа

Мови на кшталт C, Java і C# використовують цілі типи фіксованої ширини: 32-бітний `int`, 64-бітний `long` тощо. Арифметика, що виходить за межі діапазону, спричиняє **переповнення** (overflow): значення «загортається» або операція завершується помилкою.

`int` у Python інший: він використовує стільки бітів, скільки потрібно значенню. Переповнення немає. Єдине обмеження — доступна пам'ять:

```python
import sys

big = 2 ** 100
print(big)
print(big * big)
print(sys.maxsize)
print(sys.maxsize + 1)
```

Результат:

```text
1267650600228229401496703205376
1606938044258990275541962092341162602522202993782792835301376
9223372036854775807
9223372036854775808
```

> **Зверніть увагу:** `sys.maxsize` — **не** найбільше ціле число. Це найбільший розмір, який може мати контейнер (список, рядок) на цій платформі. Як бачите, `sys.maxsize + 1` працює без проблем.

Усередині CPython зберігає ціле число як невеликий заголовок плюс масив **цифр** за основою `2**30`, тож кожна цифра містить 30 бітів:

```python
import sys

print(sys.int_info)
```

Результат (64-бітна збірка):

```text
sys.int_info(bits_per_digit=30, sizeof_digit=4, default_max_str_digits=4300, str_digits_check_threshold=640)
```

Ця гнучкість має свою ціну:

- кожне ціле число — повноцінний об'єкт із заголовком, тож навіть `0` займає чимало байтів;
- арифметика над великими числами виконується цифра за цифрою, тому що більші числа, то повільніше працюють `+`, `*` і особливо `**` та `//`. Для чисел, що вміщуються в одне машинне слово, є швидкі шляхи.

## Як дізнатися розмір цілого числа

`sys.getsizeof()` повертає кількість байтів, які займає об'єкт:

```python
from sys import getsizeof

for number in (0, 1, 100, 2**30 - 1, 2**30, 2**60, 2**64, 2**100, -100):
    print(f"{number:>32}: {getsizeof(number)} bytes")
```

Результат (Python 3.14, 64-біт):

```text
                               0: 28 bytes
                               1: 28 bytes
                             100: 28 bytes
                      1073741823: 28 bytes
                      1073741824: 32 bytes
             1152921504606846976: 36 bytes
            18446744073709551616: 36 bytes
 1267650600228229401496703205376: 40 bytes
                            -100: 28 bytes
```

Закономірність така: **24 байти заголовка об'єкта + 4 байти на кожну 30-бітну цифру**.

- `0`, `1`, `100` і все до `2**30 - 1` вміщується в одну цифру: 28 байтів.
- `2**30` потребує 31 біт, тобто двох цифр: 32 байти.
- `2**60` і `2**64` потребують трьох цифр: 36 байтів.
- Знак зберігається в заголовку, тож `-100` має той самий розмір, що й `100`.

> **Зверніть увагу:** у старіших посібниках `getsizeof(0) == 24`. Так було до Python 3.11 включно, коли нуль зберігався взагалі без цифр. Починаючи з Python 3.12 кожне ціле число, зокрема `0`, має щонайменше одну цифру, тож мінімум — 28 байтів. Точні розміри — деталь реалізації CPython.

## Літерали цілих чисел і перетворення

Цілі числа можна записувати в різних системах числення і групувати цифри підкресленнями:

```python
population = 41_000_000
mask = 0b1010
permissions = 0o755
color = 0xFF8800

print(population, mask, permissions, color)
print(hex(color), oct(permissions), bin(mask))
```

Результат:

```text
41000000 10 493 16746496
0xff8800 0o755 0b1010
```

`int()` перетворює рядки й дробові числа:

```python
print(int("42"))
print(int("  -17  "))
print(int("ff", 16))
print(int("0b1010", 0))
print(int(3.99))
print(int(-3.99))
print(int("3.5"))
```

Результат:

```text
42
-17
255
10
3
-3
Traceback (most recent call last):
  ...
ValueError: invalid literal for int() with base 10: '3.5'
```

- Пробіли на початку й у кінці ігноруються.
- Другий аргумент — основа системи числення; з основою `0` префікс (`0b`, `0o`, `0x`) читається з самого рядка.
- `int(float)` **відкидає дробову частину в бік нуля**: `3.99` стає `3`, а `-3.99` — `-3`. Округлення не відбувається.
- Рядок із десятковою крапкою — некоректний літерал цілого числа. Пишіть `int(float("3.5"))` або `round(float("3.5"))`.

## Операції з цілими числами

Додавання, віднімання, множення й піднесення до степеня цілих чисел дають цілі числа:

```python
a = 10
b = 20

c = a + b
print(c)
print(type(c))

c = a - b
print(c)
print(type(c))

c = a * b
print(c)
print(type(c))

c = a ** b
print(c)
print(type(c))
```

Результат:

```text
30
<class 'int'>
-10
<class 'int'>
200
<class 'int'>
100000000000000000000
<class 'int'>
```

Звичайне ділення `/` **завжди** повертає `float`, навіть якщо результат цілий:

```python
a = 10
b = 5
c = a / b

print(c)
print(type(c))
```

Результат:

```text
2.0
<class 'float'>
```

Інші корисні операції:

```python
print(7 / 2)
print(7 // 2)
print(7 % 2)
print(divmod(7, 2))
print(2 ** -1)
print(pow(2, 10, 1000))
print(abs(-42))
```

Результат:

```text
3.5
3
1
(3, 1)
0.5
24
42
```

- `//` — ділення з округленням униз, `%` — остача (обом присвячено окремі теми).
- `divmod(a, b)` повертає обидва значення одразу.
- Від'ємний показник степеня дає `float`: `2 ** -1` дорівнює `0.5`.
- `pow(base, exp, mod)` ефективно обчислює `(base ** exp) % mod`, не будуючи величезного проміжного числа.

## Обмеження, які все ж існують

Цілі числа Python ніколи не переповнюються, але щойно вони стикаються з `float` чи `str`, з'являються обмеження.

**Перетворення на `float`.** `float` має ширину 64 біти, максимум близько `1.8e308` і лише 53 біти точності:

```python
print((2 ** 53 + 1) / 1)
print(2 ** 53 + 1)
print(int((2 ** 53 + 1) / 1) == 2 ** 53 + 1)
```

Результат:

```text
9007199254740992.0
9007199254740993
False
```

`/` перетворює значення на `float`, а `2**53 + 1` неможливо подати точно, тож одна одиниця губиться. Для цілих чисел, що взагалі не вміщуються у `float`, `/` завершується помилкою:

```python
print(10 ** 400 / 1)
```

Результат:

```text
Traceback (most recent call last):
  ...
OverflowError: integer division result too large for a float
```

Якщо потрібен точний цілий результат, використовуйте `//`: `10 ** 400 // 10 ** 398` дорівнює рівно `100`.

**Перетворення на `str`.** Спроба перетворити на рядок ціле число, що має понад 4300 десяткових цифр, за замовчуванням генерує `ValueError`. Це обмеження додали в Python 3.11 (і в безпекові випуски старіших версій), бо перетворення величезного числа на десятковий запис займає квадратичний час і могло використовуватися для атак на відмову в обслуговуванні:

```python
import sys

huge = 10 ** 5000
print(len(str(10 ** 4000)))

try:
    print(str(huge))
except ValueError as error:
    print("ValueError:", error)

sys.set_int_max_str_digits(6000)
print(len(str(huge)))
```

Результат:

```text
4001
ValueError: Exceeds the limit (4300 digits) for integer string conversion; use sys.set_int_max_str_digits() to increase the limit
5001
```

Обчислення з такими числами не обмежені. Обмежено лише перетворення в десятковий текст і назад.

## Типові помилки

- **Використовувати `/`, коли потрібне ціле число.** `10 / 5` дорівнює `2.0`, тобто `float`. Для цілочислового ділення пишіть `//`.
- **Очікувати, що `int()` округлює.** `int(2.7)` дорівнює `2`, а `int(-2.7)` — `-2`. Для округлення використовуйте `round()`.
- **Виконувати точні цілочислові обчислення через `float`.** `int(2**64 / 3)` дає `6148914691236516864`, тоді як точне `2**64 // 3` дорівнює `6148914691236517205`. Тримайте обчислення з великими числами в `int`.
- **Вважати `sys.maxsize` найбільшим цілим числом.** Цілі числа Python не мають максимуму.
- **Передавати `"3.5"` в `int()`.** Це генерує `ValueError`. Спершу перетворіть через `float()`.
- **Писати нулі на початку числа.** `code = 012` — це `SyntaxError` у Python 3 («leading zeros in decimal integer literals are not permitted»). Для вісімкового числа пишіть `0o12`, а для кодів — рядок `"012"`.

## Підсумок

- Python представляє всі цілі числа класом `int`. `bool` — підклас `int`.
- Комп'ютери зберігають цілі числа у двійковому вигляді. `n` бітів уміщують `2**n` значень: `0 .. 2**n - 1` без знака або `-2**(n-1) .. 2**(n-1) - 1` у доповняльному коді.
- `int` у Python має довільну точність: він зростає за потреби й ніколи не переповнюється. `sys.maxsize` не є обмеженням для цілих чисел.
- CPython зберігає ціле число як 24-байтний заголовок плюс 4 байти на кожну 30-бітну цифру. Починаючи з Python 3.12 навіть `0` займає 28 байтів.
- `+`, `-`, `*` і `**` (з невід'ємним показником) над цілими числами повертають цілі числа. `/` завжди повертає `float`.
- Обмеження з'являються лише на межах: під час перетворення на `float` (точність і діапазон) та на `str` (за замовчуванням 4300 цифр).

## Практика

### Вправа 1: Діапазони цілих чисел фіксованої ширини

Напишіть `int_range(bits, signed=True)`, яка повертає кортеж `(найменше, найбільше)` для цілого числа фіксованої ширини. Перевірте `int_range(8)`, `int_range(8, signed=False)`, `int_range(16)` і `int_range(32, signed=False)`.

### Вправа 2: Передбачте `getsizeof()`

Спираючись на правило «24 байти + 4 байти на кожну 30-бітну цифру, щонайменше одна цифра», напишіть `predicted_size(n)` і порівняйте її результат із `sys.getsizeof(n)` для `0`, `7`, `-7`, `2**30 - 1`, `2**30`, `10**20`, `-(2**90)` і `2**1000`. Підказка: `abs(n).bit_length()` показує, скільки бітів потрібно числу.

### Вправа 3: Справді велике число

Обчисліть `2 ** 1000`. Скільки воно має десяткових цифр, яка сума його цифр і скільки бітів йому потрібно?

### Вправа 4: Імітація 8-бітного переповнення

У C додавання `1` до знакового 8-бітного значення `127` дає `-128`. Напишіть `to_int8(n)`, яка перетворює будь-яке ціле число Python на значення, яке зберігав би знаковий 8-бітний цілий тип (залиште молодші 8 бітів і прочитайте їх у доповняльному коді). Перевірте `0, 127, 128, 255, 256, -128, -129, 1000` і звірте кожну відповідь через `to_bytes()` / `from_bytes()`.

## Розв'язки

### Вправа 1

```python
def int_range(bits, signed=True):
    if signed:
        return -(2 ** (bits - 1)), 2 ** (bits - 1) - 1
    return 0, 2 ** bits - 1


print(int_range(8))
print(int_range(8, signed=False))
print(int_range(16))
print(int_range(32, signed=False))
```

Результат:

```text
(-128, 127)
(0, 255)
(-32768, 32767)
(0, 4294967295)
```

### Вправа 2

```python
import sys


def predicted_size(n):
    digits = max(1, (abs(n).bit_length() + 29) // 30)   # округлюємо вгору до цілих цифр
    return 24 + 4 * digits


for n in (0, 7, -7, 2**30 - 1, 2**30, 10**20, -(2**90), 2**1000):
    actual = sys.getsizeof(n)
    print(f"{n.bit_length():>4} bits: predicted {predicted_size(n)}, actual {actual}")
```

Результат (Python 3.14, 64-біт):

```text
   0 bits: predicted 28, actual 28
   3 bits: predicted 28, actual 28
   3 bits: predicted 28, actual 28
  30 bits: predicted 28, actual 28
  31 bits: predicted 32, actual 32
  67 bits: predicted 36, actual 36
  91 bits: predicted 40, actual 40
1001 bits: predicted 160, actual 160
```

`(bits + 29) // 30` — це цілочислове ділення з округленням угору: 31 біт потребує 2 цифр, 1001 біт — 34 цифр (`24 + 34 * 4 = 160`). `max(1, ...)` обробляє `0`, який має нуль бітів, але все одно отримує одну цифру.

### Вправа 3

```python
number = 2 ** 1000
text = str(number)

print(len(text))
print(sum(int(digit) for digit in text))
print(number.bit_length())
```

Результат:

```text
302
1366
1001
```

Число має 302 десяткові цифри — значно менше за ліміт перетворення в 4300 цифр, тож `str()` працює. У двійковому вигляді `2 ** 1000` — це одиниця і 1000 нулів, тому йому потрібен 1001 біт.

### Вправа 4

```python
def to_int8(n):
    return (n + 128) % 256 - 128


def to_int8_bytes(n):
    return int.from_bytes((n % 256).to_bytes(1, "big"), "big", signed=True)


for n in (0, 127, 128, 255, 256, -128, -129, 1000):
    print(n, to_int8(n), to_int8(n) == to_int8_bytes(n))
```

Результат:

```text
0 0 True
127 127 True
128 -128 True
255 -1 True
256 0 True
-128 -128 True
-129 127 True
1000 -24 True
```

`n % 256` залишає молодші 8 бітів як беззнакове значення `0..255` (у Python `%` з додатним дільником завжди дає невід'ємний результат). Зсув на 128 до й після переводить цей діапазон у `-128..127`. Версія з байтами приходить до того самого результату, бо читає байт як знаковий.
