# Динамічна типізація

У Python тип належить **об'єкту**, а не змінній. Ім'я може зараз посилатися на рядок, а за мить — на число, і Python перевіряє, чи має операція сенс, лише тоді, коли ця операція справді виконується. Це називається **динамічною типізацією** (dynamic typing). Вона пояснює і те, чому код на Python короткий та гнучкий, і те, чому деякі помилки виявляються лише під час виконання.

## Що ви дізнаєтесь

- Чим статична типізація відрізняється від динамічної: де «живе» тип
- Як працює перев'язування імені на об'єкт іншого типу
- Як дізнатися тип за допомогою `type()` та `isinstance()`
- Чому Python має динамічну *і водночас* сильну типізацію
- Що таке качина типізація (duck typing) і чому вона випливає з динамічної
- Що анотації типів роблять (і чого не роблять) під час виконання

## Статична типізація: тип належить змінній

У мовах зі статичною типізацією, як-от Java, C# чи C++, змінну оголошують разом із її типом:

```java
String message = "Hello";
message = 100;   // помилка компіляції: incompatible types: int cannot be converted to String
```

Тут тип `String` має саме **змінна** `message`. Компілятор це запам'ятовує і відхиляє будь-яку спробу записати в неї щось інше ще до запуску програми.

## Динамічна типізація: тип належить об'єкту

У Python тип змінної ніколи не оголошують:

```python
message = "Hello"
print(type(message))

message = 100
print(type(message))
```

Результат:

```text
<class 'str'>
<class 'int'>
```

`message` — це просто ім'я. Перше присвоєння прив'язує його до об'єкта `str`, а друге перев'язує на зовсім новий об'єкт `int`. `type(message)` повідомляє не тип *змінної* (у неї типу немає), а тип об'єкта, на який ім'я посилається **саме зараз**.

```text
після message = "Hello":          після message = 100:

message ---> +-------------+      message ---> +-------------+
             | str "Hello" |                   | int 100     |
             +-------------+                   +-------------+

                                               +-------------+
                                               | str "Hello" |  посилань немає:
                                               +-------------+  знищено
```

Жодного перетворення не відбувається. Рядковий об'єкт не стає числом. Він просто втрачає посилання і, якщо на нього не посилається жодне інше ім'я, знищується. Якщо ж інше ім'я досі посилається на рядок, той лишається живим і незмінним:

```python
message = "Hello"
greeting = message
message = 100

print(message, type(message))
print(greeting, type(greeting))
print(message is greeting)
```

Результат:

```text
100 <class 'int'>
Hello <class 'str'>
False
```

## Як дізнатися тип: `type()` та `isinstance()`

`type(obj)` повертає точний клас об'єкта. `isinstance(obj, cls)` ставить корисніше запитання: «чи є цей об'єкт екземпляром `cls` **або його підкласу**?»

```python
value = True

print(type(value))
print(type(value) is int)
print(isinstance(value, int))
print(isinstance(3.5, (int, float)))
print(isinstance(3.5, int | float))
```

Результат:

```text
<class 'bool'>
False
True
True
True
```

- `bool` — підклас `int`, тому з погляду `isinstance()` значення `True` є `int`, але його точний тип — `bool`.
- `isinstance()` приймає кортеж класів, а починаючи з Python 3.10 — також об'єднання, записане через `|`.

> **Порада:** якщо потрібно розгалужувати логіку за типом, віддавайте перевагу `isinstance()`. Ця функція враховує успадкування, тож підкласи обробляються правильно. Записуйте `type(x) is SomeClass` лише тоді, коли вам справді потрібен точний клас.

## Динамічна не означає слабка

Часто плутають два окремі питання:

- **Статична чи динамічна:** *коли* перевіряються типи — під час компіляції чи під час виконання програми?
- **Сильна чи слабка:** чи перетворює мова мовчки значення між несумісними типами?

Python має **динамічну й сильну** типізацію. Він не перевіряє типи заздалегідь, але й не намагається вгадати, що ви мали на увазі, коли типи не підходять:

```python
print("1" + 1)
```

Результат:

```text
Traceback (most recent call last):
  ...
TypeError: can only concatenate str (not "int") to str
```

JavaScript, що має динамічну, але *слабку* типізацію, обчислює той самий вираз як рядок `"11"`. У Python ви перетворюєте значення явно й самі вирішуєте, яким має бути результат:

```python
print(int("1") + 1)
print("1" + str(1))
print(1 + 2.5)
print(True + 1)
print("3" * 2)
```

Результат:

```text
2
11
3.5
2
33
```

Останні три рядки — не слабка типізація, а операції, які типи визначають явно: числа різних видів можна поєднувати (`int` + `float` дає `float`), `bool` є підкласом `int`, а `str * int` означає повторення рядка.

## Помилки типів виникають під час виконання

Оскільки заздалегідь нічого не перевіряється, функція з помилкою типів цілком коректна доти, доки проблемний рядок не виконається з невідповідними даними:

```python
def total_length(items):
    return sum(len(item) for item in items)


print(total_length(["ab", "cde"]))
print(total_length(["ab", 5]))
```

Результат:

```text
5
Traceback (most recent call last):
  ...
    return sum(len(item) for item in items)
               ~~~^^^^^^
TypeError: object of type 'int' has no len()
```

Перший виклик працює й виводить `5`. Другий падає лише тоді, коли доходить до `len(5)`. У великій програмі така помилка може місяцями ховатися в гілці, яка рідко виконується. Саме тому проєкти на Python спираються на тести, а дедалі частіше — ще й на анотації типів зі статичним аналізатором.

## Качина типізація

«Якщо щось ходить як качка і крякає як качка, то це качка». Код на Python зазвичай не питає, *якого типу* об'єкт. Він просто використовує потрібні операції, і підходить будь-який об'єкт, що їх підтримує:

```python
def describe_size(thing):
    return f"{type(thing).__name__} of length {len(thing)}"


class Playlist:
    def __init__(self, songs):
        self.songs = songs

    def __len__(self):
        return len(self.songs)


print(describe_size("hello"))
print(describe_size([1, 2, 3]))
print(describe_size({"a": 1}))
print(describe_size(Playlist(["Intro", "Outro"])))
```

Результат:

```text
str of length 5
list of length 3
dict of length 1
Playlist of length 2
```

`describe_size()` ніколи не перевіряє тип аргументу. Їй потрібно лише, щоб працювала `len()`, тож вона приймає рядки, списки, словники і навіть наш власний клас `Playlist`, який визначає `__len__`. Така гнучкість — головна перевага динамічної типізації.

## Анотації типів: необов'язкові й не примусові

Функції (починаючи з Python 3.5) і змінні (починаючи з Python 3.6) можна позначати **анотаціями типів** (type hints):

```python
def greet(name: str) -> str:
    return "Hello, " + name


print(greet("Olena"))
print(greet.__annotations__)

age: int = 30
age = "thirty"   # під час виконання помилки немає
print(age)
```

Результат:

```text
Hello, Olena
{'name': <class 'str'>, 'return': <class 'str'>}
thirty
```

Інтерпретатор зберігає анотації, але **не перевіряє їх**: присвоєння рядка змінній `age` минає без жодних заперечень. Анотації використовують редактори коду та статичні аналізатори типів, як-от mypy чи Pyright, що читають код, не запускаючи його. Збережіть приклад вище як `hints.py` і перевірте його (mypy — це сторонній інструмент: `pip install mypy`):

```bash
mypy hints.py
```

Результат:

```text
hints.py:9: error: Incompatible types in assignment (expression has type "str", variable has type "int")  [assignment]
Found 1 error in 1 file (checked 1 source file)
```

Анотації типів дають багато переваг статичної типізації (раннє виявлення помилок, краще автодоповнення, код, що сам себе документує), а Python при цьому лишається динамічним.

## Переваги й недоліки

| Що дає динамічна типізація | Чим за неї доводиться платити |
|---|---|
| Короткий код без оголошень типів | Помилки типів виявляються лише під час виконання |
| Качина типізація: одна функція працює з багатьма типами | Під час читання коду тип імені може бути неочевидним |
| Швидке прототипування та інтерактивні експерименти | Для надійності потрібні тести (і, за бажанням, анотації типів) |

## Типові помилки

- **Забувати, що `input()` повертає рядок.** `age = input("Age: ")`, а потім `age + 1` генерує `TypeError: can only concatenate str (not "int") to str`. Спершу перетворіть значення: `int(input("Age: "))`.
- **Використовувати одне ім'я для різних даних.** `data = "1,2,3"`, потім `data = data.split(",")`, потім `data = [int(x) for x in data]` — це коректно, але читачеві доведеться стежити, якого типу `data` у кожному рядку. Краще взяти різні імена: `raw`, `parts`, `numbers`.
- **Затінювати вбудовані імена.** Перев'язати можна будь-яке ім'я, зокрема вбудоване:

  ```python
  list = [1, 2, 3]
  letters = list("abc")
  ```

  Результат:

  ```text
  Traceback (most recent call last):
    ...
  TypeError: 'list' object is not callable
  ```

  Уникайте імен на кшталт `list`, `dict`, `str`, `id`, `type`, `input`, `sum`.
- **Перевіряти тип через `type(x) == int`.** Така перевірка відкидає підкласи, і це рідко те, що потрібно. Використовуйте `isinstance(x, int)` і пам'ятайте, що `isinstance(True, int)` дорівнює `True`.
- **Вважати, що анотації типів перевіряються під час виконання.** Це не так. Щоб отримати від них користь, запускайте аналізатор типів, наприклад mypy.

## Підсумок

- У Python змінні не мають типу. Тип мають об'єкти, а ім'я можна перев'язати на об'єкт будь-якого типу.
- `type(obj)` повертає точний клас об'єкта, на який посилається ім'я; `isinstance(obj, cls)` враховує ще й підкласи.
- Перев'язування ніколи не перетворює об'єкт. Воно спрямовує ім'я на інший об'єкт.
- Python має динамічну типізацію (типи перевіряються під час виконання) і сильну типізацію (жодних мовчазних перетворень між несумісними типами).
- Качина типізація означає, що ви покладаєтеся на те, що об'єкт уміє робити, а не на його оголошений тип.
- Анотації типів документують наміри й допомагають статичним аналізаторам, але інтерпретатор їх не перевіряє.

### Вправа 1: Простежте за типом

Перш ніж запускати код, передбачте кожен виведений рядок.

```python
x = 42
print(type(x).__name__)

x = x / 2
print(type(x).__name__, x)

x = str(x)
print(type(x).__name__, x)

x = x.split(".")
print(type(x).__name__, x)

x = len(x) > 1
print(type(x).__name__, x)
```

### Вправа 2: Виправте суму замовлення

Код нижче падає. Поясніть помилку, виправте код так, щоб він виводив `7.5`, і передбачте, що виведе `quantity * 2` та чому це небезпечно.

```python
quantity = "3"      # значення прийшло з вебформи, тож це рядок
price = 2.5

total = quantity * price
print(total)
```

### Вправа 3: Опишіть значення

Напишіть `describe(value)`, яка повертає `"boolean"`, `"integer"`, `"float"`, `"string"`, `"sequence"` (для списків і кортежів) або `"other"`. Перевірте її на `True`, `7`, `2.5`, `"hi"`, `[1]`, `(1, 2)` та `None`. Переконайтеся, що `describe(True)` повертає `"boolean"`, а не `"integer"`.

### Вправа 4: Загальний розмір у стилі качиної типізації

Напишіть `total_size(items)`, яка підсумовує `len(item)` для кожного елемента, що підтримує `len()`, і рахує елементи, які її не підтримують. Поверніть кортеж `(total, skipped)`. Не перевіряйте типи через `isinstance()`: просто спробуйте викликати `len()` і обробіть невдачу. Для `["abc", [1, 2], 10, {"k": "v"}, None]` результат має бути `(6, 2)`.

## Розв'язки

### Вправа 1

Результат:

```text
int
float 21.0
str 21.0
list ['21', '0']
bool True
```

Ім'я `x` перев'язується п'ять разів. `/` завжди повертає `float`, `str()` створює новий рядок, `split()` повертає список, а порівняння — `bool`.

### Вправа 2

Початковий код падає з помилкою:

```text
TypeError: can't multiply sequence by non-int of type 'float'
```

`quantity` — це рядок, і Python не перетворить його на число мовчки. Виправлена версія:

```python
quantity = "3"
price = 2.5

print(quantity * 2)          # str * int повторює рядок

total = int(quantity) * price
print(total)
```

Результат:

```text
33
7.5
```

`"3" * 2` не генерує помилку: рядок повторюється, і виходить `"33"`. Це небезпечно, бо пропущене перетворення дає хибний результат замість аварійного завершення.

### Вправа 3

```python
def describe(value):
    if isinstance(value, bool):          # має йти перед int
        return "boolean"
    if isinstance(value, int):
        return "integer"
    if isinstance(value, float):
        return "float"
    if isinstance(value, str):
        return "string"
    if isinstance(value, (list, tuple)):
        return "sequence"
    return "other"


for item in [True, 7, 2.5, "hi", [1], (1, 2), None]:
    print(repr(item), "->", describe(item))
```

Результат:

```text
True -> boolean
7 -> integer
2.5 -> float
'hi' -> string
[1] -> sequence
(1, 2) -> sequence
None -> other
```

`bool` — підклас `int`, тож `isinstance(True, int)` дорівнює `True`. Перевірка на `bool` має стояти першою.

### Вправа 4

```python
def total_size(items):
    total = 0
    skipped = 0
    for item in items:
        try:
            total += len(item)
        except TypeError:
            skipped += 1
    return total, skipped


print(total_size(["abc", [1, 2], 10, {"k": "v"}, None]))
print(total_size([]))
```

Результат:

```text
(6, 2)
(0, 0)
```

Такий стиль називають EAFP («easier to ask forgiveness than permission» — «легше попросити пробачення, ніж дозволу»): спробуйте виконати операцію й обробіть виняток. Він працює з будь-яким об'єктом, що визначає `__len__`, зокрема з класами, яких іще не існує.
