# Оператор is

У Python є два різні способи запитати, чи дві речі «однакові». Оператор `==` перевіряє, чи мають два об'єкти **рівні значення**. Оператор `is` перевіряє, чи посилаються два імені на **один і той самий об'єкт**. Якщо їх переплутати, код працюватиме на швидкому тесті, а потім зламається в робочому середовищі.

## Що ви дізнаєтесь

- Що таке ідентичність об'єкта і як її перевіряє `is`
- Чим `is` (ідентичність) відрізняється від `==` (рівності)
- Чому `a = 100; b = 100; a is b` може дати `True` і чому на це не можна покладатися
- Як працює `is not` і чим він відрізняється від `is (not ...)`
- Коли `is` — правильний інструмент: `None`, об'єкти-маркери, точні типи
- Граничні випадки: власний `__eq__`, `NaN` і попередження `SyntaxWarning` для літералів

## Ідентичність: оператор `is`

Кожен об'єкт має ідентичність, яку повертає `id()`. `a is b` дорівнює `True` саме тоді, коли `a` і `b` посилаються на той самий об'єкт. Поки обидва об'єкти живі, це те саме, що `id(a) == id(b)`.

```python
a = 100
b = a
print(a is b)
```

Результат:

```text
True
```

`b = a` нічого не копіює. Це присвоєння прив'язує друге ім'я до об'єкта, на який посилається `a`, тож обидва імені вказують на один об'єкт `int`.

Два об'єкти, створені окремо, — різні об'єкти, навіть якщо їхній вміст однаковий:

```python
ranks = [1, 2, 3]
rates = [1, 2, 3]

print(ranks == rates)
print(ranks is rates)
```

Результат:

```text
True
False
```

```text
ranks ---> list [1, 2, 3]     (об'єкт №1)
rates ---> list [1, 2, 3]     (об'єкт №2: рівне значення, інша ідентичність)
```

Кожен вираз `[...]` створює новий список. Списки змінювані, тож Python ніколи не повинен непомітно робити їх спільними: якби `rates` і `ranks` були одним об'єктом, додавання елемента в один змінило б інший.

## `is` проти `==`

| | `a is b` | `a == b` |
|---|---|---|
| Запитання | Це той самий об'єкт? | Чи рівні їхні значення? |
| Хто реалізує | Інтерпретатор (порівнює ідентичності) | Метод `__eq__()` об'єкта |
| Чи може клас це змінити? | Ні | Так |
| Швидкість | Завжди одна перевірка за сталий час | Може бути повільним (наприклад, порівняння двох довгих списків) |

Якщо `a is b` дорівнює `True`, то зазвичай і `a == b` дорівнює `True`. Навпаки — ні: рівні об'єкти часто є різними об'єктами.

Оскільки `==` викликає `__eq__()`, клас може змусити його повертати будь-що. Перевизначити `is` неможливо:

```python
class AlwaysEqual:
    def __eq__(self, other):
        return True


thing = AlwaysEqual()
print(thing == 42)
print(thing == None)
print(thing is None)
```

Результат:

```text
True
True
False
```

Це головна причина порівнювати з `None` саме через `is` (докладніше — у наступній темі).

## Малі цілі числа та інші кешовані об'єкти

Ось несподіваний результат з оригінального уроку:

```python
a = 100
b = 100
print(a is b)

x = int("256")
y = int("256")
print(x is y)

x = int("257")
y = int("257")
print(x is y)
print(x == y)
```

Результат:

```text
True
True
False
True
```

Ваш код ніяк не пов'язує два об'єкти `100`. Вони виявляються одним об'єктом, тому що CPython тримає кеш малих цілих чисел від `-5` до `256`. Щоразу, коли потрібне мале ціле число, використовується об'єкт із кешу. `257` у кеш не входить, тож два цілі числа, обчислені під час виконання, — окремі об'єкти.

Далі ще менш передбачувано. У скрипті обидва рядки компілюються разом, і компілятор зберігає константу `1000` лише один раз:

```python
a = 1000
b = 1000
print(a is b)
```

Результат (під час запуску як скрипта):

```text
True
```

В інтерактивному інтерпретаторі кожен рядок компілюється окремо:

```python
>>> a = 1000
>>> b = 1000
>>> a is b
False
```

Рядки поводяться схожим чином: короткі літерали, схожі на ідентифікатори, часто **інтернуються** (стають спільними), а рядки, побудовані під час виконання, зазвичай ні:

```python
first = "hello"
second = "".join(["hel", "lo"])

print(first == second)
print(first is second)
```

Результат:

```text
True
False
```

> **Зверніть увагу:** кешування цілих чисел, спільні константи та інтернування рядків — це оптимізації CPython. Вони відрізняються між версіями, між REPL і скриптами та між реалізаціями Python. Ніколи не порівнюйте числа чи рядки через `is`. Використовуйте `==`.

Починаючи з Python 3.8, компілятор попереджає, якщо ви використовуєте `is` з літералом:

```python
count = 5
print(count is 5)
```

Результат:

```text
.../example.py:2: SyntaxWarning: "is" with 'int' literal. Did you mean "=="?
  print(count is 5)
True
```

Тут результат `True` лише завдяки кешу малих чисел. Попередження виводиться під час компіляції коду (у стандартний потік помилок), ще до запуску програми.

## Оператор `is not`

`is not` — це один оператор, заперечення `is`. Він повертає `True`, коли імена посилаються на різні об'єкти:

```python
ranks = [1, 2, 3]
rates = [1, 2, 3]

print(ranks is not rates)
print(not ranks is rates)
print(ranks is (not rates))
```

Результат:

```text
True
True
False
```

- `ranks is not rates` — ідіоматична форма.
- `not ranks is rates` дає той самий результат, бо `is` має вищий пріоритет, ніж `not`, але читається гірше. PEP 8 радить писати `is not`.
- `ranks is (not rates)` — зовсім інше: `not rates` обчислюється як `False` (список не порожній), а `ranks is False` дорівнює `False`.

## Ідентичність і рівність для `NaN`

Значення з рухомою комою «не число» (NaN) не дорівнює навіть самому собі. Проте контейнери під час порівняння елементів перевіряють ідентичність **перед** рівністю:

```python
nan = float("nan")

print(nan == nan)
print(nan is nan)
print([nan] == [nan])
print(nan in [nan])
```

Результат:

```text
False
True
True
True
```

`list.__eq__` та `in` вважають елемент збігом, якщо він `is` шуканий об'єкт, навіть коли `==` сказав би інакше. Ця перевірка ідентичності — свідома оптимізація, яку використовують усі вбудовані контейнери.

## Коли використовувати `is`

Використовуйте `is` та `is not` лише тоді, коли питання справді в ідентичності:

- **Порівняння з `None`:** `if result is None:`. `None` — синглтон, і `is` неможливо обдурити власним `__eq__`.
- **Об'єкти-маркери (sentinel):** унікальна позначка на кшталт `_MISSING = object()`, що означає «значення не передали». Лише `is` може відрізнити її від будь-якого іншого значення, зокрема від `None`.
- **Перевірка точного типу:** `type(x) is int` (коли ви свідомо хочете виключити підкласи; інакше використовуйте `isinstance`).
- **Виявлення псевдонімів:** `if source is target:`, щоб перевірити, що два імені не посилаються на спільний змінюваний об'єкт, перш ніж змінювати один із них.
- **Інші синглтони:** `...` (`Ellipsis`) і `NotImplemented`.

Для `True` і `False` пишіть `if flag:` замість `if flag is True:`. Обидва булеві значення — синглтони, тож `is` спрацює, але звичайна перевірка істинності ідіоматичніша.

## Типові помилки

- **Порівнювати числа чи рядки через `is`.** Це може працювати для малих значень і коротких рядків, а потім зламатися на інших. Для значень завжди використовуйте `==`.
- **Перевіряти на `None` через `==`.** Власний `__eq__` може повернути `True` для `obj == None`. Пишіть `obj is None`.
- **Писати `a is (not b)` або `not a is b`.** Використовуйте єдиний оператор `a is not b`.
- **Очікувати, що `is` порівнює вміст.** `[1, 2] is [1, 2]` дорівнює `False`: це два окремі списки.
- **Ігнорувати `SyntaxWarning: "is" with ... literal`.** Майже завжди це попередження вказує на справжню помилку.

## Підсумок

- `a is b` перевіряє ідентичність: чи посилаються обидва імені на один об'єкт? Перевизначити цю поведінку неможливо.
- `a == b` перевіряє рівність, викликаючи `__eq__()`. Рівні об'єкти часто є різними об'єктами.
- `is not` — заперечення `is`. Віддавайте йому перевагу перед `not a is b`.
- Малі цілі числа (від `-5` до `256`), спільні константи й інтерновані рядки можуть змусити `is` повернути `True` для рівних значень. Це деталь реалізації: ніколи на неї не покладайтеся.
- Використовуйте `is` для `None`, маркерів, перевірки точного типу та виявлення псевдонімів. Для всього іншого — `==`.

### Вправа 2: Маркер як значення за замовчуванням

Напишіть `get_setting(settings, key, default=...)`, що працює як `dict.get()` з однією відмінністю: якщо ключа немає **і значення за замовчуванням не передали**, функція генерує `KeyError`. Явно переданий `default=None` усе одно має повертати `None`. Підказка: створіть унікальний маркер через `object()` і порівнюйте з ним за допомогою `is`.

### Вправа 3: Порахуйте різні об'єкти

Напишіть `count_distinct(items)`, яка повертає, скільки **різних об'єктів** (а не різних значень) містить список. Перевірте її на `row = [0, 0]` і `grid = [row, row, [0, 0]]`: відповідь має бути `2`, хоча всі три рядки рівні. Потім змініть `grid[0][0]` і виведіть `grid`, щоб побачити наслідки.

## Розв'язки

### Вправа 1

Результат:

```text
True True
False True
False True
True
True
```

- `b` — ще одне ім'я для того самого списку.
- `c` — окремий список із рівним вмістом.
- `a[:]` створює поверхневу копію: новий список із рівним вмістом.
- `a is not c` дорівнює `True`, бо це різні об'єкти.
- `type(a)` повертає сам клас `list`, а клас `list` існує лише один.

### Вправа 2

```python
_MISSING = object()   # унікальний об'єкт, який жоден виклик не передасть випадково


def get_setting(settings, key, default=_MISSING):
    if key in settings:
        return settings[key]
    if default is _MISSING:
        raise KeyError(key)
    return default


config = {"debug": False, "timeout": None}
print(get_setting(config, "debug"))
print(get_setting(config, "timeout"))
print(get_setting(config, "retries", None))

try:
    get_setting(config, "retries")
except KeyError as error:
    print("KeyError:", error)
```

Результат:

```text
False
None
None
KeyError: 'retries'
```

`None` тут не годиться як позначка «нічого не передали», бо `None` — цілком допустиме значення за замовчуванням. `object()` створює новий об'єкт, рівний лише самому собі, а `is` перевіряє саме цей об'єкт.

### Вправа 3

```python
def count_distinct(items):
    seen_ids = set()
    for item in items:
        seen_ids.add(id(item))   # безпечно: кожен елемент живий, поки він у списку
    return len(seen_ids)


row = [0, 0]
grid = [row, row, [0, 0]]

print(count_distinct(grid))
print(grid[0] == grid[2])
grid[0][0] = 5
print(grid)
```

Результат:

```text
2
True
[[5, 0], [5, 0], [0, 0]]
```

Перші два рядки — той самий об'єкт, тож зміна `grid[0]` змінює й `grid[1]`. Порівнювати значення `id()` тут безпечно, бо список тримає всі елементи живими протягом усього виклику.

### Вправа 4

Початковий код виводить попередження і дві різні відповіді для рівних рядків:

```text

```

Літерал `"admin"` і рядок, побудований через `join()`, рівні, але є різними об'єктами, тому `is` повертає `False`. Порівнюйте значення через `==`:

```python
def is_admin(role):
    return role == "admin"


print(is_admin("admin"))
print(is_admin("".join(["ad", "min"])))
```

Результат:

```text
True
True
```
