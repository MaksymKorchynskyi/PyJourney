# Області видимості змінних

Ім'я змінної видно не в усій програмі. Кожне ім'я належить певній **області видимості** (scope), і Python за чіткими правилами визначає, на який об'єкт посилається ім'я в конкретному місці коду. Ці правила пояснюють `NameError`, сумнозвісну `UnboundLocalError` і те, чому функція не може просто так перепризначити глобальну змінну.

## Що ви дізнаєтесь

- Що таке область видимості й простір імен і як вони пов'язані
- Які бувають області видимості: вбудована, глобальна (модульна) та локальна, і як вони вкладені одна в одну
- Як Python шукає ім'я: правило LEGB
- Чому присвоєння всередині функції робить ім'я локальним і що означає `UnboundLocalError`
- Як і коли використовувати ключове слово `global`
- Які блоки коду створюють нову область видимості, а які ні

## Області видимості та простори імен

Присвоєння на кшталт `counter = 10` **прив'язує** ім'я `counter` до об'єкта `int`. Ця прив'язка існує не всюди, а лише в певній частині коду. Ділянку вихідного коду, де ім'я видно, називають **областю видимості** цього імені. Python визначає області видимості за *структурою вихідного коду* (де саме імені присвоюють значення), а не за порядком викликів функцій. Тому області видимості в Python називають **лексичними** (або статичними).

Прив'язки Python зберігає у **просторах імен** (namespaces). Простір імен — це, по суті, відображення імен на об'єкти, і багато просторів імен справді є звичайними словниками, які можна переглянути:

```text
 простір імен модуля app.py
+-----------+------------------------+
| ім'я      | посилається на         |
+-----------+------------------------+
| counter   | об'єкт int 10          |
| increment | об'єкт функції         |
+-----------+------------------------+
```

Кожна область видимості має власний простір імен, тож одне й те саме ім'я може водночас існувати в кількох просторах і посилатися на різні об'єкти. Python потребує правил, щоб вирішити, яке з них «перемагає», і решта теми саме про ці правила.

## Вбудована область видимості

**Вбудована область видимості** (built-in scope) містить імена, доступні в кожному модулі без імпорту: `print`, `len`, `range`, `int`, `None`, `True`, `False`, класи винятків на зразок `ValueError` і багато інших. Усі вони живуть у модулі `builtins`:

```python
import builtins

print(builtins.print is print)
print(builtins.len("scope"))
print("ValueError" in dir(builtins))
```

Результат:

```text
True
5
True
```

Імпортувати `builtins`, щоб користуватися цими іменами, не потрібно. Python автоматично звертається до цього модуля на останньому кроці кожного пошуку.

## Глобальна (модульна) область видимості

**Глобальна область видимості** — це область видимості модуля, тобто одного файлу `.py`. Імена, яким присвоєно значення на верхньому рівні файлу (поза будь-якими функціями й класами), зокрема імена, створені інструкціями `def`, `class` та `import`, є глобальними для цього модуля.

«Глобальна» в Python **не** означає «спільна для всієї програми». Кожен модуль має власний глобальний простір імен. Єдина область видимості, яку справді видно з будь-якого модуля, — вбудована.

Коли код на рівні модуля використовує ім'я, Python спершу шукає його в глобальному просторі імен модуля, а потім у вбудованому. У файлі `app.py`:

```python
print("Hello")
```

Результат:

```text
Hello
```

`print` не визначено в `app.py`, тож Python не знаходить це ім'я в глобальному просторі імен і переходить до вбудованої області, де пошук завершується успішно. Якщо імені немає ні там, ні там, Python генерує `NameError`:

```python
print(counter)
```

Результат:

```text
Traceback (most recent call last):
  File "app.py", line 1, in <module>
    print(counter)
          ^^^^^^^
NameError: name 'counter' is not defined
```

Глобальний простір імен модуля можна переглянути за допомогою `globals()`. Ця функція повертає справжній словник, яким користується Python:

```python
counter = 10


def increment(value):
    return value + 1


print("counter" in globals())
print(globals()["counter"])
print(type(globals()["increment"]).__name__)
```

Результат:

```text
True
10
function
```

## Локальна область видимості

Параметри функції та імена, яким присвоюють значення в її тілі, належать до **локальної області видимості** функції:

```python
def increment(counter, by=1):
    result = counter + by
    return result
```

Виконання файлу Python відбувається у дві фази:

1. **Компіляція.** Python перетворює вихідний код на байт-код. Для кожної функції він раз і назавжди вирішує, які імена локальні: це всі параметри й усі імена, яким *присвоюється* значення будь-де в тілі функції (`=`, `+=`, змінні циклу `for`, `import`, `def`, `with ... as` тощо). У нашому прикладі це `counter`, `by` і `result`.
2. **Виконання.** Інструкції виконуються згори донизу. Інструкція `def` створює об'єкт функції та прив'язує ім'я `increment` у глобальному просторі імен. Локальних змінних поки що не існує.

Рішення компілятора зберігається в об'єкті коду функції, тож його можна побачити ще до першого виклику:

```python
def increment(counter, by=1):
    result = counter + by
    return result


print(increment.__code__.co_varnames)
```

Результат:

```text
('counter', 'by', 'result')
```

**Кожен виклик створює новий локальний простір імен.** Під час `increment(10, 2)` локальні імена прив'язані до `10`, `2` і `12`. Коли виклик завершується, цей простір імен зникає. Наступний виклик `increment(100, 3)` починається з абсолютно нового простору, де імена прив'язані до `100`, `3` і `103`. Різні виклики ніколи не мають спільних локальних змінних, і саме завдяки цьому працює рекурсія.

```python
def increment(counter, by=1):
    result = counter + by
    print(locals())
    return result


increment(10, 2)
increment(100, 3)

try:
    print(result)
except NameError as error:
    print("NameError:", error)
```

Результат:

```text
{'counter': 10, 'by': 2, 'result': 12}
{'counter': 100, 'by': 3, 'result': 103}
NameError: name 'result' is not defined
```

`locals()` показує поточний локальний простір імен. Поза функцією імені `result` взагалі не існує.

> **Зверніть увагу:** починаючи з Python 3.13, `locals()` усередині функції щоразу повертає незалежний знімок. Зміни в цьому словнику ніколи не впливають на справжні локальні змінні. Використовуйте його лише для читання, як інструмент налагодження.

## Пошук імен: правило LEGB

Області видимості вкладені одна в одну. Локальна область функції розташована всередині глобальної області модуля, а глобальна — всередині вбудованої. Функція, оголошена всередині іншої функції, додає ще один рівень — **охопну** (enclosing) область видимості, тобто область зовнішньої функції (докладно про неї йдеться в темі про `nonlocal`).

```text
+-----------------------------------------------------+
| B  Built-in   print, len, range, None, ...          |
|   +---------------------------------------------+   |
|   | G  Global   імена верхнього рівня app.py    |   |
|   |   +-------------------------------------+   |   |
|   |   | E  Enclosing   зовнішня функція     |   |   |
|   |   |   +-----------------------------+   |   |   |
|   |   |   | L  Local   вкладена функція |   |   |   |
|   |   |   +-----------------------------+   |   |   |
|   |   +-------------------------------------+   |   |
|   +---------------------------------------------+   |
+-----------------------------------------------------+
```

Коли ви **читаєте** ім'я, Python шукає його зсередини назовні й зупиняється на першому збігу:

1. **L**ocal (локальна): поточна функція.
2. **E**nclosing (охопна): локальні області зовнішніх функцій, починаючи з найближчої.
3. **G**lobal (глобальна): модуль.
4. **B**uilt-in (вбудована): модуль `builtins`.

Якщо імені немає в жодній області, виникає `NameError`.

```python
counter = 10


def current():
    print(counter)


current()
```

Результат:

```text
10
```

`counter` не є локальною змінною `current()`, тож Python знаходить її в глобальній області.

Перемагає перший збіг, тому ім'я у внутрішній області **затіняє** (shadows) таке саме ім'я в зовнішніх областях. Це стосується й вбудованих імен: оголосіть глобальну змінну `len`, і вбудована функція `len` стане недоступною в цьому модулі.

## Присвоєння робить ім'я локальним

Щоб прочитати глобальну змінну у функції, жодного спеціального синтаксису не треба. З **присвоєнням** інакше:

```python
counter = 10


def reset():
    counter = 0
    print(counter)


reset()
print(counter)
```

Результат:

```text
0
10
```

Оскільки `reset()` присвоює значення `counter`, компілятор позначає `counter` як локальну змінну `reset()`. Присвоєння створює нову локальну змінну, яка затіняє глобальну, а глобальна `counter` так і лишається `10`.

### `UnboundLocalError`

Правило «присвоєно будь-де — отже, локальна в усій функції» спричиняє одну з найпоширеніших помилок у Python:

```python
counter = 10


def increment():
    counter = counter + 1
    return counter


increment()
```

Результат:

```text
Traceback (most recent call last):
  File "app.py", line 9, in <module>
    increment()
    ~~~~~~~~~^^
  File "app.py", line 5, in increment
    counter = counter + 1
              ^^^^^^^
UnboundLocalError: cannot access local variable 'counter' where it is not associated with a value
```

Python **не** читає глобальну `counter` у правій частині виразу. Компілятор уже вирішив, що `counter` локальна в усьому тілі `increment()`, а на цей момент локальна змінна ще не має значення. `counter += 1` завершується такою самою помилкою. Місце присвоєння не має значення: навіть присвоєння в останньому рядку функції робить ім'я локальним із першого рядка.

## Ключове слово `global`

Щоб **перепризначити** (rebind) глобальне ім'я зсередини функції, оголосіть його через `global`:

```python
counter = 10


def reset():
    global counter
    counter = 0
    print(counter)


reset()
print(counter)
```

Результат:

```text
0
0
```

`global counter` повідомляє компілятору: «у цій функції `counter` означає ім'я рівня модуля». Тепер присвоєння змінює глобальну прив'язку.

Кілька правил щодо `global`:

- Воно потрібне лише для **присвоєння** (перепризначення) глобального імені. Для читання глобальної змінної оголошення не потрібне.
- Через нього можна створити глобальну змінну, якої до виклику не існувало:

  ```python
  def setup():
      global config
      config = {"debug": True}


  setup()
  print(config)
  ```

  Результат:

  ```text
  {'debug': True}
  ```

- Оголошення має стояти перед будь-яким використанням імені в цій функції. Інакше код навіть не скомпілюється:

  ```python
  counter = 0


  def reset():
      counter = 1
      global counter
  ```

  Результат:

  ```text
    File "app.py", line 6
      global counter
      ^^^^^^^^^^^^^^
  SyntaxError: name 'counter' is assigned to before global declaration
  ```

- Щоб **змінити** глобальний об'єкт (а не перепризначити ім'я), `global` не потрібне, адже жодне ім'я не перев'язується:

  ```python
  events = []


  def log(event):
      events.append(event)


  log("start")
  log("stop")
  print(events)
  ```

  Результат:

  ```text
  ['start', 'stop']
  ```

### Чому варто уникати глобального стану

`global` працює, але функції, які читають і переписують глобальні змінні, важко тестувати й аналізувати: їхній результат залежить від прихованого стану, а змінити цей стан може будь-яка інша функція. Краще передавати значення як аргументи й повертати результат:

```python
def increment(counter, by=1):
    return counter + by


counter = 10
counter = increment(counter)
print(counter)
```

Результат:

```text
11
```

Залиште `global` для рідкісних випадків, як-от кеш на рівні модуля чи конфігурація, яку задають один раз. Якщо потрібен стан, що зберігається між викликами, зазвичай чистіше рішення — клас або замикання.

## Блоки не створюють областей видимості

У C, Java чи JavaScript (`let`) фігурні дужки створюють нову область видимості. У Python області видимості створюють лише **модулі, функції (зокрема лямбди), класи та включення (comprehensions)**. Тіла `if`, `for`, `while`, `with` і `try` нової області не створюють, тож імена, присвоєні в них, належать до зовнішньої області:

```python
for i in range(3):
    pass
print(i)

if True:
    status = "ready"
print(status)

squares = [n * n for n in range(3)]
try:
    print(n)
except NameError as error:
    print("NameError:", error)
```

Результат:

```text
2
ready
NameError: name 'n' is not defined
```

- Змінна циклу `i` доступна й після циклу та зберігає останнє значення.
- `status` створено всередині блоку `if`, але це звичайна змінна рівня модуля.
- Змінна `n` зі спискового включення назовні не «просочується», бо включення мають власну область видимості. (Python 3.12 пришвидшив включення, вбудовуючи їх у навколишній код, але цю поведінку зберіг.)

Окремий випадок: ім'я з `except SomeError as error:` видаляється, щойно блок `except` завершується, тож після блоку використати `error` не вийде. Якщо виняток потрібен пізніше, скопіюйте його в іншу змінну.

## Типові помилки

- **Очікувати, що `+=` оновить глобальну змінну.** `total += 1` у функції — це присвоєння `total`, тому `total` стає локальною, і рядок генерує `UnboundLocalError`. Або оголосіть `global total`, або (що краще) передайте значення в функцію й поверніть нове.
- **Вважати, що `global` потрібне для читання змінної.** Воно потрібне лише для перепризначення. Якщо додавати `global` усюди «про всяк випадок», код стає важче читати.
- **Затіняти вбудовані імена.** Якщо назвати змінну `list`, `dict`, `str`, `sum`, `max`, `id` чи `input`, вбудоване ім'я стане недоступним до кінця області видимості:

  ```python
  list = [1, 2, 3]
  try:
      print(list("abc"))
  except TypeError as error:
      print("TypeError:", error)

  del list
  print(list("abc"))
  ```

  Результат:

  ```text
  TypeError: 'list' object is not callable
  ['a', 'b', 'c']
  ```

  `del list` видаляє глобальне ім'я, і пошук знову доходить до вбудованої області. Але краще одразу обирати імена на кшталт `items` чи `numbers`.

- **Очікувати, що методи бачать імена рівня класу напряму.** Тіло класу має власний простір імен, але воно *не є* охопною областю видимості для методів, оголошених у ньому:

  ```python
  class Config:
      retries = 3

      def show(self):
          return retries


  try:
      Config().show()
  except NameError as error:
      print("NameError:", error)
  ```

  Результат:

  ```text
  NameError: name 'retries' is not defined
  ```

  Пишіть `self.retries` або `Config.retries`.

- **Вважати «глобальне» загальнопрограмним.** Глобальна змінна належить одному модулю. Інший модуль дістається до неї через об'єкт модуля, наприклад `settings.debug` після `import settings`.

## Підсумок

- Область видимості — це ділянка коду, де видно ім'я. Прив'язки зберігаються в просторах імен, по одному на кожну область.
- У Python є вбудована, глобальна (модульна), охопна й локальна області видимості, і імена шукаються в порядку LEGB: перемагає перший збіг.
- Вбудовану область видно всюди. Глобальна охоплює один модуль. Локальна існує лише під час виклику функції, і кожен виклик отримує нову.
- Присвоєння імені будь-де у функції робить його локальним для всієї функції, звідси й `UnboundLocalError`.
- `global name` дає функції змогу перепризначити ім'я рівня модуля. Для читання глобальних змінних і зміни глобальних об'єктів воно не потрібне.
- Області видимості створюють лише модулі, функції, класи та включення (comprehensions). Блоки `if`, `for`, `while`, `with` і `try` їх не створюють.
- Надавайте перевагу аргументам і поверненим значенням замість глобального стану й не затіняйте вбудовані імена.

## Практика

### Вправа 1: Передбачте результат

Не запускаючи код, запишіть, що він виведе. Потім запустіть і перевірте.

```python
x = "global"


def first():
    x = "local"
    return x


def second():
    return x


def third():
    global x
    x = "changed"
    return x


print(first(), x)
print(second())
print(third(), x)
print(second())
```

### Вправа 2: Виправте накопичувальну суму

Код нижче генерує `UnboundLocalError`. Виправте його двома способами: (а) за допомогою ключового слова `global` і (б) взагалі без глобального стану: нехай `add()` приймає поточну суму й повертає нову.

## Розв'язки

### Вправа 1

Результат:

```text
local global
global
changed changed
changed
```

`first()` створює власну локальну `x`, тому глобальна не змінюється. `second()` лише читає `x` і знаходить глобальну змінну. `third()` оголошує `x` глобальною й перепризначає її, тож і повернене значення, і `x` рівня модуля дорівнюють `"changed"`, а останній виклик `second()` бачить уже нове значення.

### Вправа 2

(а) З `global`:

```python
total = 0


def add(amount):
    global total
    total += amount
    return total


add(5)
add(10)
print(total)
```

Результат:

```text
15
```

(б) Без глобального стану:

```python
def add(total, amount):
    return total + amount


total = 0
total = add(total, 5)
total = add(total, 10)
print(total)
```

Результат:

```text
15
```

Варіант (б) легше тестувати: `add(0, 5)` завжди повертає `5`, хоч би що відбувалося раніше.

### Вправа 3

```python
import builtins

limit = 100


def where_is(name):
    if name in globals():
        return "global"
    if hasattr(builtins, name):
        return "built-in"
    return "not found"


print(where_is("limit"))
print(where_is("len"))
print(where_is("where_is"))
print(where_is("magic"))
```

Результат:

```text
global
built-in
global
not found
```

`where_is` теж є глобальним ім'ям, бо `def` на рівні модуля прив'язує його в глобальному просторі імен.

### Вправа 4

Перший рядок прив'язує глобальне ім'я `sum` до об'єкта `int`. Відтоді пошук `sum` зупиняється в глобальній області й ніколи не доходить до вбудованої функції `sum()`, тож `sum(numbers)` намагається викликати ціле число `60` і генерує `TypeError: 'int' object is not callable`. total = 0

