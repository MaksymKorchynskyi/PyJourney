# Групи захоплення

Дужки в регулярному виразі виконують дві роботи: **групують** частину шаблону і **захоплюють** текст, який ця частина знайшла, щоб його можна було прочитати потім. Групи захоплення (capturing groups) перетворюють регулярний вираз із перевірки «так чи ні» на інструмент, що витягує з тексту структуровані дані: ідентифікатори, дати, імена, числа.

## Що ви дізнаєтесь

- Як створити групу захоплення за допомогою `(...)` і прочитати її через `group()`, індексацію та `groups()`
- Як нумеруються групи, зокрема вкладені
- Як давати групам імена за допомогою `(?P<name>...)` і отримувати їх словником через `groupdict()`
- Що повертають необов'язкові групи, які не брали участі у збігу, і групи з повторенням
- Як групи змінюють результат `re.findall()`
- Чому `lastindex` — це не кількість груп

## Збіг без груп

Припустімо, сайт показує новину з ідентифікатором `100` за шляхом `news/100`. Такий шаблон знаходить цей шлях:

```text
\w+/\d+
```

- `\w+` збігається з одним або кількома символами слова (літерами, цифрами та `_`).
- `/` збігається з символом скісної риски.
- `\d+` збігається з однією або кількома цифрами.

Шаблон не обмежується словом `news`: він так само знайде `posts/7`, `todos/42` тощо.

```python
import re

path = "news/100"

for match in re.finditer(r"\w+/\d+", path):
    print(match)
```

Результат:

```text
<re.Match object; span=(0, 8), match='news/100'>
```

Збіг повідомляє лише, *що* текст відповідає шаблону, а ідентифікатор усе ще доводиться вирізати вручну. Саме для цього й потрібні групи.

> **Зверніть увагу:** записуйте кожен шаблон як сирий рядок (raw string): `r"..."`. У звичайному рядку `"\d"` — недопустима escape-послідовність, і починаючи з Python 3.12 вона спричиняє `SyntaxWarning`. Гірше те, що деякі послідовності є цілком допустимими в рядках, але означають інше: `"\b"` — це символ backspace, а не межа слова. Сирий рядок передає зворотну скісну риску рушію регулярних виразів без змін.

## Створення групи захоплення

Щоб захопити частину збігу, візьміть відповідну частину шаблону в дужки:

```text
\w+/(\d+)
```

Дужки не змінюють того, *що* саме знаходить шаблон. Вони лише кажуть рушію запам'ятати текст, який знайшов `\d+`, щоб потім його можна було отримати.

```python
import re

match = re.search(r"\w+/(\d+)", "news/100")

print(match)
print(match.group(0))
print(match.group(1))
```

Результат:

```text
<re.Match object; span=(0, 8), match='news/100'>
news/100
100
```

- `group(0)` (або просто `group()`) — це **увесь збіг**.
- `group(1)` — текст, захоплений **першою** групою, `group(2)` — другою і так далі.

Щоб захопити ще й назву ресурсу, додайте другу групу:

```python
import re

match = re.search(r"(\w+)/(\d+)", "news/100")

print(match.group())        # те саме, що group(0)
print(match.group(1))
print(match.group(2))
print(match.group(1, 2))    # кілька груп одразу -> кортеж
print(match[1], match[2])   # індексація — скорочення для group()
print(match.groups())       # усі групи кортежем

resource, news_id = match.groups()
print(resource, int(news_id) + 1)
```

Результат:

```text
news/100
news
100
('news', '100')
news 100
('news', '100')
news 101
```

Захоплені значення завжди є **рядками** (або `None`, як ви побачите далі). Перед арифметикою перетворюйте їх самостійно за допомогою `int()`, `float()` тощо.

### API об'єкта `Match` коротко

| Вираз | Результат |
|---|---|
| `m.group()` / `m.group(0)` / `m[0]` | увесь збіг |
| `m.group(n)` / `m[n]` | текст групи `n` |
| `m.group(a, b)` | кортеж із групами `a` і `b` |
| `m.groups(default=None)` | кортеж усіх груп (`1..N`) |
| `m.groupdict(default=None)` | словник усіх **іменованих** груп |
| `m.start(n)`, `m.end(n)`, `m.span(n)` | де саме в рядку збіглася група `n` |
| `m.re.groups` | скільки груп визначає шаблон |
| `m.lastindex`, `m.lastgroup` | номер / ім'я останньої групи, що збіглася |

## Як нумеруються групи

Групи нумеруються за їхньою **відкривною дужкою**, зліва направо, починаючи з 1. Тому вкладені групи теж отримують номери:

```text
((\d{4})-(\d{2}))-(\d{2})
12       3        4
```

```python
import re

match = re.search(r"((\d{4})-(\d{2}))-(\d{2})", "Released on 2024-10-07.")

for index in range(match.re.groups + 1):
    print(index, match.group(index), match.span(index))
```

Результат:

```text
0 2024-10-07 (12, 22)
1 2024-10 (12, 19)
2 2024 (12, 16)
3 10 (17, 19)
4 07 (20, 22)
```

Група 1 — зовнішня (`рік-місяць`), а групи 2 і 3 містяться всередині неї. `span(n)` повертає позиції `(початок, кінець)` групи у вихідному рядку.

### Чому не варто перебирати групи через `lastindex`?

Іноді трапляється код, що перебирає `range(match.lastindex + 1)`. Здається, ніби так охоплюються всі групи, але `lastindex` — це номер **останньої групи, яка завершила збіг**, а не кількість груп. А якщо жодна група не збіглася, він дорівнює `None`:

```python
import re

nested = re.search(r"((\w+)/(\d+))", "news/100")
print(nested.groups())
print(nested.lastindex)     # зовнішня група закрилася останньою
print(nested.re.groups)     # кількість груп у шаблоні

plain = re.search(r"\w+/\d+", "news/100")
print(plain.lastindex)
```

Результат:

```text
('news/100', 'news', '100')
1
3
None
```

З вкладеним шаблоном такий цикл вивів би лише групи 0 і 1, а без груп вираз `None + 1` згенерує `TypeError`. Використовуйте `match.re.groups` (кількість груп) або просто перебирайте `match.groups()`.

## Іменовані групи: `(?P<name>...)`

Номери зручні, коли груп одна-дві, але `match.group(3)` нічого не каже про те, *що* містить група 3, а додавання нової групи зсуває всі номери після неї. **Іменована група** (named group) отримує змістовне ім'я:

```text
(?P<name>rule)
```

- Дужки створюють групу.
- `?P<name>` задає ім'я. Воно має бути коректним ідентифікатором Python і не повторюватися в межах шаблону.
- `rule` — підшаблон, який треба захопити.

```python
import re

pattern = r"(?P<resource>\w+)/(?P<id>\d+)"
match = re.search(pattern, "news/100")

print(match.group("resource"))
print(match["id"])
print(match.group(2))        # іменовані групи теж мають номери
print(match.groupdict())
```

Результат:

```text
news
100
100
{'resource': 'news', 'id': '100'}
```

`groupdict()` повертає словник, де ключі — імена груп, а значення — захоплені рядки. Неіменовані групи до нього не потрапляють, проте кожна група, з іменем чи без, однаково має номер.

Довший приклад розбирає шляхи з датами. `fullmatch()` вимагає, щоб збігся **весь** рядок, і саме це зазвичай потрібно для перевірки шляху:

```python
import re

pattern = r"(?P<resource>\w+)/(?P<year>\d{4})/(?P<month>\d{1,2})/(?P<day>\d{1,2})"

for path in ["news/2021/12/31", "posts/2024/3/7", "news/2021/12"]:
    match = re.fullmatch(pattern, path)
    if match:
        print(match.groupdict())
    else:
        print(path, "-> no match")
```

Результат:

```text
{'resource': 'news', 'year': '2021', 'month': '12', 'day': '31'}
{'resource': 'posts', 'year': '2024', 'month': '3', 'day': '7'}
news/2021/12 -> no match
```

Скомпільований шаблон теж знає імена груп: `re.compile(pattern).groupindex` — це відображення з імені групи на її номер, наприклад `{'resource': 1, 'id': 2}` для першого шаблону вище.

> **Зверніть увагу:** у Python іменовані групи записують як `(?P<name>...)`. Коротший запис `(?<name>...)`, прийнятий у JavaScript, .NET і PCRE, модуль `re` **не** підтримує: він згенерує `re.PatternError: unknown extension ?<n` (до Python 3.13 цей клас винятку називався `re.error`, і стара назва досі працює як псевдонім).

## Групи, що не брали участі у збігу

Група з `?` після неї необов'язкова. Якщо вона не брала участі у збігу, її значення — `None`:

```python
import re

pattern = r"(\w+)/(\d+)(/edit)?"

print(re.fullmatch(pattern, "news/100/edit").groups())
print(re.fullmatch(pattern, "news/100").groups())
print(re.fullmatch(pattern, "news/100").groups(default=""))
```

Результат:

```text
('news', '100', '/edit')
('news', '100', None)
('news', '100', '')
```

`groups()` і `groupdict()` приймають аргумент `default`, який підставляється замість `None` для груп, що не збіглися. Пам'ятайте про різницю: `None` означає «група не брала участі», а `''` — «брала участь і збіглася з порожнім рядком» (наприклад, `(\d*)`, коли цифр немає).

## Група з повторенням пам'ятає лише останнє повторення

Коли до групи застосовано квантифікатор, вона збігається кілька разів, але запам'ятовується лише **останнє** повторення:

```python
import re

match = re.search(r"(\d+-)+", "10-20-30-")
print(match.group(0))
print(match.group(1))

match = re.search(r"((\d+-)+)", "10-20-30-")
print(match.group(1))
```

Результат:

```text
10-20-30-
30-
10-20-30-
```

Щоб захопити всю повторювану частину, огорніть повторення ще однією групою, як у другому шаблоні. А щоб отримати кожен фрагмент окремо, скористайтеся `re.findall()` або `re.finditer()` із простішим шаблоном.

## Групи змінюють результат `findall()`

Результат `re.findall()` залежить від кількості груп у шаблоні:

- груп немає — список повних збігів;
- одна група — список текстів цієї групи;
- кілька груп — список кортежів, по одному на кожен збіг.

```python
import re

text = "news/100, posts/7, todos/42"

print(re.findall(r"\w+/\d+", text))
print(re.findall(r"\w+/(\d+)", text))
print(re.findall(r"(\w+)/(\d+)", text))
```

Результат:

```text
['news/100', 'posts/7', 'todos/42']
['100', '7', '42']
[('news', '100'), ('posts', '7'), ('todos', '42')]
```

Коли потрібні і весь збіг, і іменовані групи, часто зручніший `re.finditer()`: він повертає повноцінні об'єкти `Match`:

```python
import re

text = "news/100, posts/7, todos/42"
pattern = r"(?P<resource>\w+)/(?P<id>\d+)"

for match in re.finditer(pattern, text):
    print(match.group(), match.groupdict(), match.span("id"))

ids = {m["resource"]: int(m["id"]) for m in re.finditer(pattern, text)}
print(ids)
```

Результат:

```text
news/100 {'resource': 'news', 'id': '100'} (5, 8)
posts/7 {'resource': 'posts', 'id': '7'} (16, 17)
todos/42 {'resource': 'todos', 'id': '42'} (25, 27)
{'news': 100, 'posts': 7, 'todos': 42}
```

Захоплені групи можна також повторно використати в тому самому шаблоні та в рядку заміни. Про це йдеться в наступній темі — про зворотні посилання.

## Типові помилки

- **Виклик `.group()` на `None`.** `re.search()`, `re.match()` і `re.fullmatch()` повертають `None`, коли збігу немає, тому `re.search(r"\d+", "no digits").group()` згенерує `AttributeError: 'NoneType' object has no attribute 'group'`. Спершу перевірте результат:

  ```python
  import re

  if (match := re.search(r"(\d+)", "order #512")):
      print(match.group(1))
  else:
      print("no number")
  ```

  Результат:

  ```text
  512
  ```

- **Звичайний рядок замість сирого.** `"\bcat\b"` містить два символи backspace, тож такий шаблон мовчки нічого не знаходить:

  ```python
  import re

  print(re.findall("\bcat\b", "cat"))
  print(re.findall(r"\bcat\b", "cat"))
  ```

  Результат:

  ```text
  []
  ['cat']
  ```

- **Сприймати `lastindex` як кількість груп.** Це номер останньої групи, що збіглася, і він може бути `None`. Кількість груп — це `match.re.groups`.
- **Очікувати числа замість рядків.** `match.group(1) + 1` згенерує `TypeError`, бо група містить `'100'`, а не `100`. Перетворюйте явно.
- **Дивуватися результату `findall()`.** Група, додана «лише для групування», змушує `findall()` повертати вміст групи замість усього збігу. Для чистого групування використовуйте групу без захоплення `(?:...)` (див. відповідну тему).
- **Очікувати, що група з повторенням зберігає всі повторення.** `(\d+-)+` пам'ятає лише останнє `\d+-`.
- **Писати `(?<name>...)`.** У Python потрібна літера `P`: `(?P<name>...)`.

## Підсумок

- Дужки `(...)` створюють групу захоплення. Вони не змінюють того, що знаходить шаблон, а лише запам'ятовують його частину.
- `group(0)` — увесь збіг, `group(n)` або `match[n]` — група `n`, а `groups()` повертає всі групи кортежем.
- Групи нумеруються за відкривною дужкою зліва направо, зокрема й вкладені. Їхня кількість — `match.re.groups`.
- `(?P<name>...)` створює іменовану групу. Її читають через `group("name")`, `match["name"]` або всі разом через `groupdict()`.
- Група, яка не брала участі у збігу, дорівнює `None`. Замінити його можна через `groups(default=...)` або `groupdict(default=...)`.
- Група під квантифікатором зберігає лише останнє повторення.
- Якщо в шаблоні є групи, `findall()` повертає групи (рядки або кортежі) замість повних збігів. `finditer()` дає повноцінні об'єкти `Match`.

## Розв'язки

### Вправа 1

```python
import re

line = "2024-05-17 12:30:01 ERROR Disk full on /dev/sda1"
pattern = (
    r"(?P<date>\d{4}-\d{2}-\d{2}) "
    r"(?P<time>\d{2}:\d{2}:\d{2}) "
    r"(?P<level>[A-Z]+) "
    r"(?P<message>.*)"
)

match = re.fullmatch(pattern, line)
print(match.groupdict())
```

Результат:

```text
{'date': '2024-05-17', 'time': '12:30:01', 'level': 'ERROR', 'message': 'Disk full on /dev/sda1'}
```

Сусідні сирі рядки склеюються в один шаблон, і довгий регулярний вираз лишається читабельним.

### Вправа 2

```python
import re

settings = "name=Olena; age=31; city=Lviv"
pairs = re.findall(r"(\w+)=([^;]+)", settings)
print(pairs)
print(dict(pairs))
```

Результат:

```text
[('name', 'Olena'), ('age', '31'), ('city', 'Lviv')]
{'name': 'Olena', 'age': '31', 'city': 'Lviv'}
```

З двома групами `findall()` повертає список кортежів `(ключ, значення)` — саме те, що приймає `dict()`.

### Вправа 3

```python
import re
from datetime import date

PATTERN = re.compile(r"news/(?P<year>\d{4})/(?P<month>\d{1,2})/(?P<day>\d{1,2})")


def parse_news_path(path):
    match = PATTERN.fullmatch(path)
    if match is None:
        return None
    parts = {name: int(value) for name, value in match.groupdict().items()}
    return date(**parts)


print(parse_news_path("news/2021/12/31"))
print(parse_news_path("news/2024/3/7"))
print(parse_news_path("news/2024/03"))
```

Результат:

```text
2021-12-31
2024-03-07
None
```

Імена груп збігаються з іменами параметрів `date(year, month, day)`, тож перетворений словник можна одразу розпакувати в конструктор.

### Вправа 4

Результат:

```text
[('10', 'px'), ('2', 'em'), ('7', '')]
```

У шаблоні дві групи, тому кожен збіг стає кортежем. Для `7` необов'язкова група `(px|em)?` не брала участі у збігу. `Match.groups()` показав би для неї `None`, але `findall()` для груп, що не збіглися, завжди підставляє порожній рядок.
