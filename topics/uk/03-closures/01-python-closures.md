# Замикання в Python

**Замикання** (closure) — це функція, яка пам'ятає змінні з області видимості, де її оголошено, навіть після того, як ця область завершила роботу. На замиканнях побудовано фабрики функцій, колбеки й декоратори, і саме вони пояснюють одну з класичних несподіванок Python: лямбди, створені в циклі, які всі повертають однаковий результат.

## Що ви дізнаєтесь

- Що таке вільні змінні і що перетворює вкладену функцію на замикання
- Як замикання зберігає зовнішні змінні «живими» після повернення із зовнішньої функції
- Що таке об'єкти-комірки (cells) і як їх дослідити через `__closure__` та `__code__.co_freevars`
- Чому кожен виклик зовнішньої функції створює нове, незалежне замикання
- Чому замикання захоплюють змінні, а не значення (пізнє зв'язування), і як виправити пастку з циклом
- Коли варто використати замикання, а коли краще підійде клас

## Вкладені функції та вільні змінні

Функція, оголошена всередині іншої функції, може користуватися змінними зовнішньої:

```python
def say():
    greeting = "Hello"

    def display():
        print(greeting)

    display()


say()
```

Результат:

```text
Hello
```

Усередині `display` ім'я `greeting` не є ні локальною змінною (там їй нічого не присвоюють), ні глобальною. Воно належить охопній області видимості функції `say`. Змінну, яку функція використовує, але яка визначена в охопній функції, називають **вільною змінною** (free variable) цієї функції.

Дивлячись на `display`, ви насправді бачите дві речі:

- код функції `display`;
- вільну змінну `greeting`, яка посилається на `"Hello"`.

Таке поєднання функції та вільних змінних, які вона «носить» із собою, і є **замиканням**. За визначенням, **замикання — це вкладена функція, яка посилається на одну чи кілька змінних зі своєї охопної області видимості**.

> **Зверніть увагу:** вкладена функція, яка не використовує жодної змінної зовнішньої функції, замиканням не є. Її атрибут `__closure__` дорівнює `None`.

## Повернення внутрішньої функції

Найцікавіше починається, коли зовнішня функція не викликає внутрішню, а **повертає** її:

```python
def say():
    greeting = "Hello"

    def display():
        print(greeting)

    return display


fn = say()
fn()
```

Результат:

```text
Hello
```

Простежмо порядок подій:

1. Виконується `say()`: вона створює локальну змінну `greeting` і функцію `display`, а потім повертає `display`.
2. `say()` завершується. Її локальної області видимості більше немає.
3. Виконується `fn()` і все одно виводить `"Hello"`.

Якби локальні змінні зникали разом із викликом функції, `fn` не мала б що виводити. Замикання зберігає `greeting`: `fn` — це функція `display` плюс посилання на потрібну їй змінну.

## Комірки: як змінна переживає свою область видимості

Змінна, яку використовує внутрішня функція, живе одночасно у двох областях: в області `say` і в замиканні. Щоб обидві посилалися на одне й те саме, Python зберігає такі змінні в проміжному об'єкті — **комірці** (cell). І зовнішня функція, і замикання дістаються до значення через цю комірку:

```text
greeting у say() --------+
                         +---> комірка ---> об'єкт str 'Hello'
fn.__closure__[0] -------+
```

Коли `say()` повертає результат, її локальний простір імен зникає, але на комірку й далі посилається замикання, тож комірка та рядок, на який вона вказує, лишаються живими. Щоб прочитати `greeting` усередині замикання, Python робить «подвійний стрибок»: від замикання до комірки, від комірки до об'єкта.

Комірки можна побачити через атрибут функції `__closure__` — це кортеж, у якому на кожну вільну змінну припадає одна комірка:

```python
def say():
    greeting = "Hello"

    def display():
        print(greeting)

    return display


fn = say()
print(fn.__closure__)
print(fn.__closure__[0].cell_contents)
```

Результат (адреси щоразу різні):

```text
(<cell at 0x101128880: str object at 0x101104b40>,)
Hello
```

`cell_contents` повертає об'єкт, на який комірка посилається зараз.

Імена вільних змінних зберігаються в об'єкті коду. Внутрішня функція перелічує їх у `co_freevars`, а зовнішня перелічує змінні, які вона ділить із внутрішніми функціями, у `co_cellvars`:

```python
def say():
    greeting = "Hello"

    def display():
        print(greeting)

    return display


fn = say()
print(fn.__code__.co_freevars)
print(say.__code__.co_cellvars)
```

Результат:

```text
('greeting',)
('greeting',)
```

Можна також переконатися, що зовнішня функція та замикання бачать той самий об'єкт:

```python
def say():
    greeting = "Hello"
    print(hex(id(greeting)))

    def display():
        print(hex(id(greeting)))
        print(greeting)

    return display


fn = say()
fn()
```

Результат (адреси щоразу різні, але два числа завжди однакові):

```text
0x104b74b40
0x104b74b40
Hello
```

Виходячи з цього механізму, замикання можна уявляти як **функцію плюс розширену область видимості, що містить її вільні змінні**.

## Кожен виклик створює нове замикання

Кожен виклик функції створює нову локальну область видимості. Якщо функція будує замикання, то кожен виклик дає й **нове** замикання з **власними** комірками:

```python
def multiplier(x):
    def multiply(y):
        return x * y

    return multiply


m1 = multiplier(1)
m2 = multiplier(2)
m3 = multiplier(3)

print(m1(10))
print(m2(10))
print(m3(10))
print(m1 is m2)
print(m2.__closure__[0].cell_contents)
```

Результат:

```text
10
20
30
False
2
```

`multiplier` — це **фабрика функцій**: вона виготовляє спеціалізовані функції. `m1`, `m2` і `m3` мають спільний код, але кожна має власну комірку для `x`.

А от замикання, створені в **одному** виклику, комірки ділять між собою. Саме так кілька внутрішніх функцій можуть працювати з одним спільним станом:

```python
def make_counter():
    count = 0

    def increment():
        nonlocal count
        count += 1
        return count

    def current():
        return count

    return increment, current


increment, current = make_counter()
increment()
increment()
print(current())
print(increment.__closure__[0] is current.__closure__[0])
```

Результат:

```text
2
True
```

`increment` перепризначає `count`, тому їй потрібне `nonlocal` (див. попередню тему). `current` лише читає змінну.

## Замикання захоплюють змінні, а не значення

Замикання не копіює значення вільної змінної в момент свого створення. Воно тримає посилання на **змінну** (комірку) і читає її значення в момент **виклику**. Це називають **пізнім зв'язуванням** (late binding):

```python
def make_greeter():
    greeting = "Hello"

    def greet(name):
        return f"{greeting}, {name}!"

    greeting = "Hi"
    return greet


print(make_greeter()("Olena"))
```

Результат:

```text
Hi, Olena!
```

`greet` оголосили, коли `greeting` дорівнювала `"Hello"`, але на момент виклику змінна вже посилається на `"Hi"`.

## Пастка з циклом

Через пізнє зв'язування виникає відома несподіванка. Припустімо, ви хочете створити три множники в циклі:

```python
def make_multipliers():
    multipliers = []
    for x in range(1, 4):
        multipliers.append(lambda y: x * y)
    return multipliers


m1, m2, m3 = make_multipliers()

print(m1(10))
print(m2(10))
print(m3(10))
```

Результат:

```text
30
30
30
```

Цикл не створює нову змінну на кожній ітерації. У `make_multipliers` є лише **одна** змінна `x`, і всі три лямбди ділять її комірку. Коли їх викликають, цикл уже завершився, і `x` дорівнює `3`:

```python
def make_multipliers():
    multipliers = []
    for x in range(1, 4):
        multipliers.append(lambda y: x * y)
    return multipliers


m1, m2, m3 = make_multipliers()
print(m1.__code__.co_freevars)
print(m1.__closure__[0] is m3.__closure__[0])
print(m1.__closure__[0].cell_contents)
```

Результат:

```text
('x',)
True
3
```

> **Зверніть увагу:** якщо написати такий самий цикл на рівні модуля, лямбди навіть не будуть замиканнями: `x` там глобальна змінна, і кожна лямбда шукає її в глобальній області під час виклику. Результат той самий, `30 30 30`, і з тієї ж причини: значення читається пізно.

Є три поширені способи це виправити. Кожен із них гарантує, що функція отримає власне значення `x` **в момент створення**.

**Спосіб 1: фабрика функцій.** Кожен виклик `multiplier(x)` створює нову область видимості й нову комірку:

```python
def multiplier(x):
    def multiply(y):
        return x * y

    return multiply


multipliers = []
for x in range(1, 4):
    multipliers.append(multiplier(x))

m1, m2, m3 = multipliers

print(m1(10))
print(m2(10))
print(m3(10))
```

Результат:

```text
10
20
30
```

**Спосіб 2: значення за замовчуванням.** Значення параметрів за замовчуванням обчислюються один раз, під час оголошення функції, тож поточне значення `x` зберігається разом із кожною лямбдою:

```python
multipliers = [lambda y, x=x: x * y for x in range(1, 4)]
print([m(10) for m in multipliers])
```

Результат:

```text
[10, 20, 30]
```

Це коротко, але додає параметр `x`, який викликач може випадково перевизначити (`m(10, 5)`).

**Спосіб 3: `functools.partial`.** Ця функція «заморожує» частину аргументів наявної функції:

```python
import operator
from functools import partial

multipliers = [partial(operator.mul, x) for x in range(1, 4)]
print([m(10) for m in multipliers])
```

Результат:

```text
[10, 20, 30]
```

## Де застосовують замикання

- **Фабрики функцій.** Створення налаштованих функцій, як-от `multiplier(3)` чи логер нижче.
- **Колбеки.** Обробникам подій і функціям для `key=` часто потрібні додаткові дані. Замикання передає ці дані без глобальних змінних.
- **Приватний стан.** Лічильник чи кеш, захований у замиканні, не можна змінити ззовні інакше, ніж через повернені функції.
- **Декоратори.** Декоратор повертає замикання, яке обгортає початкову функцію. Про це йдеться в наступній темі.

```python
def make_logger(level):
    def log(message):
        print(f"[{level}] {message}")

    return log


info = make_logger("INFO")
error = make_logger("ERROR")

info("Server started")
error("Disk is full")
```

Результат:

```text
[INFO] Server started
[ERROR] Disk is full
```

### Замикання чи клас?

Замикання — це легкий об'єкт з одним методом. Той самий множник можна написати як клас із методом `__call__`:

```python
class Multiplier:
    def __init__(self, x):
        self.x = x

    def __call__(self, y):
        return self.x * y


triple = Multiplier(3)
print(triple(10))
print(triple.x)
```

Результат:

```text
30
3
```

Обирайте замикання для невеликої, чітко окресленої поведінки з мінімумом стану. Переходьте на клас, коли потрібні кілька операцій, видимий стан (`triple.x`), зрозуміле `repr` або успадкування.

## Типові помилки

- **Створювати замикання в циклі й очікувати, що кожне запам'ятає поточне значення.** Усі вони ділять змінну циклу й бачать її останнє значення. Використовуйте фабрику функцій, значення за замовчуванням або `functools.partial`.
- **Вважати, що замикання зберігає копію.** Воно зберігає посилання на змінну. Якщо зовнішня функція згодом змінить змінну, замикання побачить нове значення.
- **Перепризначати вільну змінну без `nonlocal`.** `count += 1` усередині замикання генерує `UnboundLocalError`. Оголосіть `nonlocal count`.
- **Викликати внутрішню функцію замість того, щоб повернути її.** `return display()` повертає результат виклику (тут `None`), а не функцію. Повертайте `display` без дужок.
- **Випадково тримати живими великі об'єкти.** Замикання не дає знищити жодну зі своїх вільних змінних, доки існує саме. Не захоплюйте величезний список, якщо вам потрібна лише його довжина.

## Підсумок

- Вільна змінна — це змінна, яку функція використовує, але яка визначена в охопній функції.
- Замикання — це вкладена функція разом із вільними змінними, на які вона посилається. Воно зберігає їх після повернення із зовнішньої функції.
- Спільні змінні Python зберігає в об'єктах-комірках. `fn.__closure__` містить комірки, `cell.cell_contents` показує значення, а `__code__.co_freevars` перелічує імена.
- Кожен виклик зовнішньої функції створює нове замикання з власними комірками. Функції, створені в одному виклику, ділять комірки.
- Замикання захоплюють змінні, а не значення: значення читається під час виклику замикання (пізнє зв'язування).
- Замикання, створені в циклі, ділять змінну циклу. Виправити це можна фабрикою функцій, значенням за замовчуванням або `functools.partial`.
- Замикання — основа фабрик функцій, колбеків і декораторів.

### Вправа 2

Усі лямбди ділять одну змінну `label` і читають її лише під час виклику. На той момент цикл уже завершився, і `label` дорівнює `"Exit"`.

Виправлення через значення за замовчуванням:

```python
def build_handlers(labels):
    handlers = []
    for label in labels:
        handlers.append(lambda label=label: print("Clicked", label))
    return handlers


for handler in build_handlers(["Save", "Open", "Exit"]):
    handler()
```

Виправлення через фабрику функцій:

```python
def make_handler(label):
    def handler():
        print("Clicked", label)

    return handler


def build_handlers(labels):
    return [make_handler(label) for label in labels]


for handler in build_handlers(["Save", "Open", "Exit"]):
    handler()
```

Результат обох варіантів:

```text
Clicked Save
Clicked Open
Clicked Exit
```

### Вправа 3

```python
def describe(fn):
    code = getattr(fn, "__code__", None)
    if code is None or fn.__closure__ is None:
        return {}
    return {
        name: cell.cell_contents
        for name, cell in zip(code.co_freevars, fn.__closure__)
    }


def make_power(n):
    def power(x):
        return x ** n

    return power


def make_logger(level):
    def log(message):
        print(f"[{level}] {message}")

    return log


print(describe(make_power(3)))
print(describe(make_logger("INFO")))
print(describe(len))
```

Результат:

```text
{'n': 3}
{'level': 'INFO'}
{}
```

Вбудовані функції, як-от `len`, не мають атрибута `__code__`, тож `getattr(..., None)` захищає від `AttributeError`.

### Вправа 4

```python
def make_cached(func):
    cache = {}

    def cached(n):
        if n not in cache:
            cache[n] = func(n)
        return cache[n]

    return cached


def square(n):
    print("computing", n)
    return n * n


fast_square = make_cached(square)
print(fast_square(4))
print(fast_square(4))
print(fast_square(5))
print(fast_square(4))
```

Результат:

```text
computing 4
16
16
computing 5
25
16
```

`cache` змінюється (`cache[n] = ...`), а не перепризначається, тому `nonlocal` не потрібне. Такий шаблон «функція, що обгортає іншу функцію» — це саме те, чим є декоратор.
