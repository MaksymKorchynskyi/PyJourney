# Кортеж чи список

І кортежі, і списки — це послідовності, які можуть містити будь-які об'єкти, і обидва підтримують індексацію, зрізи, `len()`, `in`, `index()` та `count()`. Ключова відмінність у тому, що **список змінюваний**, а **кортеж незмінюваний**. Ця одна відмінність впливає на використання пам'яті, швидкість, можливість бути ключем словника та на те, як слід застосовувати кожен тип у коді.

## Що ви дізнаєтесь

- Що насправді означає «незмінюваний» для кортежу, зокрема для кортежів зі змінюваними об'єктами всередині
- Чому кортеж займає менше пам'яті, ніж список, і що таке надлишкове виділення пам'яті для списку
- Чому «копіювання» кортежу майже нічого не коштує і як чесно вимірювати швидкість за допомогою `timeit`
- Чому кортежі можуть бути ключами словника й елементами множини, а списки — ні
- Як по-різному поводиться `+=` зі списками й кортежами
- Як обирати між кортежем і списком

## Список змінюваний, кортеж незмінюваний

Список можна змінювати після створення:

```python
fruits = ["apple", "orange", "banana"]
fruits[0] = "strawberry"
fruits.append("kiwi")

print(fruits)
```

Результат:

```text
['strawberry', 'orange', 'banana', 'kiwi']
```

Кортеж змінити не можна. Присвоєння елементу завершується помилкою, а методів на кшталт `append()`, `remove()` чи `sort()` у кортежів просто немає:

```python
fruits = ("apple", "orange", "banana")

try:
    fruits[0] = "strawberry"
except TypeError as error:
    print("TypeError:", error)

try:
    fruits.append("kiwi")
except AttributeError as error:
    print("AttributeError:", error)
```

Результат:

```text
TypeError: 'tuple' object does not support item assignment
AttributeError: 'tuple' object has no attribute 'append'
```

Кортежі мають лише два методи: `count()` та `index()`.

### Перев'язування — це не зміна

Тій самій змінній можна присвоїти **новий** кортеж. Старий кортеж від цього не змінюється: створюється інший об'єкт, і ім'я перев'язується на нього:

```python
fruits = ("apple", "orange", "banana")
print(hex(id(fruits)))

fruits = ("strawberry", "orange", "banana")
print(hex(id(fruits)))
```

Результат (адреси щоразу інші, але завжди різні між собою):

```text
0x1047a2f80
0x1047a3040
```

Те саме стосується `+=`. Для списку `+=` розширює наявний об'єкт на місці. Для кортежу — створює новий кортеж і перев'язує ім'я:

```python
numbers_list = [1, 2]
alias_list = numbers_list
numbers_list += [3]
print(alias_list, numbers_list is alias_list)

numbers_tuple = (1, 2)
alias_tuple = numbers_tuple
numbers_tuple += (3,)
print(alias_tuple, numbers_tuple is alias_tuple)
```

Результат:

```text
[1, 2, 3] True
(1, 2) False
```

### Незмінюваність поверхнева

Кортеж зберігає посилання. «Незмінюваний» означає, що ці посилання ніколи не можна замінити, але об'єкти, на які вони вказують, можуть бути змінюваними:

```python
order = ("Olena", ["coffee"])
order[1].append("croissant")
print(order)
```

Результат:

```text
('Olena', ['coffee', 'croissant'])
```

Кортеж і далі містить той самий список. Змінився саме список. Тож кортеж «повністю» незмінюваний лише тоді, коли незмінювані й усі його елементи.

### Створення кортежів

Кортеж створює кома, а не дужки. Це важливо для кортежів з одного елемента:

```python
print(type((1)))
print(type((1,)))
print(type(()))

point = 3, 4
x, y = point
print(point, x, y)
```

Результат:

```text
<class 'int'>
<class 'tuple'>
<class 'tuple'>
(3, 4) 3 4
```

`(1)` — це просто число `1` у дужках. `point = 3, 4` **пакує** два значення в кортеж, а `x, y = point` **розпаковує** його.

## Кортеж займає менше пам'яті

`sys.getsizeof()` повертає розмір самого об'єкта в байтах (без урахування елементів, на які він посилається):

```python
from sys import getsizeof

fruits = ["apple", "orange", "banana"]
print(f"The size of the list is {getsizeof(fruits)} bytes.")

fruits = ("apple", "orange", "banana")
print(f"The size of the tuple is {getsizeof(fruits)} bytes.")
```

Результат (Python 3.14, 64-біт; точні числа відрізняються між версіями):

```text
The size of the list is 88 bytes.
The size of the tuple is 72 bytes.
```

Причин дві:

1. **Будова.** Кортеж зберігає посилання на елементи безпосередньо всередині об'єкта. Список тримає їх в окремому масиві й має ще й пам'ятати, скільки місця для нього виділено.
2. **Надлишкове виділення пам'яті** (over-allocation). Оскільки список може зростати, під час зміни розміру CPython резервує додаткові комірки. Тоді більшості викликів `append()` не доводиться перевиділяти пам'ять, і додавання в середньому відбувається швидко. Кортеж має фіксовану довжину, тож отримує рівно стільки місця, скільки потрібно.

Надлишкове виділення видно, якщо стежити за зростанням списку:

```python
from sys import getsizeof

items = []
last = None
for i in range(20):
    size = getsizeof(items)
    if size != last:
        print(f"len={len(items):2} size={size}")
        last = size
    items.append(i)
```

Результат (Python 3.14, 64-біт):

```text
len= 0 size=56
len= 1 size=88
len= 5 size=120
len= 9 size=184
len=17 size=248
```

Розмір зростає стрибками: після першого `append()` у списку є місце для 4 елементів, потім для 8, потім для 16 і так далі. Кожна комірка — це 8-байтове посилання.

Для одного об'єкта економія невелика, але вона накопичується, коли в пам'яті зберігаються мільйони дрібних записів.

## Копіювання кортежу майже безкоштовне

Копіювання списку мусить створити новий список, адже копія та оригінал повинні змінюватися незалежно:

```python
fruit_list = ["apple", "orange", "banana"]
fruit_list2 = list(fruit_list)

print(fruit_list2 == fruit_list)
print(fruit_list2 is fruit_list)
```

Результат:

```text
True
False
```

Кортеж ніколи не змінюється, тож дублювати його немає сенсу. `tuple(t)`, `t[:]` і `copy.copy(t)` просто повертають той самий об'єкт:

```python
import copy

fruit_tuple = ("apple", "orange", "banana")

print(tuple(fruit_tuple) is fruit_tuple)
print(fruit_tuple[:] is fruit_tuple)
print(copy.copy(fruit_tuple) is fruit_tuple)
```

Результат:

```text
True
True
True
```

> **Зверніть увагу:** таке повторне використання — оптимізація CPython, а не гарантія мови. Ніколи не пишіть код, який покладається на те, що `is` тут поверне `True`.

### Чесне вимірювання

Чесний бенчмарк має вимірювати лише копіювання, тож початковий об'єкт варто створити один раз у `setup`:

```python
from timeit import timeit

times = 1_000_000

t_list = timeit("list(data)", setup="data = ['apple', 'orange', 'banana']", number=times)
t_tuple = timeit("tuple(data)", setup="data = ('apple', 'orange', 'banana')", number=times)

print(f"copy a list  {times:,} times: {t_list:.3f} s")
print(f"copy a tuple {times:,} times: {t_tuple:.3f} s")
print(f"difference: {(t_tuple - t_list) / t_list:.0%}")
```

Результат (час залежить від комп'ютера й запуску):

```text
copy a list  1,000,000 times: 0.028 s
copy a tuple 1,000,000 times: 0.007 s
difference: -76%
```

«Копіювання» кортежу лише повертає наявний об'єкт, тоді як копіювання списку виділяє пам'ять і копіює посилання. Під час створення об'єктів розрив схожий, але з іншої причини: літерал кортежу лише з констант, як-от `("apple", "orange", "banana")`, будується один раз під час компіляції коду й зберігається як константа, а літерал списку будується заново під час кожного виконання.

Ідеться про наносекунди на операцію. Обирайте між кортежами й списками за тим, що вони **означають**, а різницю у швидкості сприймайте як бонус.

## Кортежі можуть бути ключами словника

Ключі словника й елементи множини мають бути **хешованими** (hashable): їхній хеш ніколи не повинен змінюватися. Кортеж із хешованих елементів хешований, список — ніколи:

```python
visits = {(50.45, 30.52): "Kyiv", (49.84, 24.03): "Lviv"}
print(visits[(49.84, 24.03)])

try:
    bad = {[50.45, 30.52]: "Kyiv"}
except TypeError as error:
    print("TypeError:", error)

try:
    hash(("Kyiv", [50.45, 30.52]))
except TypeError as error:
    print("TypeError:", error)
```

Результат:

```text
Lviv
TypeError: cannot use 'list' as a dict key (unhashable type: 'list')
TypeError: unhashable type: 'list'
```

Останній приклад знову показує поверхневу незмінюваність: кортеж, що містить список, не хешований.

## Коли що використовувати

| | `list` | `tuple` |
|---|---|---|
| Змінюваний | так | ні |
| Типове значення | колекція однотипних елементів, кількість яких може змінюватися | фіксована група значень, запис, де позиція має зміст |
| Приклад | `["apple", "orange"]`, рядки, прочитані з файлу | `(x, y)`, `(name, age)`, `(r, g, b)` |
| Методи | багато: `append`, `extend`, `insert`, `remove`, `pop`, `sort`, ... | лише `count` та `index` |
| Хешований (ключ словника, елемент множини) | ні | так, якщо всі елементи хешовані |
| Пам'ять | більше, з надлишковим виділенням | менше, рівно стільки, скільки треба |

Практичні правила:

- Використовуйте **список**, коли додаватимете, видалятимете, сортуватимете чи замінюватимете елементи.
- Використовуйте **кортеж** для даних, які не повинні змінюватися: координат, кольорів RGB, рядків бази даних, кількох значень, що повертає функція (`return low, high`), і ключів словника.
- Кортеж ще й документує намір: той, хто читає код, бачить, що дані не мають змінюватися.
- Для записів із багатьма полями розгляньте `collections.namedtuple` чи `typing.NamedTuple`, які додають кортежу імена полів, або dataclass.

## Типові помилки

- **Забути кому в кортежі з одного елемента.** `(1)` — це `int`. Пишіть `(1,)` або `1,`.
- **Вважати, що вміст кортежу ніколи не змінюється.** Якщо кортеж містить список, цей список може змінитися. Незмінні лише посилання.
- **Використати `+=` для списку всередині кортежу.** Це генерує помилку *і* все одно змінює список:

  ```python
  t = (1, [2])
  try:
      t[1] += [3]
  except TypeError as error:
      print("TypeError:", error)
  print(t)
  ```

  Результат:

  ```text
  TypeError: 'tuple' object does not support item assignment
  (1, [2, 3])
  ```

  `t[1] += [3]` спершу розширює список на місці (це вдається), а потім намагається записати результат назад у `t[1]` (це не вдається). Натомість викличте `t[1].extend([3])`.

- **Перетворювати туди й назад заради швидкості.** Перетворення списку на кортеж «щоб було швидше» коштує повного копіювання й рідко окупається. Обирайте тип, який відповідає даним.
- **Нечесний бенчмарк.** Порівняння `list([...])` з `tuple((...))` здебільшого вимірює створення літералів, а не копіювання. Початковий об'єкт варто створювати в `setup`.

## Підсумок

- Список змінюваний, кортеж незмінюваний. Присвоєння змінній нового кортежу перев'язує ім'я, а старий кортеж лишається незмінним.
- Незмінюваність кортежу поверхнева: посилання фіксовані, але змінювані об'єкти всередині можуть змінюватися.
- Кортежі займають менше пам'яті: немає окремого масиву й надлишкового виділення. Списки виділяють пам'ять із запасом, щоб `append()` в середньому працював швидко.
- Копіювання кортежу через `tuple(t)` чи `t[:]` у CPython повертає той самий об'єкт, тож практично нічого не коштує. Копіювання списку створює новий список.
- Кортежі з хешованих елементів можуть бути ключами словника й елементами множини, списки — ні.
- Обирайте за змістом: список — для колекції, що змінюється, кортеж — для фіксованого запису чи значень, які не мають змінюватися.

```python
a = [1, 2]
b = a
a += [3]

c = (1, 2)
d = c
c += (3,)

print(a, b, a is b)
print(c, d, c is d)
```

Ви отримуєте GPS-точки у вигляді списків: `[[50.45, 30.52], [49.84, 24.03], [50.45, 30.52]]`. Підрахуйте, скільки разів трапляється кожна точка, використавши словник, ключами якого є точки. Виведіть словник.

### Вправа 3: Розмір на один елемент

За допомогою `sys.getsizeof()` порівняйте список і кортеж, створені з `range(1000)`. Виведіть обидва розміри й кількість байтів на один елемент для кожного (розмір поділити на `1000`, округлити до двох знаків). Потім поясніть, звідки в списку зайві байти.

## Розв'язки

### Вправа 1

Результат:

```text
[1, 2, 3] [1, 2, 3] True
(1, 2, 3) (1, 2) False
```

Для списку `+=` викликає `extend()` на наявному об'єкті, тож `a` і `b` і далі посилаються на той самий, тепер довший, список. Для кортежу `+=` створює новий кортеж `(1, 2, 3)` і перев'язує `c`, а `d` зберігає початковий `(1, 2)`.

### Вправа 2

```python
points = [[50.45, 30.52], [49.84, 24.03], [50.45, 30.52]]

counts = {}
for point in points:
    key = tuple(point)
    counts[key] = counts.get(key, 0) + 1

print(counts)
```

Результат:

```text
{(50.45, 30.52): 2, (49.84, 24.03): 1}
```

Списки не можуть бути ключами словника, тому кожну точку спершу перетворено на кортеж. `collections.Counter(tuple(p) for p in points)` дає той самий результат в один рядок.

### Вправа 3

```python
from sys import getsizeof

as_list = list(range(1000))
as_tuple = tuple(range(1000))

print(getsizeof(as_list), round(getsizeof(as_list) / 1000, 2))
print(getsizeof(as_tuple), round(getsizeof(as_tuple) / 1000, 2))
```

Результат (Python 3.14, 64-біт):

```text
8056 8.06
8048 8.05
```

Обидва зберігають одне 8-байтове посилання на елемент, тож вартість одного елемента майже однакова. Різниця — у заголовку об'єкта: список має окремий масив і стежить за виділеною місткістю. Тут `list(range(1000))` заздалегідь знає кінцеву довжину, тож не виділяє пам'ять із запасом. Список, побудований 1000 викликами `append()`, більший (8856 байтів у Python 3.14) через запасні комірки, зарезервовані під час зростання.

### Вправа 4

`order[1] += ["tea"]` виконується у два кроки: список `order[1]` розширюється на місці (це вдається), а потім результат присвоюється назад в `order[1]` (це не вдається, бо кортежі не підтримують присвоєння елементів). Змінюйте список напряму, без жодного присвоєння кортежу:

```python
order = ("Olena", ["coffee"])
order[1].append("tea")
print(order)
```

Результат:

```text
('Olena', ['coffee', 'tea'])
```

Якщо замовлення має бути повністю незмінюваним, зберігайте позиції як кортеж і створюйте нове замовлення: `order = (order[0], order[1] + ("tea",))`.
