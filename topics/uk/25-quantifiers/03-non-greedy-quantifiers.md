# Нежадібні квантифікатори

**Нежадібний** (non-greedy), або **лінивий** (lazy), квантифікатор — протилежність жадібному: він бере **якнайменше** повторень і додає ще одне лише тоді, коли решта шаблону поки що не може збігтися. Будь-який квантифікатор стає лінивим, якщо дописати до нього знак питання: `*?`, `+?`, `??`, `{n,m}?`. Ліниві квантифікатори — найшвидший спосіб виправити шаблон, що «захоплює забагато» між роздільниками: лапками, тегами чи позначками коментарів.

## Що ви дізнаєтесь

- Як зробити будь-який квантифікатор лінивим
- Як рушій крок за кроком розширює лінивий квантифікатор
- Як поводяться жадібна й лінива версії кожного квантифікатора на тих самих вхідних даних
- Чому лінивий квантифікатор усе одно повертає найлівіший збіг, а не найкоротший
- Чому лінивий квантифікатор у кінці шаблону майже нічого не захоплює
- Коли обирати лінивий квантифікатор, а коли краще підходить заперечний набір

## Жадібні й ліниві квантифікатори

| Жадібний | Лінивий | Лінива версія збігається з попереднім елементом |
|---|---|---|
| `*` | `*?` | нуль або більше разів, якнайменше |
| `+` | `+?` | один або більше разів, якнайменше |
| `?` | `??` | нуль разів або один, переважно нуль |
| `{n}` | `{n}?` | рівно `n` разів (вибору немає, тож те саме, що й жадібний) |
| `{n,}` | `{n,}?` | щонайменше `n` разів, якнайменше |
| `{n,m}` | `{n,m}?` | від `n` до `m` разів, якнайменше |

Обидва режими приймають ті самі рядки. Різниця в тому, який збіг рушій **пробує першим**: жадібний починає з найбільшої кількості повторень і відступає, лінивий починає з найменшої й просувається вперед.

## Приклад із кнопкою

У темі «Жадібні квантифікатори» шаблон `".+"` збігався від першої лапки до останньої. Якщо додати `?`, квантифікатор `+` стає лінивим, і кожне значення в лапках стає окремим збігом:

```python
import re

s = '<button type="submit" class="btn">Send</button>'

for match in re.finditer(r'".+?"', s):
    print(match.group())
```

Результат:

```text
"submit"
"btn"
```

## Як працює ліниве зіставлення

1. Рушій знаходить першу `"` на індексі 13.
2. `.+?` мусить узяти щонайменше один символ, тож бере `s`.
3. Тепер шаблон потребує `"`, але наступний символ — `u`. Замість того щоб здатися, рушій дозволяє `.+?` узяти **ще один** символ і перевіряє знову.
4. Так триває, доки `.+?` не міститиме `submit`, а наступним символом не буде `"`. Шаблон завершується: збіг — `"submit"`.
5. `finditer()` продовжує пошук після збігу й так само знаходить `"btn"`.

```text
string:  <button type="submit" class="btn">Send</button>
try 1:                "s
try 2:                "su
try 3:                "sub
try 4:                "subm
try 5:                "submi
try 6:                "submit
```

Після спроби 6 наступний символ — лапка, тож збіг — `"submit"`. Лінивий квантифікатор зупинився на **першій** закривній лапці, бо саме там увесь шаблон уперше збігається.

## Усі квантифікатори на тих самих даних

`re.match()` на рядку `"aaaa"` показує, скільки бере кожна версія, коли ніщо після неї не змушує брати більше:

```python
import re

text = "aaaa"
patterns = [
    r"a*", r"a*?",
    r"a+", r"a+?",
    r"a?", r"a??",
    r"a{2}", r"a{2}?",
    r"a{2,}", r"a{2,}?",
    r"a{2,4}", r"a{2,4}?",
]

for pattern in patterns:
    print(f"{pattern:8}", repr(re.match(pattern, text).group()))
```

Результат:

```text
a*       'aaaa'
a*?      ''
a+       'aaaa'
a+?      'a'
a?       'a'
a??      ''
a{2}     'aa'
a{2}?    'aa'
a{2,}    'aaaa'
a{2,}?   'aa'
a{2,4}   'aaaa'
a{2,4}?  'aa'
```

Кожна лінива версія бере свій **мінімум**: нуль для `*?` і `??`, один для `+?`, `n` для `{n,}?` і `{n,m}?`. `{n}?` нічим не відрізняється від `{n}`, бо «рівно `n`» не залишає вибору.

Лінивий `??` змінює лише пріоритет, а не те, які рядки підходять. `colou??r` так само збігається і з `color`, і з `colour`: спершу він пробує без `u`, а коли наступним символом виявляється `u`, а не `r`, рушій відкочується й бере `u`.

## Лінивий не означає «найкоротший збіг»

Рушій, як і раніше, спершу обирає **найлівішу** початкову позицію. Лінивість вирішує лише те, наскільки далеко збіг тягнеться від неї:

```python
>>> import re
>>> re.search(r"a.*?b", "a a b")
<re.Match object; span=(0, 5), match='a a b'>
```

Коротший `a b` починається з індексу 2, але збіг з індексу 0 існує, тож перемагає він.

Лінивий квантифікатор також розширюється **за** роздільник, якщо цього вимагає решта шаблону:

```python
import re

text = "<a> <b>end"

print(re.search(r"<.+?>end", text))
print(re.search(r"<[^>]+>end", text))
```

Результат:

```text
<re.Match object; span=(0, 10), match='<a> <b>end'>
<re.Match object; span=(4, 10), match='<b>end'>
```

Лінивий `.+?` охоче зупинився б на першій `>`, але за нею немає `end`, тож він розширюється через `> <b`, доки `>end` не підійде. Заперечний набір `[^>]+` не може перетнути `>`, тому збіг з індексу 0 не вдається, і рушій знаходить `<b>end`. Лінивість — це **перевага**, а не межа.

## Ліниві квантифікатори в кінці шаблону

Коли після лінивого квантифікатора нічого немає, ніщо не змушує його рости, тож він лишається на мінімумі:

```python
import re

print(re.search(r"\d+?", "12345").group())
print(repr(re.search(r"\d*?", "12345").group()))
print(re.search(r"\d+?$", "12345").group())
```

Результат:

```text
1
''
12345
```

`\d+?` бере одну цифру, а `\d*?` — жодної. Лінивий квантифікатор корисний лише тоді, коли щось після нього — закривний роздільник, якір чи межа слова — визначає, де закінчується збіг. Із `$` після нього `\d+?` мусить розширитися до кінця.

## Багаторядкові блоки: лінивий квантифікатор плюс `re.DOTALL`

Ліниві квантифікатори ідеальні, коли закривний роздільник складається з **кількох символів**, як-от `*/` у коментарях у стилі C. Якщо блок може займати кілька рядків, пам'ятайте: без `re.DOTALL` крапка не збігається із символом нового рядка:

```python
import re

code = """x = 1  /* first
comment */ y = 2 /* second */"""

print(re.findall(r"/\*.*?\*/", code))
print(re.findall(r"/\*.*?\*/", code, re.DOTALL))
```

Результат:

```text
['/* second */']
['/* first\ncomment */', '/* second */']
```

`/\*` і `\*/` екранують зірочки, які інакше були б квантифікаторами. Без `re.DOTALL` перший коментар пропущено, бо в ньому є символ нового рядка. Жадібний `.*` з `re.DOTALL` був би ще гіршим: він збігся б від першого `/*` до останнього `*/` і проковтнув би й `y = 2`.

## Лінивий квантифікатор чи заперечний набір?

Обидва розв'язують проблему «забагато», але вони не рівноцінні:

- **Заперечний набір** (`"[^"]*"`, `<[^>]+>`): використовуйте, коли закривний роздільник — **один символ**. Набір точно описує, що дозволено всередині, ніколи не перетинає роздільник і не потребує відкату, тож це найточніший і зазвичай найшвидший варіант.
- **Лінивий квантифікатор** (`/\*.*?\*/`, `\*\*.+?\*\*`, `<b>.*?</b>`): використовуйте, коли закривний роздільник — **послідовність символів**. Набором не виразиш «будь-що, крім послідовності `*/`».
- **Жоден не справляється з вкладеністю.** `\(.*?\)` на `"f(a, g(b)) and h(c)"` повертає `'(a, g(b)'`, тобто зупиняється на першій `)`. Для збалансованих дужок потрібен справжній парсер (або сторонній модуль `regex`, що підтримує рекурсивні шаблони).

```python
>>> import re
>>> re.findall(r"\(.*?\)", "f(a, g(b)) and h(c)")
['(a, g(b)', '(c)']
```

## Типові помилки

- **Лінивий квантифікатор у кінці шаблону.** `\d+?` повертає одну цифру, а `.*?` — порожній рядок. Після лінивої частини обов'язково має щось бути.
- **Очікувати найкоротший збіг у рядку.** Перемагає найлівіший збіг, а лінивий квантифікатор розширюється настільки, наскільки потрібно решті шаблону.
- **Забувати `re.DOTALL` для блоків на кілька рядків.** `.*?` зупиняється на символі нового рядка, як і будь-яка крапка.
- **Використовувати ліниві квантифікатори для вкладених структур.** Дужки всередині дужок ламають шаблон. Скористайтеся парсером.
- **Обирати `.*?` там, де вистачить `[^x]*`.** Заперечний набір ясніше передає намір, не може випадково перетнути роздільник і працює швидше на довгих даних.

## Підсумок

- Додайте `?` до будь-якого квантифікатора, щоб зробити його лінивим: `*?`, `+?`, `??`, `{n,}?`, `{n,m}?`.
- Лінивий квантифікатор починає з мінімальної кількості повторень і додає по одному, доки решта шаблону не збіжиться.
- `{n}?` — те саме, що й `{n}`.
- Найлівіший збіг, як і раніше, перемагає. Лінивість впливає лише на довжину збігу від цієї позиції.
- Лінивий квантифікатор у кінці шаблону бере свій мінімум, тож ставте після нього роздільник, якір або межу.
- Для односимвольних роздільників обирайте заперечний набір на кшталт `[^"]*`. Для багатосимвольних — `.*?`, а якщо блок може займати кілька рядків, додайте `re.DOTALL`.

## Практика

### Вправа 1: Усі теги

Виберіть усі теги з `"<p>Hi</p><br><b>x</b>"` за допомогою лінивого квантифікатора. Результат має бути `['<p>', '</p>', '<br>', '<b>', '</b>']`.

### Вправа 2: Жирний текст у Markdown

Виберіть текст між подвійними зірочками в `"This is **bold** and **also bold**"`. Поверніть лише внутрішній текст, без зірочок. Візьміть ліниву частину в групу захоплення `(...)`: коли в шаблоні одна група, `findall()` повертає те, що збіглося з цією групою.

### Вправа 3: Передбачте числа

Передбачте результат кожного рядка, а потім запустіть код:

```python
import re

text = "2024 year"

print(re.search(r"\d+", text).group())
print(re.search(r"\d+?", text).group())
print(re.search(r"\d+?\b", text).group())
print(repr(re.search(r"\d*?", text).group()))
```

### Вправа 4: Мітки в журналі

Виберіть мітки у квадратних дужках із `"[INFO] [db] connected [ok]"`. Розв'яжіть задачу двічі: з лінивим квантифікатором і з заперечним набором.

## Розв'язки

### Вправа 1

```python
import re

print(re.findall(r"<.+?>", "<p>Hi</p><br><b>x</b>"))
```

Результат:

```text
['<p>', '</p>', '<br>', '<b>', '</b>']
```

Жадібний `<.+>` повернув би весь рядок як один збіг. `<[^>]+>` дає той самий результат, що й лінива версія.

### Вправа 2

```python
import re

text = "This is **bold** and **also bold**"

print(re.findall(r"\*\*(.+?)\*\*", text))
print(re.findall(r"\*\*.+?\*\*", text))
```

Результат:

```text
['bold', 'also bold']
['**bold**', '**also bold**']
```

Із групою `findall()` повертає лише внутрішній текст. Без неї — цілі збіги. Жадібний `.+` дав би один збіг від першого `**` до останнього.

### Вправа 3

Результат:

```text
2024
2
2024
''
```

- Жадібний `\d+` бере всі чотири цифри.
- Лінивий `\d+?` зупиняється на мінімумі в одну цифру, бо в шаблоні після нього нічого немає.
- Із `\b` після нього `\d+?` мусить розширюватися до межі слова, а вона йде після `2024`.
- Лінивому `\d*?` досить нуля цифр, тож збіг порожній.

### Вправа 4

```python
import re

log = "[INFO] [db] connected [ok]"

print(re.findall(r"\[.*?\]", log))
print(re.findall(r"\[[^\]]*\]", log))
```

Результат:

```text
['[INFO]', '[db]', '[ok]']
['[INFO]', '[db]', '[ok]']
```

Квадратні дужки — метасимволи, тому буквальні дужки екрановано як `\[` і `\]`. У другому шаблоні `[^\]]*` — це заперечний набір: «будь-які символи, крім закривної квадратної дужки». Жадібний `\[.*\]` повернув би весь рядок як один збіг.
