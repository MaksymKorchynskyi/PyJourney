# Жадібні квантифікатори

Типово кожен квантифікатор у Python **жадібний** (greedy): він бере стільки символів, скільки може, і віддає частину назад лише тоді, коли інакше решта шаблону не збігається. Здебільшого саме це й потрібно (`\d+` має повернути ціле число), але між роздільниками, як-от лапками чи тегами, жадібність дає збіги, значно довші за очікувані. Якщо розуміти, як рушій працює крок за кроком, такі сюрпризи стають передбачуваними.

## Що ви дізнаєтесь

- Що означає «жадібний» для `*`, `+`, `?` і `{n,m}`
- Як рушій регулярних виразів шукає збіг жадібно і що таке **відкат** (backtracking)
- Чому `".+"` захоплює забагато і три способи це виправити
- Чому найлівіший збіг перемагає найдовший
- Коли жадібність корисна
- Як присвійні квантифікатори й атомарні групи (Python 3.11+) вимикають відкат і чому вкладені квантифікатори можуть зробити регулярний вираз надзвичайно повільним

## Неочікуваний результат

Припустімо, є HTML-фрагмент кнопки, і з нього потрібно взяти значення атрибутів у подвійних лапках, `submit` і `btn`:

```python
s = '<button type="submit" class="btn">Send</button>'
```

Перша природна спроба — шаблон `".+"`:

- `"` відкривна лапка;
- `.+` один або більше будь-яких символів (крім символу нового рядка);
- `"` закривна лапка.

```python
import re

s = '<button type="submit" class="btn">Send</button>'

for match in re.finditer(r'".+"', s):
    print(match.group())
```

Результат:

```text
"submit" class="btn"
```

Замість двох коротких збігів маємо один довгий: від першої лапки до **останньої** лапки в рядку. Квантифікатор `+` жадібний, а крапка приймає й лапки, тож ніщо не зупиняє його на першій закривній лапці.

> **Зверніть увагу:** шаблон записано як сирий рядок в одинарних лапках, `r'".+"'`, щоб подвійні лапки всередині не довелося екранувати. Сирі рядки — добра звичка для кожного шаблону, навіть без зворотних скісних рисок.

## Як працює жадібний пошук

Ось що робить рушій крок за кроком:

1. Шукає першу `"`. Символи `<button type=` не підходять, тож рушій рухається далі до індексу 13, де знаходить першу лапку.
2. `.+` жадібний, тому бере всі символи, які може: аж до кінця рядка.
3. Тепер шаблон потребує `"`, але символів не лишилося. Ця спроба невдала.
4. Рушій **відкочується** (backtracking): `.+` віддає один символ (`>`), і рушій перевіряє, чи далі йде `"`. Не йде, тож `.+` віддає ще один символ, і так далі.
5. Коли `.+` віддав `">Send</button>`, наступним символом стає лапка після `btn`. Остання `"` шаблону збігається з нею, і збіг охоплює індекси від 13 до 33.

```text
string:  <button type="submit" class="btn">Send</button>
step 1:               ^
step 2:               "submit" class="btn">Send</button>
step 5:               "submit" class="btn"
```

Ключова ідея: жадібний квантифікатор спершу захоплює якомога більше, а потім відступає **по одному символу**, доки решта шаблону не збіжиться. Він зупиняється на першому успіху, тобто на найдовшому можливому збігу з цієї початкової позиції.

## Відкат наочно

Групи дають змогу побачити відкат на власні очі. Кожна пара круглих дужок захоплює те, що збіглося з її частиною шаблону (докладно про групи — у розділі «Групування»):

```python
import re

print(re.search(r"(\d+)(\d{2})", "12345").groups())
```

Результат:

```text
('123', '45')
```

Спершу `\d+` бере всі п'ять цифр. Тоді `\d{2}` нічого не лишається, тож `\d+` віддає одну цифру (`5`), що все ще замало, потім ще одну (`4`). Тепер `\d{2}` збігається з `45`, і пошук успішний. Жадібна частина залишає собі якомога більше: `123`.

## Спершу найлівіший, потім жадібний

Жадібність **не** означає «найдовший збіг у всьому рядку». Рушій завжди обирає **найлівішу** позицію, де шаблон може збігтися. Жадібність лише визначає довжину збігу від цієї позиції:

```python
>>> import re
>>> re.search(r"a+", "baaa caaaaa")
<re.Match object; span=(1, 4), match='aaa'>
```

`aaaaa` далі в рядку довше, але `aaa` починається раніше, тож перемагає він.

## Як виправити приклад із кнопкою

Є три поширені способи зупинитися на першій закривній лапці.

**1. Лінивий квантифікатор.** Знак `?` після квантифікатора змушує його брати якомога **менше** символів (див. тему «Нежадібні квантифікатори»):

```python
import re

s = '<button type="submit" class="btn">Send</button>'

for match in re.finditer(r'".+?"', s):
    print(match.group())
```

Результат:

```text
"submit"
"btn"
```

**2. Заперечний набір.** `[^"]` означає «будь-який символ, крім лапки» (див. тему «Набори та діапазони»). Тоді квантифікатор ніколи не проскочить закривну лапку, і відкочуватися нема куди:

```python
import re

s = '<button type="submit" class="btn">Send</button>'

for match in re.finditer(r'"[^"]+"', s):
    print(match.group())
```

Результат:

```text
"submit"
"btn"
```

Цей варіант точно описує, що дозволено між лапками. Зазвичай він найнадійніший і найшвидший.

**3. Справжній парсер.** Для реального HTML використовуйте парсер, наприклад стандартний модуль `html.parser` або сторонню бібліотеку BeautifulSoup. HTML має вкладеність, коментарі, екрановані лапки й безліч інших деталей, з якими регулярні вирази справляються погано.

## Коли жадібність — саме те, що треба

Жадібність типова, бо часто це правильна поведінка:

- `\d+` повертає `2021`, а не `2`.
- `.*/` бере все до **останньої** скісної риски, тобто частину шляху з каталогом. Якщо замінити її порожнім рядком, лишиться назва файлу.
- `.*\.` бере все до останньої крапки, тож лишається розширення файлу.

```python
import re

path = "/home/olena/notes.txt"

print(re.search(r".*/", path).group())
print(re.sub(r".*/", "", path))
print(re.sub(r".*\.", "", "archive.tar.gz"))
```

Результат:

```text
/home/olena/
notes.txt
gz
```

Пам'ятайте також, що крапка не відповідає символу нового рядка (якщо не вказати `re.DOTALL`). Тому жадібний `.+` ніколи не виходить за межі рядка тексту:

```python
>>> import re
>>> re.findall(r'".+"', 'say "hi"\nand "bye"')
['"hi"', '"bye"']
```

## Присвійні квантифікатори й атомарні групи (Python 3.11+)

Починаючи з Python 3.11, `re` підтримує **присвійні квантифікатори** (possessive quantifiers): `*+`, `++`, `?+` і `{n,m}+`. Вони жадібні, але **ніколи нічого не віддають назад**. Захоплені ними символи для відкату недоступні:

```python
import re

print(re.search(r"\d+5", "12345"))
print(re.search(r"\d++5", "12345"))
```

Результат:

```text
<re.Match object; span=(0, 5), match='12345'>
None
```

Жадібний `\d+` бере всі цифри, потім віддає `5`, щоб збігся буквальний символ `5`. Присвійний `\d++` теж бере всі цифри разом із `5` і відмовляється щось віддавати, тому шаблон не збігається.

**Атомарна група** (atomic group) `(?>...)` робить те саме для цілої групи: щойно група збіглася, рушій більше не повертається всередину неї, щоб спробувати інші варіанти. `(?>\d+)5` поводиться так само, як `\d++5`.

Навіщо вони? Вони змушують шаблон швидко **зазнати невдачі**, коли відкат усе одно не допоможе. Наприклад, у `"[^"]++"` віддавання символів, що не є лапками, ніколи не дасть лапку, тож заборона відкату нічого не втрачає й економить роботу.

## Катастрофічний відкат

Відкат має й темний бік. Коли квантифікатори **вкладені** один в одного над тими самими символами, кількість способів розбити вхідний рядок може зростати експоненційно. Класичний приклад — `(a+)+b` на рядку з літер `a` без `b`: перш ніж здатися, рушій перебирає всі можливі способи розподілити літери `a` між внутрішнім і зовнішнім `+`.

```python
import re
import time

pattern = re.compile(r"(a+)+b")

for n in [16, 18, 20, 22]:
    start = time.perf_counter()
    pattern.search("a" * n)
    print(n, f"{time.perf_counter() - start:.3f} s")
```

Результат (час залежить від комп'ютера, темп зростання — ні):

```text
16 0.003 s
18 0.013 s
20 0.044 s
22 0.170 s
```

Кожні два додаткові символи сповільнюють пошук приблизно вчетверо. Для 40 символів знадобилися б години. Коли такий шаблон обробляє дані користувачів, це справжня вразливість, відома як **ReDoS** (regular expression denial of service, відмова в обслуговуванні через регулярний вираз).

Як виправити:

- Приберіть вкладеність: `(a+)+b` означає те саме, що й `a+b`, який зазнає невдачі миттєво.
- Використайте присвійний квантифікатор або атомарну групу: `(?:a++)+b` чи `(?>a+)+b` теж завершуються миттєво.
- Між роздільниками віддавайте перевагу точним наборам, як-от `[^"]+`, а не розмитим, як-от `.+`.

## Типові помилки

- **`.+` чи `.*` між роздільниками.** `".+"`, `<.+>` і `\(.*\)` доходять до **останнього** роздільника в рядку. Використовуйте заперечний набір (`"[^"]*"`) або лінивий квантифікатор (`".*?"`).
- **Думати, що жадібний означає «найдовший збіг у рядку».** Завжди перемагає найлівіший збіг. Жадібність впливає лише на його довжину.
- **Розбирати HTML чи XML регулярними виразами.** Використовуйте `html.parser`, `xml.etree.ElementTree` або інший парсер.
- **Вкладати квантифікатори над тими самими символами.** `(a+)+`, `(\w*)*` і `(.*)*` можуть спричинити катастрофічний відкат.
- **Присвійний квантифікатор там, де потрібен відкат.** `\d++5` ніколи не збігається, бо `\d++` уже проковтнув `5`.

## Підсумок

- Усі квантифікатори типово жадібні: вони беруть якомога більше.
- Якщо решта шаблону не збігається, жадібний квантифікатор віддає символи по одному. Це називається відкатом (backtracking).
- Рушій спершу обирає найлівіший збіг. Жадібність потім робить його якомога довшим від цієї позиції.
- Між роздільниками жадібний `.+` доходить до останнього роздільника. Виправляйте це заперечним набором `[^"]+` (найточніше) або лінивим квантифікатором `.+?`.
- Жадібність корисна для цілих чисел, шляхів та інших задач «до останнього X».
- Присвійні квантифікатори (`++`, `*+`, ...) й атомарні групи `(?>...)` (Python 3.11+) жадібні й ніколи не віддають символів.
- Вкладені квантифікатори, як-от `(a+)+`, можуть спричинити експоненційний відкат (ReDoS).

### Вправа 4: Кому дістануться цифри?

```python
import re

```

## Розв'язки

### Вправа 1

```python
import re

text = "<b>bold</b> text"

print(re.search(r"<.+>", text).group())
print(re.search(r"<[^>]+>", text).group())
```

Результат:

```text
<b>bold</b>
<b>
```

`.+` доходить до кінця рядка й відкочується до **останнього** `>`. `[^>]+` не може перейти через `>`, тому зупиняється на першому.

### Вправа 2

```python
import re

for name in ["archive.tar.gz", "photo.jpeg", "README"]:
    print(re.sub(r".*\.", "", name))
```

Результат:

```text
gz
jpeg
README
```

Жадібний `.*` бере все до **останньої** крапки, тож для `archive.tar.gz` лишається тільки `gz`. Назва без крапки не дає жодного збігу, і `re.sub()` повертає її без змін. У реальному коді зрозуміліший інструмент — `pathlib.Path(name).suffix`.

### Вправа 3

```python
import re

text = 'say "hi", "" and "bye"'

print(re.findall(r'"[^"]+"', text))
print(re.findall(r'"[^"]*"', text))
```

Результат:

```text
['"hi"', '" and "']
['"hi"', '""', '"bye"']
```

З `+` порожній рядок `""` не може збігтися, бо потрібен щонайменше один символ, що не є лапкою. Тоді рушій бере **другу** лапку з `""` як відкривну, забирає ` and ` як уміст і закривається відкривною лапкою слова `"bye"`. Дозвіл на нуль символів через `*` це виправляє.

### Вправа 4

Результат:

```text
(\d+)(\d+) ('202', '4')
(\d*)(\d+) ('202', '4')
(\d+)(\d*) ('2024', '')
```

Перший квантифікатор жадібний і залишає собі якомога більше. У перших двох шаблонах друга група потребує принаймні однієї цифри, тож перша група віддає рівно одну. У третьому шаблоні другу групу влаштовує нуль цифр, тож перша група залишає собі всі чотири.
