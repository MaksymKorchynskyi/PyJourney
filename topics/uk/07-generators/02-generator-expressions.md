# Генераторні вирази

**Генераторний вираз** (generator expression) створює генератор в одному рядку. Він виглядає так само, як спискове включення (list comprehension), але записується в круглих дужках замість квадратних і не будує весь список одразу, а видає значення ліниво, по одному. Це ідіоматичний спосіб передавати дані у функції на кшталт `sum()`, `max()`, `any()` і `str.join()`.

## Що ви дізнаєтесь

- Як генераторний вираз пов'язаний із генераторною функцією
- Повний синтаксис: фільтри, умовні значення, кілька циклів `for`
- Як передати генераторний вираз у функцію, з додатковими дужками чи без них
- Чим генераторні вирази відрізняються від спискових включень: синтаксис, пам'ять, повторне використання
- Які частини генераторного виразу обчислюються одразу, а які пізніше
- Як обрати між списковим включенням, генераторним виразом і генераторною функцією

## Від генераторної функції до генераторного виразу

Ось генераторна функція, яка видає квадрати цілих чисел від `0` до `length - 1`:

```python
def squares(length):
    for n in range(length):
        yield n ** 2


for square in squares(5):
    print(square)
```

Результат:

```text
0
1
4
9
16
```

Коли все тіло генераторної функції зводиться до «перебрати щось і видати вираз», те саме можна записати як **генераторний вираз**:

```python
squares = (n ** 2 for n in range(5))
print(type(squares))

for square in squares:
    print(square)
```

Результат:

```text
<class 'generator'>
0
1
4
9
16
```

Результат — звичайний об'єкт-генератор, точнісінько такий, як той, що повертав `squares(5)` у першому прикладі. Це ітератор, він лінивий, і спожити його можна лише раз.

Загальна форма:

```text
(expression for item in iterable if condition)
```

і вона поводиться як така генераторна функція:

```python
def gen(iterable):
    for item in iterable:
        if condition:
            yield expression
```

## Повний синтаксис

Генераторні вирази підтримують усе, що підтримують спискові включення.

**Фільтр** з `if` залишає лише частину елементів:

```python
multiples_of_3 = (n for n in range(10) if n % 3 == 0)
print(list(multiples_of_3))
```

Результат:

```text
[0, 3, 6, 9]
```

**Умовний вираз** обирає значення, яке буде видано. Зверніть увагу: він стоїть *перед* `for`, а фільтр — *після*:

```python
labels = ("even" if n % 2 == 0 else "odd" for n in range(4))
print(list(labels))
```

Результат:

```text
['even', 'odd', 'even', 'odd']
```

**Кілька циклів `for`** працюють як вкладені цикли, причому крайній лівий — зовнішній:

```python
pairs = ((letter, number) for letter in "ab" for number in (1, 2))
print(list(pairs))
```

Результат:

```text
[('a', 1), ('a', 2), ('b', 1), ('b', 2)]
```

Це те саме, що:

```python
def pairs_gen():
    for letter in "ab":
        for number in (1, 2):
            yield letter, number


print(list(pairs_gen()))
```

Результат:

```text
[('a', 1), ('a', 2), ('b', 1), ('b', 2)]
```

**Вкладені включення** теж дозволені. Тут кожен елемент, який видає генератор, сам є списком, побудованим внутрішнім списковим включенням:

```python
table = ([row * col for col in range(1, 4)] for row in range(1, 4))

for line in table:
    print(line)
```

Результат:

```text
[1, 2, 3]
[2, 4, 6]
[3, 6, 9]
```

> **Порада:** якщо генераторному виразу потрібно більше двох циклів `for` або складна умова, перепишіть його як генераторну функцію. Зрозуміла функція на п'ять рядків краща за хитромудрий однорядковий вираз.

## Генераторний вираз як аргумент функції

Найчастіше генераторний вираз передають як аргумент функції, яка споживає ітерований об'єкт. Коли це **єдиний** аргумент, власні дужки виразу можна не писати, бо його вже оточують дужки виклику:

```python
words = ["generator", "yield", "lazy", "iterator"]

print(sum(len(word) for word in words))
print(max(len(word) for word in words))
print(", ".join(word.upper() for word in words if len(word) > 4))
print(dict((word, len(word)) for word in words))
```

Результат:

```text
26
9
GENERATOR, YIELD, ITERATOR
{'generator': 9, 'yield': 5, 'lazy': 4, 'iterator': 8}
```

Якщо функція приймає ще й інші аргументи, генераторний вираз **мусить** мати власні дужки:

```python
words = ["generator", "yield", "lazy", "iterator"]

print(sorted((len(word) for word in words), reverse=True))
```

Результат:

```text
[9, 8, 5, 4]
```

Без внутрішніх дужок `sorted(len(word) for word in words, reverse=True)` дає `SyntaxError: Generator expression must be parenthesized`.

### Коротке замикання з `any()` і `all()`

Оскільки значення обчислюються на вимогу, `any()` і `all()` можуть зупинитися, щойно відповідь стає відомою (так зване коротке замикання, short-circuit). Спискове включення спершу обчислює всі значення:

```python
def is_big(n):
    print("  checking", n)
    return n > 10


numbers = [3, 15, 7, 20]

print("generator expression:")
print(any(is_big(n) for n in numbers))

print("list comprehension:")
print(any([is_big(n) for n in numbers]))
```

Результат:

```text
generator expression:
  checking 3
  checking 15
True
list comprehension:
  checking 3
  checking 15
  checking 7
  checking 20
True
```

З генераторним виразом `any()` зупинилася на `15`, першому великому числі. Зі списком усі чотири перевірки відбулися ще до того, як `any()` узагалі почала роботу. Якби `is_big()` була дорогою перевіркою (мережевий запит, запит до бази даних), різниця була б дуже відчутною.

## Генераторні вирази проти спискових включень

```python
square_list = [n ** 2 for n in range(5)]
square_generator = (n ** 2 for n in range(5))

print(square_list)
print(type(square_generator).__name__)
```

Результат:

```text
[0, 1, 4, 9, 16]
generator
```

### Синтаксис

Спискове включення записують у квадратних дужках `[]`, генераторний вираз — у круглих `()`. Усе, що всередині, однакове.

### Негайне чи ліниве обчислення, і пам'ять

Спискове включення обчислюється **негайно** (eager): воно одразу обчислює всі елементи й зберігає повний список у пам'яті. Генераторний вираз **лінивий** (lazy): він зберігає лише свій поточний стан і обчислює наступний елемент, коли його попросять. Обсяг пам'яті, який він займає, не залежить від того, скільки елементів він видасть:

```python
import sys

big_list = [n ** 2 for n in range(1_000_000)]
big_gen = (n ** 2 for n in range(1_000_000))

print(sys.getsizeof(big_list))
print(sys.getsizeof(big_gen))
```

Результат (Python 3.14, 64-біт; точні числа залежать від версії):

```text
8448728
208
```

Розмір списку зростає разом із кількістю елементів, і `getsizeof()` ще навіть не враховує цілочислові об'єкти, на які він посилається. Генератор лишається в межах кількох сотень байтів.

### Багаторазовий ітерований об'єкт чи одноразовий ітератор

Спискове включення повертає список, тобто **ітерований об'єкт**: його можна перебирати скільки завгодно разів. Генераторний вираз повертає генератор, тобто **ітератор**: після одного повного проходу він вичерпаний.

```python
square_list = [n ** 2 for n in range(5)]
square_generator = (n ** 2 for n in range(5))

print(sum(square_list), sum(square_list))
print(sum(square_generator), sum(square_generator))
```

Результат:

```text
30 30
30 0
```

Друга `sum()` по генератору не знайшла жодного значення.

### Можливості послідовності

Список підтримує `len()`, індексацію, зрізи, `reversed()`, сортування на місці й виведення на екран цілком. Генератор підтримує лише перебір. `len()` для нього генерує `TypeError: object of type 'generator' has no len()`, а під час виведення видно лише опис на зразок `<generator object <genexpr> at 0x...>` (адреса щоразу інша).

| | Спискове включення `[...]` | Генераторний вираз `(...)` |
|---|---|---|
| Результат | `list` | генератор (ітератор) |
| Обчислення | негайне, все одразу | ліниве, по одному елементу на запит |
| Пам'ять | зростає з кількістю елементів | невелика і стала |
| Скільки разів можна перебрати | багато | один |
| `len()`, індексація, зрізи | так | ні |
| Працює з нескінченними даними | ні | так |
| Найкраще підходить для | даних, які використовуватимуть повторно чи переглядатимуть | даних, які споживають один раз |

> **Зверніть увагу:** у Python є також включення для множин `{...}` і словників `{k: v ...}`, але **немає кортежного включення**. `(x for x in data)` — це завжди генератор. Щоб отримати кортеж, пишіть `tuple(x for x in data)`.

## Коли обчислюються частини виразу?

Генераторний вираз **одразу**, у момент створення, обчислює ітерований об'єкт свого **першого** циклу `for`. Усе інше (вираз-результат, умови, подальші цикли `for`) виконується **ліниво**, під час перебору. Це має кілька помітних наслідків.

Якщо після створення генератора перев'язати ім'я, об'єкт, який він перебирає, не зміниться, бо цей об'єкт уже захоплено:

```python
numbers = [1, 2, 3]
gen = (n * 10 for n in numbers)
numbers = [7, 8, 9]   # перев'язуємо ім'я: gen і далі тримає старий список
print(list(gen))
```

Результат:

```text
[10, 20, 30]
```

А от *зміну* того самого списку до початку перебору видно, бо генератор читає список лише тоді, коли в нього просять елементи:

```python
numbers = [1, 2, 3]
gen = (n * 10 for n in numbers)
numbers.append(4)
print(list(gen))
```

Результат:

```text
[10, 20, 30, 40]
```

Інші змінні, що трапляються у виразі, шукаються в момент обчислення кожного значення, тож використовується їхнє **поточне** значення:

```python
factor = 10
gen = (n * factor for n in range(3))
factor = 100
print(list(gen))
```

Результат:

```text
[0, 100, 200]
```

Це саме правило визначає, коли з'являються помилки. Неітерований об'єкт у першому `for` спричиняє помилку одразу, а помилка у виразі з'являється лише тоді, коли обчислюється відповідний елемент:

```python
try:
    gen = (x for x in 5)
except TypeError as error:
    print("at creation:", error)

gen = (1 / n for n in [1, 0])     # створюється без проблем
print(next(gen))
try:
    next(gen)
except ZeroDivisionError as error:
    print("during iteration:", error)
```

Результат:

```text
at creation: 'int' object is not iterable
1.0
during iteration: division by zero
```

І нарешті, як і включення в Python 3, генераторний вираз має власну область видимості: його змінна циклу не «протікає» в навколишній код.

## Як обрати інструмент

- **Спискове включення** — коли результати потрібні кілька разів, потрібні `len()` чи індексація, їх треба відсортувати чи вивести, або коли даних небагато.
- **Генераторний вираз** — коли значення одразу передаються у функцію-споживача (`sum`, `max`, `min`, `any`, `all`, `"".join`, `set`, `dict`), коли даних багато чи вони нескінченні, або коли ви будуєте лінивий конвеєр.
- **Генераторна функція** — коли логіка не вміщується в один зрозумілий вираз: кілька інструкцій, `try`/`except`, стан, що зберігається між елементами, або `return` зі значенням.

## Типові помилки

- **Чекати кортеж.** Круглі дужки навколо включення створюють генератор, а не кортеж. Використовуйте `tuple(...)`.

- **Виводити генератор, щоб побачити значення.** `print(gen)` показує `<generator object <genexpr> at 0x...>`. Для налагодження пишіть `print(list(gen))`, пам'ятаючи, що це споживає генератор.

- **Повторно використовувати вичерпаний генераторний вираз.** Якщо обчислювати дві статистики з одного генератора, друга буде хибною:

  ```python
  prices = (float(p) for p in ["4.5", "10", "2.5"])
  print(max(prices))
  print(sum(prices))   # нічого не лишилося: 0
  ```

  Результат:

  ```text
  10.0
  0
  ```

  Якщо потрібно кілька проходів, один раз побудуйте список (`prices = [float(p) for p in ...]`).

- **Не ставити дужки, коли функція має інші аргументи.** `sorted(x for x in data, key=abs)` — це `SyntaxError`. Пишіть `sorted((x for x in data), key=abs)` або просто `sorted(data, key=abs)`.

- **Забувати про пізнє обчислення.** Змінні у виразі зчитуються тоді, коли обчислюються значення. Якщо змінити їх між створенням і споживанням генератора, будуть використані нові значення.

- **Використовувати генератор у вкладених циклах.** `for a in gen: for b in gen: ...` ділить один ітератор між обома циклами (див. *Ітератор та ітерований об'єкт*). Для даних, які перебирають кілька разів, беріть список.

## Підсумок

- Генераторний вираз `(expr for item in iterable if cond)` — компактний спосіб створити генератор.
- Він підтримує фільтри, умовні вирази, кілька циклів `for` і вкладені включення — так само, як спискове включення.
- Як єдиний аргумент виклику він не потребує додаткових дужок: `sum(x * x for x in data)`.
- Спискові включення обчислюються негайно й повертають багаторазовий список. Генераторні вирази ліниві, займають сталий обсяг пам'яті й повертають одноразовий ітератор.
- Ітерований об'єкт першого циклу `for` обчислюється одразу, усе інше — під час перебору.
- Генераторні вирази добрі для даних, які споживають один раз (особливо з `sum`, `any`, `all`, `join`), спискові включення — для даних, які використовують повторно, а генераторні функції — для складної логіки.

### Вправа 1: Перепишіть як генераторний вираз

Перепишіть цю генераторну функцію одним генераторним виразом, а потім за його допомогою виведіть суму квадратів парних чисел від `1` до `10`. Передайте вираз у `sum()` без додаткових дужок.

```python
def even_squares(numbers):
    for n in numbers:
        if n % 2 == 0:
            yield n * n
```

Запишіть, що виведе цей код, перш ніж запускати його.

```python
data = [1, 2, 3]
gen = (x + offset for x in data)
offset = 10
data.append(4)
data = [100]

print(next(gen))

print(list(gen))
```

### Вправа 3: Статистика тексту

Для `text = "Python generators are Lazy and Python lists are Eager"` за допомогою генераторних виразів (передаючи їх прямо у вбудовані функції, без списків) обчисліть:

1. довжину найдовшого слова;
2. скільки слів починається з великої літери;
3. чи є хоч одне слово, довше за 9 символів;
4. рядок з перших літер усіх слів, наприклад `"PgaLaPlaE"`.

### Вправа 4: Лінивий конвеєр

Список нижче замінює рядки великого конфігураційного файлу. Використовуючи лише з'єднані в ланцюжок генераторні вирази, обчисліть суму всіх чисел, пропускаючи порожні рядки й рядки-коментарі, що починаються з `#` (після вилучення пробілів на краях).

```python
lines = ["# limits", "10", "  25  ", "", "# more", "7", "   "]
```

## Розв'язки

### Вправа 1

```python
numbers = range(1, 11)
print(sum(n * n for n in numbers if n % 2 == 0))
```

Результат:

```text
220
```

Фільтр `if n % 2 == 0` залишає `2, 4, 6, 8, 10`, а `4 + 16 + 36 + 64 + 100 = 220`.

### Вправа 2

Результат:

```text
11
[12, 13, 14]
[]
```

- Об'єкт-список `[1, 2, 3]` було захоплено під час створення `gen`. Пізніше перев'язування `data` на `[100]` на `gen` не впливає.
- `data.append(4)` змінив захоплений список *до* того, як `data` перев'язали, тож генератор бачить `1, 2, 3, 4`.
- `offset` зчитується під час перебору, коли він уже дорівнює `10`. (Якби перебір почався до `offset = 10`, ви отримали б `NameError`.)
- Другий `list(gen)` порожній, бо генератор вичерпано.

### Вправа 3

```python
text = "Python generators are Lazy and Python lists are Eager"
words = text.split()

print(max(len(word) for word in words))
print(sum(1 for word in words if word[0].isupper()))
print(any(len(word) > 9 for word in words))
print("".join(word[0] for word in words))
```

Результат:

```text
10
4
True
PgaLaPlaE
```

`sum(1 for ... if ...)` — поширена ідіома, щоб порахувати елементи, які відповідають умові, не будуючи списку. Тут `words` — список, бо його використовують чотири рази. Кожен генераторний вираз над ним створюється заново, тож нічого не вичерпується.

### Вправа 4

```python
lines = ["# limits", "10", "  25  ", "", "# more", "7", "   "]

stripped = (line.strip() for line in lines)
meaningful = (line for line in stripped if line and not line.startswith("#"))
total = sum(int(line) for line in meaningful)

print(total)
```

Результат:

```text
42
```

Кожен етап — генераторний вираз над попереднім, тож нічого не обчислюється, доки `sum()` не почне витягати значення. Після цього кожен рядок проходить усі три етапи, перш ніж буде прочитано наступний. Зі справжнім файлом ви написали б `stripped = (line.strip() for line in file)`, і програма використовувала б так само мало пам'яті для файлу будь-якого розміру.
